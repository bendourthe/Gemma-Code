# Hooks-over-Prompts Inventory

This is a reference document, not a subagent definition. It has no YAML frontmatter and is never loaded as a runnable agent.

It inventories the current prompt-based rules in [AGENTS.md](../../AGENTS.md) and ranks them by the enforcement-determinism gain of converting each to a hook (a script that runs without the model in the loop). It supports the "hooks for deterministic automation" Critical Rule added in v1.2.0 Phase 1.3. The actual migrations land in v1.2.0 Phase 5 (agent-loop policy enforcement); nothing here is implemented yet.

Source: the "best practices in large codebases" article (S3), item 21, via [docs/v1.2.0/comparison-ecosystem-2026-05.md Section 5](../../docs/v1.2.0/comparison-ecosystem-2026-05.md).

## Ranking criteria

- **Enforcement-determinism gain**: how completely a script can enforce the rule without a model judgment call. A rule a script can verify with zero false positives is a strong hook candidate; a rule that needs semantic judgment stays a prompt.
- **Current coverage**: whether a hook already exists. The repo ships three agent-agnostic harness scripts under `scripts/hooks/` (see AGENTS.md "Optional Developer Harness"): `check-tool-permission.mjs`, `check-git-control-plane.mjs`, `check-prompt-policy.mjs`. Some rules below are already partially covered by these.

## High gain (deterministic; convert in Phase 5)

| Rule (from AGENTS.md) | Hook surface | Determinism | Current coverage |
|---|---|---|---|
| Commit messages must be ASCII-only (no em/en-dashes, curly quotes, ellipsis chars) | `commit-msg` hook scanning the message for non-ASCII / banned codepoints | Full -- pure codepoint scan, zero false positives | None committed; relies on the prompt today |
| Never add `Co-Authored-By` / AI attribution footers to commit messages | `commit-msg` hook regex-rejecting the footer patterns | Full -- fixed string / regex match | None committed |
| Destructive git commands (force-push, hard reset, branch deletion, history rewrite) require explicit confirmation | `pre-tool` / pre-push guard detecting `push --force`, `reset --hard`, `branch -D`, `filter-repo` | Full -- argv pattern match | Partial: `scripts/hooks/check-git-control-plane.mjs` refuses sessions on `main`/`master` and on a too-dirty tree; does not yet gate individual destructive invocations |
| Shell-execution tool calls must include a plain-text description | `pre-tool` hook rejecting a shell tool call whose `description` is empty | Full -- presence check on the tool payload | None committed (the description requirement is prompt-enforced) |
| Boundary rule: `core/**` must not import `modules/**`; modules must not import each other | `pre-commit` hook running `npm run deps:check` (dependency-cruiser) | Full -- already a deterministic check | Strong: gated in CI via `deps:check` / `check-architecture`; could also run pre-commit |
| Reject prompts containing pasted secrets (AWS keys, GitHub PATs, JWTs, PEM, Slack tokens) | prompt-policy hook | Full -- pattern match | Covered: `scripts/hooks/check-prompt-policy.mjs` |

## Medium gain (deterministic for some surfaces; partial false positives)

| Rule (from AGENTS.md) | Hook surface | Determinism | Notes |
|---|---|---|---|
| No em-dashes; use parentheses, commas, or separate sentences | `commit-msg` + Markdown lint for committed docs | Full for commit messages; heuristic for prose (legitimate em-dashes are rare here but possible in quoted external text) | Scope the hook to commit messages and `docs/**` generated by the agent |
| Never hard-wrap paragraph text at a fixed column width | Markdown lint flagging suspicious mid-sentence newlines in agent-authored Markdown | Heuristic -- code blocks, tables, and intentional lists are false positives that must be excluded | Worth a hook only with a tight allowlist of target files |
| Place punctuation outside quotation marks (logical punctuation) | Markdown lint | Heuristic -- many legitimate exceptions | Low priority; likely stays a prompt |
| Secret-path denylist on file/list/grep tools | `pre-tool` permission guard | Full for the denylist patterns | Covered: `scripts/hooks/check-tool-permission.mjs` (workspace boundary + secret-path denylist) |

## Stays a prompt (non-deterministic; needs model judgment)

These are cognitive-workflow and intent rules a script cannot verify without understanding the change. They remain prompt-based by design.

- Verify work before marking complete.
- Find root causes; no temporary fixes.
- Every file-read / glob / grep must be preceded by a one-sentence explanation (this constrains the model's narration, not a tool argument, so it is not script-checkable).
- Ask clarifying questions before coding when requirements are ambiguous; batch them into the first turn.
- Every changed line must trace directly to the user's request; do not clean up adjacent code outside scope.
- The ANALYZE / PLAN / EXECUTE / VERIFY / PROPAGATE cognitive rhythm.

## Migration order for Phase 5

1. Commit-message hooks (ASCII-only + no attribution footer) -- highest determinism, currently uncovered, single `commit-msg` surface.
2. Per-invocation destructive-git guard -- extend `check-git-control-plane.mjs`.
3. Shell-description presence guard -- new `pre-tool` check.
4. Wire `deps:check` into a pre-commit hook (already in CI).
5. Reassess the medium-gain Markdown lints with a tight file allowlist before committing to them.

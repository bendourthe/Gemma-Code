The idea

A small local model, made to punch far above its weight

A 4B or 12B model on your laptop will never out-reason Opus 4.8 or GPT-5.5 on raw capability. Nexus closes that gap a different way: with the harness, not the model.

The goal is that agentic coding in Nexus feels like working in a frontier-cloud assistant. The Nexus-Hub harness wraps a small model in plan mode, verification gates, specialized sub-agents, four-layer memory, and 200+ expert skills - so the model is guided, checked, and grounded at every step instead of being asked to be brilliant in one shot. The frontier model has raw intelligence; Nexus gives a small model discipline.

This is the design bet of the project, not a benchmarked claim. Read how the harness works on the Harness page.

Install & setup

Get Nexus running on your machine

Nexus runs on Windows, macOS, and Linux against a single consumer GPU (think RTX 3070 to 4090 class, or an Apple Silicon Mac). You install it once; the setup provisions the GPU toolchain, runtimes, and your chosen local models so every pillar works on first launch.

Which path applies to you

The guided installer (the wizard below) is the end-user experience and is rolling out with the cross-OS installer. The Windows wizard exists today; macOS and Linux outer shells are landing. If you want to run Nexus right now, use the From source path further down - it is shipping.

Prerequisites

A GPU

NVIDIA (CUDA), Apple Silicon (Metal), or AMD (ROCm). CPU-only works but is slow. 8 GB VRAM is a comfortable floor.

Ollama

The local inference runtime Nexus speaks to. The installer can provision it for you; or install it yourself first.

Disk

Models are large. The installer keeps a 10 GB OS reserve and shows per-model sizing before you commit.

Option A - The guided installer rolling out

A nine-step wizard that does the whole setup. You will not touch a terminal.

  1. Welcome & Prerequisites

    The wizard checks for the runtimes it needs and offers to provision anything missing.

  2. GPU Detection

    It detects your GPU and acceleration backend (CUDA / Metal / ROCm) and picks a matching hardware tier.

  3. Install Path

    Choose where Nexus and its models live on disk.

  4. Model Selection

    Pick your local models from a typed catalog. A disk-aware footer keeps a 10 GB OS reserve and shows each model's size. Recommended defaults are pre-checked for your tier.

  5. Configuration & Review

    Confirm settings, then review the full plan before anything is written.

  6. Install & Complete

    The installer provisions the GPU toolchain, Python, Node, Ollama, FFmpeg, the diffusion runtime, and pulls your selected models. When it finishes, every pillar works on first launch.

Option B - From source shipping today

The current way to run Nexus. Prereqs: Node 20+, Rust + Cargo (for the Tauri shell), and Ollama for inference.

bash
# clone and install $ git clone https://github.com/bendourthe/Nexus-AI.git $ cd Nexus-AI $ npm ci # root + desktop workspace deps $ npm run build # compile shared core + Coding module # launch the desktop app (Vite HMR + sidecar) $ npm run dev:shell ✓ Tauri window opens - pick a model and start working

A native bundle is produced with npm run build:shell; the Node sidecar is bundled with npm run build:sidecar.

Downloading local models

Models come from Ollama (most LLMs) or verified HTTP downloads (diffusion / video weights). The installer's Model Selection step is the easy path; you can also pull an LLM directly with Ollama and Nexus will see it.

pull a model with Ollama
$ ollama run hf.co/unsloth/gemma-4-12b-it-GGUF # multimodal, 256K context $ ollama pull qwen2.5-coder:7b # strong local coding model

Agentic coding

Work like you would in Codex or Claude Code

Open the Coding pillar, pick a local model, and describe what you want. The agent reads your repo, proposes edits, runs the terminal, and verifies its own work - the same loop you know from cloud assistants, running on your GPU.

The three modes

ask (default)

Confirm each edit

The agent shows a diff and waits for your approval before writing any file. Safest for unfamiliar code.

auto

Let it run

End-to-end tool-using sessions with verification gates and git checkpoints, so you can roll back cleanly.

plan

Plan first

Type /plan. The agent writes a numbered plan and walks each step only after you approve it.

Set the default with nexus.coding.editMode.

A session, step by step

Nexus - Coding pillar (model: qwen2.5-coder:7b)
you> add a retry with backoff to the API client and prove it works plan 1. read api/client.ts 2. add retry 3. add test 4. run tests read read_file api/client.ts [auto] edit edit_file api/client.ts (+24 -3) [confirm] edit create_file api/client.test.ts [confirm] verify run_terminal "npm test -- client" [confirm] pass 9 tests green - verification gate satisfied ✓ done retry path added, backed off 100ms x3, covered by tests

After a few edits Nexus auto-runs verification, and a pass-state gate refuses to call a task "done" until a verification tool (tests / lint / build) has actually succeeded. That gate is a big part of how a small model stays honest.

Image & video

Generate media locally - and uncensored

The Image Studio and Video Lab run diffusion and video-synthesis models on the same single GPU. Because everything happens on your machine, there is no third-party content-moderation API in the loop: you choose the weights and the prompts.

Image Studio

Four modes

txt2imgText prompt to image
img2imgTransform an existing image
inpaintRepaint a masked region
outpaintExtend the canvas any direction

Controls

Prompt, size, steps, sampler, seed, and CFG - all with tier-aware defaults. Stack LoRAs (Detail Tweaker, Cinematic) and ControlNets (Pose, Depth, Canny) on capable tiers. The default model is SANA 1.5 1.6B, with a one-step SANA Sprint preview tier for near-instant iteration.

  1. Pick a mode and model

    Open Image Studio, choose txt2img (or another mode), and accept the tier default model or pick another.

  2. Write your prompt and set controls

    Adjust size, steps, sampler, and add a LoRA or ControlNet if you want.

  3. Generate and review

    Hit Generate. Every output lands in the gallery; "Copy Workflow" pulls the full settings back out of the PNG so you can reproduce or tweak it.

Video Lab

Two modes

text2videoPrompt to short clip (LTX-Video, SANA-Video 2B)
image2videoAnimate a still (Stable Video Diffusion)

Heavier CogVideoX models are opt-in on capable tiers.

Controls & preview

Duration, FPS, resolution, steps, CFG, and seed - tier-aware. A live timeline previewer shows a latent thumbnail per generated second as the clip renders. From the gallery you can play, save, copy the workflow, or send the last frame back into img2img.

Uncensored, and your responsibility

Local generation means no cloud filter sits between your prompt and the model. That is the point - and it puts lawful, ethical use entirely in your hands. Nexus makes no outbound calls by default and adds no telemetry; what you generate stays on your machine. You are responsible for the model weights you choose and for complying with the laws that apply to you.

Chat & memory

Organized local chat that remembers

The Chat Explorer is a conversational interface with a filesystem-style organizer. Conversations live in nested folders you can drag and drop, and a four-layer memory keeps long-running threads coherent.

Organize like files

Nested folders with drag-and-drop, color tags, and a breadcrumb trail. Each folder can opt in to tool execution (off by default), so a chat can stay a pure conversation or become a working agent session.

Four-layer memory

LayerHolds (half-life)
workingIn-flight state (24h)
episodicEvents (7d)
semanticObservations (30d)
graphRelations (365d)

How memory helps a small model

Retrieval fuses keyword (BM25), semantic (dense vectors), and graph traversal via Reciprocal Rank Fusion, using a bundled local embedder that never touches a remote hub. Older memories fade on an Ebbinghaus curve unless they keep getting used. You steer it directly:

memory slash commands
chat> /remember the API base URL is read from NEXUS_API_BASE ✓ saved to semantic memory chat> /recall how do we authenticate requests hit "requests sign with an HMAC header, see auth/sign.ts" (graph, score 0.81) chat> /forget the old staging URL note

Session replay and compare-two-sessions views live in the Trace dashboard, shared with the Coding pillar.

The harness

The same harness as your cloud assistant

Nexus does not invent its own way of working. It runs the Nexus-Hub catalog - the very same skills, slash-commands, hooks, agents, and language rules you can install into Claude Code, Codex, Cursor, or Gemini. Move between tools and the workflow is identical; only the model underneath changes.

How the harness compensates for a small model

Guide

Plan mode + sub-agents

Decompose a task into a checked, numbered plan and hand narrow sub-tasks (research, verify) to scoped sub-agents, so the model never has to hold the whole problem at once.

Check

Verification gates

The pass-state gate refuses to finish until tests, lint, or build actually pass - turning a model's optimism into evidence.

Ground

Memory + retrieval

Hybrid BM25 + dense + graph retrieval feeds the model the exact lines it needs, instead of relying on it to remember your codebase.

Encode

200+ expert skills

Senior-level procedures for security, testing, refactoring, and architecture load on demand, so the model follows an expert's checklist rather than improvising.

Together these are the bet: a guided, checked, grounded small model aiming to feel comparable to a frontier model on everyday agentic coding.

Keeping the harness current

The catalog is synced from the Nexus-Hub release with one command. Every sync runs a prompt-injection scanner over the skill bodies before anything is activated, and hot-reload swaps skills in without a restart.

sync the harness
$ nexus skills sync # preview the latest Nexus-Hub release $ nexus skills sync --apply # scan, then activate ✓ 203 skills, 36 commands, 14 hooks active

Quick troubleshooting

GPU not detected

Check your CUDA / Metal / ROCm install, then re-run detection. Nexus falls back to CPU but warns you it will be slow.

Generation out of memory

Lower the diffusion tier with nexus.diffusion.tierOverride, or pick a smaller model / resolution. The model status dock shows free VRAM live.

Model feels weak

Use plan mode, keep verification on, and let memory warm up. The harness is what lifts a small model - lean on it.

## Overview

This milestone operationalizes the adoption plans (Section 7) and implementation sequences (Section 8) of the seven v2.0 comparison reports. The seven sources converge on four themes that define the v2.0 wave:

1. **Agent governance and autonomy hardening.** QM contributes the named security-posture dial, command-level hard denials that survive every posture, provenance-labelled content screening, and per-project scoping concepts. Airi's Minecraft agent, Atomic Agent's no-progress veto, and Hermes Herald's tool self-recovery all describe the same class of loop circuit breakers from three independent angles. **This theme now ships as the v1.19.1 subplan** (together with the skill-native wave); this plan's browser and stretch phases consume its outputs.
2. **Catalog, model, and tier additions.** Hermes-family local models, the merged modality/audio-conditioning schema, the quantized-weights puller, and the calibrated patient tier. **This theme now ships as the v1.19.2 subplan**; this plan's multimodal chat and Video Lab phases consume its schema and puller.
3. **Multimodal chat and the local voice loop.** Inkling-Small motivates vision-chat routing and an audio-input bridge; Airi proves the fully local STT + TTS + VAD voice loop is buildable on consumer hardware. The audio work is sequenced as one pipeline: attachment plus transcribe-then-chat first, then the real-time voice loop on top. Kept here (Phase 1).
4. **New tool and generation surfaces.** Atomic Agent's Playwright-driven `browser_*` tool family is the headline coding-agent build, gated behind the v1.19.1 hardening. LongCat-Video contributes video continuation for minutes-long output and the `audio2video` avatar tier behind `diffusion-pro`. Kept here (Phases 2-3).

Per the MCP Registry Policy's reverse-engineer-first ordering, the skill-native items landed first (v1.19.1 Phase 1), then the hardening and catalog builds (v1.19.1 Phase 2, v1.19.2 Phase 1), then this plan's product builds grouped by theme and dependency (Phases 1-3), then a clearly deferrable stretch phase (Phase 4) so core phases stay bounded, a closing architecture/known-gaps/CI phase (Phase 5), and the convergence/release gate (Phase 6). Every hosted, cloud, gateway, connector, or as-a-service surface named by any of the seven sources is rejected in the consolidated "Out of Scope / Rejected" section, which binds the whole plan family. No external code is vendored anywhere in this plan except the explicitly gated LongCat Avatar pipeline integration (Phase 3), which carries its own byte-level scan precondition per the comparison's Section 9.

Success looks like: the agent loop cannot run away and the user has one named posture dial (delivered by v1.19.1); the catalog gains the Hermes family, modality metadata, quantized-weight delivery, and an honestly-labelled patient tier (delivered by v1.19.2); Chat accepts images and audio against capable local models and can hold a fully local voice conversation; the coding agent can drive a local browser under DANGEROUS-tier gating with sanitized ARIA snapshots; the Video Lab chains clips into minutes-long output and produces lip-synced avatar video from a photo and an audio track, entirely on-device; and v2.0.0 cuts only when the whole v1.18-v2.0 plan family is verifiably complete.

## Cross-Source Dedup Decisions

Every merge/dedup decision made while consolidating the seven Section 7/8 plans, with the winning shape. This section remains the single source of truth for the plan family; each decision now names the plan file where the merged item lives.

- **D1 -- Loop hardening merged three-ways.** *Lives in: v1.19.1, Phase 2.2.* Airi A2 (bounded control-action queue, no-action budget, error-burst guard), Atomic C4 (no-progress veto after N identical calls), and the iteration-ceiling revisit inside Hermes A2 all target the same seam (`src/tools/AgentLoop.ts` auto mode) and describe overlapping circuit breakers. Merged into one work package delivering a single `LoopGuards` layer with four named guards: identical-call veto, no-action budget, error-burst guard, bounded action queue, plus a revisited iteration ceiling. The existing `modules/coding/guardrails/LoopDetector.ts` is the integration point, not a parallel implementation.
- **D2 -- Tool self-recovery kept separate from loop hardening.** *Lives in: v1.19.1, Phase 2.3.* Hermes A2's remaining behaviors (truncation spill-to-file, already-applied-patch detection, near-miss search probes) recover individual tool calls rather than govern the loop; they stay a distinct sub-task so D1 stays strictly tightening while D2 is strictly resilience.
- **D3 -- Posture dial vs existing tiers.** *Lives in: v1.19.1, Phases 2.1 and 2.5.* QM A2's Strict/Auto/Dangerous dial is adopted as named presets composed from the existing `PermissionTiers` + `ConfirmationGate` + auto-mode verification gate -- not a new permission system. QM A3's command-level hard denials land first because the dial's invariant ("denials survive every posture") requires them to exist. No no-floor mode ships; the `PermissionTiers.ts` clamp stays authoritative in every posture.
- **D4 -- Provenance screening feeds the browser surface.** *Built in: v1.19.1, Phase 2.6; consumed by: this plan, Phase 2.* QM A5 (provenance-labelled tool results routed through `PromptInjectionScanner.ts`) and Atomic C1's requirement that ARIA snapshots be sanitized before entering the prompt are the same mechanism at two call sites. Built once in v1.19.1; this plan's browser tools consume it as a hard dependency rather than building their own sanitizer.
- **D5 -- Catalog schema extensions merged.** *Lives in: v1.19.2, task 1.2.* Inkling A1 (`modalities` input-modality field) and LongCat A4 (`audioConditioning` fields in `DiffusionTierVideoDefaults` + catalog video entries) are one schema change wave on `core/registry/catalog.json` / `core/registry/catalog.ts` / `core/config/DiffusionTier.ts`, so the schema is touched once and every downstream consumer (this plan's chat attachment gating, Phase 1; avatar tier, Phase 3) reads the same fields.
- **D6 -- Quantized-weights tier built once, consumed twice.** *Built in: v1.19.2, task 1.3; consumed by: v1.19.2 task 1.6 and this plan, Phase 3.* LongCat A3 (precision-variant file sets in the installer puller) is the same plumbing Inkling A4's 74.8 GB GGUF entry needs. Both the Avatar-1.5 INT8 weights (this plan, Phase 3.2) and the Inkling-Small patient-tier entry ride it.
- **D7 -- Patient-tier items clustered.** *Lives in: v1.19.2, tasks 1.1, 1.6, and 1.7.* Kimi K2 (throughput calibration copy), K1 (RAM-budget presets), K3 (determinism-across-budget test), and Inkling A4 (patient-tier catalog entry) form one patient-tier calibration cluster: K2's copy lands first, and K1 + K3 + the Inkling entry land together with K2's numbers feeding K1's presets, per the kimi comparison's own sequencing.
- **D8 -- Audio input unified into one pipeline.** *Lives in: this plan, Phase 1 (1.2 then 1.3).* Inkling A3 (audio attachment + transcribe-then-chat via curated faster-whisper) is the STT half of Airi A1 (full local voice loop). Sequenced as one pipeline: attachment + STT bridge first (1.2), then TTS + VAD/push-to-talk real-time loop on top (1.3). No duplicate STT integration.
- **D9 -- Two avatars, deliberately NOT merged.** *Lives in: this plan, Phase 3 (LongCat) and Phase 4.7 (Airi VRM).* Airi A5 (VRM presence layer in Chat) and LongCat A1 (audio-driven talking-head video in Video Lab) are different features that merely share the word "avatar". LongCat's avatar video mode is a core Phase 3 deliverable; Airi's VRM presence is cosmetic P3 and goes to the stretch phase (4.7), keeping its dependency on the voice loop's lip-sync timing.
- **D10 -- Sandbox family related but distinct, both stretch.** *Lives in: this plan, Phase 4 (4.2, 4.3, with 4.1 first).* QM A4 (durable per-project exec sandbox) and Airi A3 (code-as-action sandboxed worker + Query DSL) both extend the v1.12.0 exec-sandbox audit but solve different problems (persistence vs execution model). Kept as separate stretch items with QM A1's `ProjectScope` (4.1) sequenced before the durable sandbox, matching QM's own A1 -> A4 ordering.
- **D11 -- Router complements, never bypasses.** *Lives in: v1.19.2, task 1.5 (Hermes A5 profiles) and this plan, Phase 4.4 (router).* Atomic C3 (fast small-model command router) overlaps in spirit with the existing v1.12.0 `HarnessSelector` per-model tuning and with Hermes A5's harness profiles. Decision: Hermes A5 is a profile-addition to `HarnessSelector.ts` (v1.19.2); the router is a distinct dispatch layer and goes to stretch with the explicit invariant that routed calls never drop a permission tier.
- **D12 -- Skill-native and verify-only dedups bundled.** *Lives in: v1.19.1, task 1.4 (verify-only bundle) and this plan, Phase 4.5 (Atomic C5 code half).* QM's scope-owned-skills and crons items are verify-only dedups (Nexus-Hub `nexus skills sync` and the v1.18 OpenWorker A2 scheduler already cover them); Atomic's lessons-capture loop and playbooks map to the existing `continuous-learning` skill and the Nexus-Hub catalog. All are bundled into one verification sub-task instead of five no-op tasks. Atomic C5's thin memory-kind storage half remains code and goes to stretch (4.5).
- **D13 -- Compression patterns absorb no rivals.** *Lives in: v1.19.1, Phase 2.4.* Hermes A1 (per-model thresholds, micro-compaction, user-tail retention) is the only compression candidate across the seven sources; Atomic's per-turn result compression is already covered by existing `compress_range` / `compress_message` tools and is folded into that task's validation scope rather than tracked separately.

## Phase 1: Multimodal Chat + Local Voice Loop

**Goal**: The Chat pillar accepts images and audio against capable local models and holds a fully local real-time voice conversation -- STT, TTS, and VAD all on-device, weights via the installer.
**Prerequisites**: v1.19.2 Phase 1 (task 1.2 `modalities` gating; task 1.3 installer catalog path for STT/TTS weights). Internal ordering: 1.1 and 1.2 independent; 1.3 builds on 1.2's STT plumbing (per D8).
**Stability Gate**: Image attachments route to vision-capable local models and are blocked (with a clear affordance) for text-only models; audio attaches, transcribes locally via curated faster-whisper, and enters chat as labelled transcript content through the `redactSecrets` path; the voice loop runs push-to-talk and VAD modes fully offline with a visible capture indicator; no audio or image bytes leave the machine.
**Recommended model**: Mid-strong tier, high effort - claude-sonnet-5 (high). Rationale: new media pipelines and real-time UX over existing chat plumbing; no new outbound surface, moderate security surface (mic capture, transcript indexing). Re-confirm against the then-current model set at implementation.

## Phase 2: Browser Tool Surface

**Goal**: The coding agent can drive a local browser -- navigate, click, type, read ARIA snapshots -- as a gated DANGEROUS-tier tool family over a locally-installed Playwright dependency and an isolated browser profile, with page content treated as hostile input.
**Prerequisites**: v1.19.1 Phase 2 (loop guards protect long browser runs; provenance screening sanitizes snapshots -- Atomic's own sequencing gates C1 on C4).
**Stability Gate**: All `browser_*` tools sit at DANGEROUS tier and pass the `ConfirmationGate` per consequential action; the browser runs an isolated profile (never the user's logged-in default); ARIA snapshots enter the prompt only as provenance-labelled, scanner-screened data; a seeded injection payload in page content is flagged; hard denials and loop guards apply to browser-driven runs.
**Recommended model**: Strong tier, high effort - claude-opus-4-8 (high). Rationale: the largest new threat surface of the cycle (agent-steered outbound + indirect prompt injection); security design quality dominates. Re-confirm against the then-current model set at implementation.

**Objective**: Decide the boundaries before writing the tools.

**Prompt**:

## Phase 3: Video Lab -- Continuation + Avatar Tier

**Goal**: The Video Lab escapes the fixed 4-8 s clip ceiling via autoregressive continuation, and gains an `audio2video` avatar mode (photo + audio -> lip-synced video) gated to `diffusion-pro`, fully local.
**Prerequisites**: v1.19.2 Phase 1 (task 1.2 `audioConditioning` schema; task 1.3 quantized-weight delivery for Avatar-1.5 INT8 -- the puller build lives in v1.19.2 per D6, this plan only consumes it). The v1.19.1 task 1.3 avatar-prep skill ships alongside 3.2 per the LongCat sequencing.
**Stability Gate**: Continuation chains segments in `TimelinePreviewer.tsx` beyond a single tier clip on the existing Wan 2.2 pipeline; the avatar mode runs the official Avatar-1.5 INT8 pipeline behind `diffusion-pro` with an explicit VRAM preflight; a byte-level security scan of the imported LongCat inference tree is recorded BEFORE integration; all weight files sha256-pinned via `model_preflight.py`; generated avatar output embeds provenance metadata.
**Recommended model**: Mid-strong tier, high effort - claude-sonnet-5 (high). Rationale: substantial sidecar pipeline work plus a gated upstream-code integration with mandatory scan preconditions. Re-confirm against the then-current model set at implementation.

### Sub-tasks

#### 3.1 - Video continuation for long-form output (LongCat A2)

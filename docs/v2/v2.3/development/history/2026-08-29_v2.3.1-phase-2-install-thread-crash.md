## 2. Chronological Steps

### 2.1 Fail closed on the install QThread

**Branch**: `fix/v2.3.1-installer-field-repair` | **PR**: none | **Merged to**: not merged

**Plan specification**: Wrap `InstallEngine.run` from `_InstallThread.run` in try/except BaseException. Always emit `install_finished` with success=False and exception type plus message (no token, no argv). Re-raise KeyboardInterrupt/SystemExit after signaling. Share a helper with headless `run_step` if smaller than duplicating.

**What happened**: Added `engine/crash.py` (`format_engine_exception`, `call_step`, redaction). `_InstallThread.run` calls `report_crash`, which records `failed_steps`/`step_failures`, appends an `[ERROR]` line, and queues `install_finished` onto the engine QObject thread. Headless `run_step` now uses `call_step`.

**Key files changed**: `scripts/installer/src/nexus_installer/engine/crash.py`, `scripts/installer/src/nexus_installer/engine/installer.py`, `scripts/installer/src/nexus_installer/main.py`

**Troubleshooting**: None identified.

**Verification**: `test_thread_runtimeerror_emits_finished_without_sys_exit` plus `test_keyboard_interrupt_is_reraised_after_signal`.

---

### 2.2 GUI-thread telemetry

**Plan specification**: `ModelStepRouter` calls `events.started` from pool threads. Marshal Qt emits onto the InstallEngine QObject thread. Do not call `PhaseGroup.ensure_model_row` from a non-GUI thread. Retry once; then record in state rather than emitting from the worker.

**What happened**: `marshal_model_*` uses `QMetaObject.invokeMethod(..., QueuedConnection)` into `@pyqtSlot` methods that emit. Installing page slots stay unchanged; they now run after the queued hop. Rows are still pre-created on the GUI in `start_installation`.

**Key files changed**: `scripts/installer/src/nexus_installer/engine/installer.py`, `scripts/installer/src/nexus_installer/pages/installing.py`

**Troubleshooting**: Sender affinity of `InstallEngine` is the GUI thread even when `run()` executes on `_InstallThread`. Pool workers calling `.emit` can therefore take DirectConnection. Queued `invokeMethod` is the fix.

**Verification**: Dummy-thread marshal tests assert `QThread.currentThread()` is the `QApplication` thread after `processEvents`.

---

### 2.3 Visible crash log

**Plan specification**: Write the reason into the install state file / log path. Show it on Complete or a modal. Do not rely on windowed `sys.stderr`. HF token must not appear in the crash file.

**What happened**: `StateRecorder.on_finished` redacts `hf_token` and appends `[ERROR]` to the rolling log. Installing shows "Installation Stopped" plus `QMessageBox.critical` (suppressed if the box itself fails). Complete uses `step_failures` for the engine step. `save_state` remains temp + `os.replace`.

**Key files changed**: `scripts/installer/src/nexus_installer/background/recorder.py`, `scripts/installer/src/nexus_installer/pages/installing.py`, `scripts/installer/src/nexus_installer/pages/complete.py`

**Troubleshooting**: `isVisible()` is false when the Complete page is not shown; tests use `isHidden()`.

**Verification**: Recorder tests assert the token is absent from JSON and the log; Complete page title is "Installation Stopped".

## 6. Assumptions Made

- **Pool-thread `.emit` on a GUI-affine QObject is DirectConnection**: that matches the field crash class. Queued `invokeMethod` is the containment.
- **`report_crash` from `_InstallThread` (a real QThread) can still queue `install_finished`**: extra `invokeMethod` is defense in depth for the same affinity trap.

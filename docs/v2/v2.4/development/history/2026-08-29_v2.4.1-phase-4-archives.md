# Development Log: Archive, Restore, Delete, and Active-State Reset

**Date**: 2026-08-29
**Operator**: Benjamin Dourthe
**Assisted by**: Codex, GPT-5.6-sol
**Outcome**: Phase 4 is complete at the internal-compatible support tier. Chatbot and Studio SQLite rows use additive archive timestamps, coding JSON sessions use optional `archivedAt`, default explorers exclude archived rows, Settings restores archives by pillar, and permanent delete is explicitly irreversible. Active Chatbot, Agents, Image, and Video views cancel work before mutation and clear state only after success.

## Implementation

- Added transactional archive and restore operations without deleting messages, turns, attachments, media references, or parent identity. Archived SQLite rows detach from cascading folder foreign keys, so deleting the former folder preserves the archive and restore falls back to root.
- Added unified `sessions.archive`, `sessions.listArchived`, and `sessions.restore` IPC with partial-store error reporting.
- Added Archive immediately left of Delete. Archive copy names Settings restore; delete copy says it cannot be undone and offers Archive instead.
- Added guarded pre-disposition cancellation and post-success reset callbacks across all four pillars.
- Added Settings > Archived chats grouped by Chatbot, Agents, Images, and Videos with loading, empty, partial-error, retry, pending, and fallback restore states.

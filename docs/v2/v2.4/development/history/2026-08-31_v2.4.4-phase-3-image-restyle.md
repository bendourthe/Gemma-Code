## 2. Chronological Steps

### 2.1 Trace the packaged path (T010)

**What happened**: The reprint had no single cause; it had four, and each alone is enough to produce it. Tracing them was only possible after the decision was collected in one place, which is itself the first fix.

1. **The parser refused a trailing period.** `MAKE_RESTYLE_RE` ended in an end-anchor with no punctuation class, so "Make the puppy black." returned `null`. With no intent, `restyle` was false and the send fell through to `inferImageIntent`, which knows nothing about restyling and produced an ordinary follow-up carrying the user's raw text at strength 0.45. That is the likeliest explanation for a result that reads as "nothing happened".
2. **Restyle depended on `intent.mode`.** Even when the parse succeeded, the actual request shape came from `inferImageIntent`, which returns `txt2img` whenever no source resolves. A restyle that degraded to `txt2img` would silently reprint the original prompt and look like a successful generation.
3. **A falsy-or default** in `image_execute` treated a real `0` strength as unset and rewrote it to 0.75.
4. **The seed was never forwarded** on the image path (the video path already did this), so an edit could not be reproduced and compared.

The UI was cleared of one suspicion: the completion handler sets `media` from the event's own PNG bytes and never copies the previous `media.src` onto the new turn.

`planRestyleRequest` in `followUpSource.ts` now makes the decision as data - mode, prompt, strength, and source in one returned object - and `ImageStudioPage` sends that plan directly rather than routing through `intent.mode`. A restyle can no longer become a `txt2img`; with no source it returns `null` and the turn fails closed with `MISSING_RESTYLE_SOURCE_TEXT`.

### 2.2 Execute restyle as a real img2img (T011)

**What happened**: `image_execute` now resolves strength with an explicit `is None` check against a named `DEFAULT_IMG2IMG_STRENGTH`, so `0` survives. Seeding moved into `_seeded_generator`, which returns pipeline kwargs and degrades to an empty mapping when torch is not importable - the stub executor and the unit environment run the same code path instead of failing on an import they do not need.

The substantive addition is a clone guard. The decoded source and the produced PNG are both digested; if they match, the function raises `RuntimeNotReady` with kind `unchanged-output` rather than returning. The field symptom was a turn that looked successful and had changed nothing, and this converts exactly that into a written error. Only the img2img branch sets a source digest, so a fresh txt2img is never affected.

`RESTYLE_IMG2IMG_STRENGTH` moved 0.7 to 0.85. The plan made this conditional on 0.7 still echoing; field screenshot 3 is that observation, taken against the build where 0.7 shipped. The identity prompt already pins composition, pose, and background, which is what keeps the higher denoise from drifting to a different animal.

### 2.3 Testing and stabilization (T012)

**What happened**: The regex now accepts a trailing period, exclamation, or question mark, covered across four phrasings, each also asserting `usesSegment` stays false so a whole-image restyle never reaches SAM2. `desktop/tests/restyle-plan.test.ts` pins the plan: always img2img, always the identity prompt rather than the user's original text, strength above the follow-up value, and `null` (not a txt2img fallback) when the source is missing.

Five Python cases cover the runtime: exact strength forwarded, a seeded generator reaching the pipeline, a deliberate `0` surviving, both digests reported and differing, and - the one that matters - a stub pipeline that returns its input raising `unchanged-output`. A fake `torch` module supplies `Generator`, following the pattern already used for `torch_cuda_state` in this file.

Three existing tests had pinned `0.7` as intended and were updated to the new constant.

## 5. Plan Discrepancies

- The plan proposed instrumenting the send path with debug-only trace fields. A pure `planRestyleRequest` was used instead: it makes the same four facts assertable without adding a debug surface that ships to users, and it also removes the txt2img fall-through rather than only reporting it.
- The plan treated 0.85 as conditional on stub evidence. A stub cannot show whether a real model echoes; the field screenshot already did, so the raise was applied.

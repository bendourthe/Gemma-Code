# v2.4.1 correction Phase 1 - runtime integrity

## Outcome

Phase 1 closes T049-T054. An interrupted diffusion repair can no longer leave a permanent PID-only sentinel, and a successful model operation can no longer be reclassified as a failure because a Qt display notification returned `None`.

## Root causes and corrections

- The previous `.diffusion-repair.lock` contained only a PID and was removed only by normal `finally` cleanup. The replacement is a versioned JSON lease containing PID, process-start identity, creation time, target, nonce, host/boot identity, and attempt id. A dead or PID-reused owner is reclaimed, malformed state is quarantined, an unverifiable live owner fails closed as `REPAIR_OWNER_UNKNOWN`, and cleanup removes only the matching nonce.
- `runtime.json` remains temp-written and atomically replaced. Its schema is now version 3 and includes `repairAttempt` with attempt id, terminal status, failure code, owner PID, and start/finish timestamps. `diffusionPython` remains absent unless the verified readiness state is `ready`.
- `QMetaObject.invokeMethod` returns `None` for a successfully queued Python void slot. Casting that return value to `bool` caused a successful dispatch to be reported as failed, retried, and written into model failure state. Dispatch now treats a non-throwing call as success, queues each terminal event once, and records an internal display diagnostic only when invocation actually throws.

- `python -m ruff check` on the three changed installer modules and three focused test modules: all checks passed.
- Regression coverage includes dead legacy owner, matching live owner, PID reuse, malformed lease quarantine, process-inspection denial, nonce-safe cleanup, immutable attempt metadata, dropped GUI receiver diagnostics, PyQt void-return success, and a 100-event terminal burst.

## Support and CI impact

Support tier is supported for the local installer contract and internal-compatible for cross-platform process identity paths pending the final packaged Windows operator run. This phase does not edit CI/CD configuration. Per the approved lifecycle, it creates one local commit and does not push or start remote CI.

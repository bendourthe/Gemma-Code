# v2.4.1 correction Phase 2 - authorization and completion

## Outcome

Phase 2 closes T055-T061. SANA INT4 no longer invokes a Hugging Face authorization dialog or a dead license page. Genuine gated models retain an explicit free-account, license-acceptance, browser authorization, and manual-token flow with a prominent copyable device code. Completion warnings now read visually as warnings and do not include dropped progress telemetry.

## Catalog and release gate

- `sana-1.6b-int4` now uses public repository `nunchaku-ai/nunchaku-sana`, immutable revision `437e41b979ec875f63c18e67d55373aa5230c308`, file `svdq-int4_r32-sana1.6b.safetensors`, and SHA-256 `320be49f2501c71825b92ab1aeddd2cb589873e73fa1d9a254ca39cd6400b1a4`.
- The stale `gated`, `requiresLicense`, `licenseUrl`, and `gatedReason` metadata and SANA-specific invariant were removed.
- `scripts/installer/build/check-hf-catalog.py` resolves every declared Hugging Face file at its catalog revision and fails a release on 404, unexpected HTTP failure, or undeclared authorization requirements.

## Authorization and completion UX

- The gated dialog presents optional free sign-up, Step 1 license acceptance, Step 2 browser authorization, then a separate manual-token fallback.
- Browser device codes render in a bordered high-contrast card with a `Copy code` action and clipboard confirmation.
- The completion issue callout uses amber warning styling. Skipped optional models are labeled separately, while internal progress-display diagnostics remain in the log only.

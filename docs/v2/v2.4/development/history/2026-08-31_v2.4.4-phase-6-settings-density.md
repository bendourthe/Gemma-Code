## 2. Chronological Steps

### 2.1 Tabs and search on one row (T023)

**What happened**: `SearchInput` was a sibling *after* `models-chrome`, wrapped in a `<label>` with a visible "Search" caption, so a single text field consumed a full row plus a label line and pushed the first card off the fold. It now sits inside the chrome in a flex row beside the `tablist`, with the visible caption swapped for the existing `visuallyHiddenStyle` - the field keeps its accessible name through `label="Search models"`, so nothing is lost to a screen reader.

The row wraps (`flexWrap: "wrap"`) and the search label is `flex: 1 1 14rem` with a `maxWidth`. A narrow Settings pane therefore drops search below the tabs rather than forcing the page to scroll sideways, which is the failure mode the plan called out.

### 2.2 One action row and hug height (T024)

**What happened**: The empty space under every description was not padding; it was the action group. It was a flex *column* in the right-hand grid cell, stacking the favourite star above `RowActions`, and a two-cell grid row is as tall as its tallest cell. So the stacked actions set the row height and the description sat beside a gap it did not create.

The group is now `flexDirection: "row"` with `alignItems`/`justifyContent: center` and `alignSelf: center`, so the actions occupy one line and the row is as tall as the copy. `cardStyle` already had no `min-height`; a test now pins that so it cannot come back. Installing progress, the muted over-budget treatment, and the favourite star colour are untouched, and the icon-only Download/Remove controls from v2.4.3 are not reverted to text buttons.

### 2.3 Details copy (T025)

**What happened**: Four of the six paragraphs in Details restated a pill rendered two lines above it: `ID: ...; task: ...`, `Also agentic`, `License: ...`, and `Backend model: ...`. All four are removed. The pills keep the v2.2.9 grammar untouched (`buildModelPills` is unchanged), so the WN-7 fixture ordering still holds.

Pills are now split into label and value by `splitModelPill`, a small pure helper next to `buildModelPills` rather than in the component - the pill grammar stays the single source of what a pill says, and the component only decides how the halves look. The label renders muted at weight 400 and the value in foreground at 500, so `Company: Google` reads as a fact with a name rather than one grey run of text. A pill with no `": "` separator is treated as all value, which keeps standalone pills like a bare released-date rendering correctly.

`Best for` became a heading plus a `<ul>` of `item.strengths` instead of a comma-joined sentence, and is omitted entirely when a model has no strengths.

`Why this one` was the one judgement call. The plan allowed keeping it when it is not a restatement, and defaulting to omit otherwise. Rather than dropping it unconditionally, `whyAddsSomething` suppresses it when the text merely repeats a listed strength or the license - which is how most catalog entries phrase it - and keeps it when it genuinely adds something. That preserves the information the field where it is useful without reintroducing the duplication the screenshot complained about.

### 2.4 Testing and stabilization (T026)

**What happened**: Nine cases in `settings-models-density.test.tsx`. Three cover the chrome: search is inside `models-chrome` and shares the tablist row container, the row is a wrapping flex, the accessible name survives the hidden label, and search still filters the list. Two cover the card: the action group is a centered horizontal row containing both the star and Remove, and the card declares neither `min-height` nor `height`. Four cover Details: the four removed paragraphs are absent, the license is not printed twice, the pill label and value carry distinct colours with the value in `--fg-0`, Best for renders as bullets rather than a comma-joined line, and Best for is omitted for a model with no strengths.

One test initially matched the enclosing chip span rather than the label half, because both start with "License:". The query was narrowed to an exact match on the label text.

## 2. Chronological Steps

### 2.1 Prominent overall progress and truthful aggregation

**Branch**: `feat/v2.4.1-field-reliability` | **PR**: none | **Merged to**: not merged

**Plan specification**: Add a larger determinate overall bar with percentage, animated gradient, reduced-motion handling, and monotonic weighted progress derived from the selected install plan.

**What happened**: Added `OverallProgressBar` with a 20 px track, centered percentage, one bounded timer, animated signature gradient, accessibility descriptions, and a static reduced-motion mode. Added `WeightedInstallProgress` so the denominator includes selected components plus runtime, Hub, and optional Unsloth work, and so malformed or backward events cannot reduce progress.

**Key files changed**: `scripts/installer/src/nexus_installer/widgets/overall_progress.py`, `scripts/installer/src/nexus_installer/engine/install_progress.py`, `scripts/installer/src/nexus_installer/pages/installing.py`, `scripts/installer/src/nexus_installer/theme.py`

**Troubleshooting**:
- **Problem**: The first visible custom paint caused the focused Qt test process to terminate without a Python traceback.
- **Attempted**: Verified that the PyQt5 enum forms used by the widget existed at runtime.
- **Root cause**: `QPainterPath.addRoundedRect` received an integer `QRect` on the new paint path rather than the required floating-point `QRectF` overload.
- **Resolution**: Converted paint geometry to `QRectF`; all six widget tests then passed.

### 2.2 Frozen Unsloth resource and contained optional failures

**Plan specification**: Bundle and validate Unsloth pins, resolve resources identically from checkout and `_MEIPASS`, and keep optional Unsloth failure separate from core installation failure.

**What happened**: Added a generic safe resource resolver and routed catalogs, assets, and tuning pins through it. The PyInstaller spec now fails closed on missing or malformed pin data and bundles the validated JSON. Install steps execute through a required/optional boundary, persist terminal step results, and report core success with actionable warnings when optional work fails. Existing `step_failures` serialization was retained byte-for-byte while detailed metadata moved to `step_results`.

**Key files changed**: `scripts/installer/build/nexus-installer.spec`, `scripts/installer/src/nexus_installer/registry_paths.py`, `scripts/installer/src/nexus_installer/engine/unsloth_venv_provisioner.py`, `scripts/installer/src/nexus_installer/engine/installer.py`, `scripts/installer/src/nexus_installer/installer_state.py`, `scripts/installer/src/nexus_installer/background/recorder.py`, `scripts/installer/src/nexus_installer/background/state_store.py`, `scripts/installer/src/nexus_installer/pages/complete.py`

**Troubleshooting**:
- **Problem**: The first full installer suite run failed `TestResultContract.test_structured_failures_and_skips_included` because `step_failures` gained `required`, `error_code`, and `retryable` keys.
- **Root cause**: The new metadata changed an existing smoke-result contract even though a new result ledger already existed.
- **Resolution**: Restored the legacy three-field failure payload and kept typed metadata only in `step_results`; the completion page joins optional step ids to failure summaries.

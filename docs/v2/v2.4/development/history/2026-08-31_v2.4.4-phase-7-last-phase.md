### 2.5 Terminal CI/CD reconciliation (T032)

**What happened**: Provider detected as GitHub Actions, 19 workflows. Thirteen contract fields pass. Three do not, and one of them is load-bearing for this plan's own final sub-task.

Every substantive workflow filters `pull_request` to `main`. PR 58 targets `develop`. On a develop-targeted pull request, `commitlint` is the only workflow that runs on the pull_request event - CI, CodeQL, coverage-diff, installer-tests, and shell-build all sit out. The push to the feature branch does trigger `ci.yml` through its push trigger, so the branch head is tested, but the **merge result** is not, and testing the merge result is the whole purpose of the integration gate the plan describes. This is v2.4.3 QG-5, and it is why the plan's step 7.9 phrasing ("wait until every required check reaches a terminal state") would otherwise be vacuous here.

The other two failures: `ci.yml` has 17 top-level jobs and no always-resolving aggregate required check, and it declares no top-level `permissions:` block so it inherits the repository default.

Per the plan, QG-5 stays proposed and not applied pending explicit approval. No workflow file was edited in this phase or in any earlier one. The smallest closing change is named with its cost and risk in the evidence file.

Cross-installer parity: the repository ships four installer workflows. No declarative parity gate was added and the real installers were not executed on their target operating systems. This is material precisely because this cycle changed the Diffusers pin those installers provision, so it is recorded as DF-1 rather than claimed as covered.

**Comparison verdict: not PASS.** A green run would not change that, because none of the three failing fields is exercised by a run.

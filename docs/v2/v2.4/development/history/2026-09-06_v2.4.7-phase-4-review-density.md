## 2. Chronological Steps

### 2.1 Facts column carries storage and time (T016)

**What happened**: v2.4.5 had deliberately moved the estimates under the model list, because the operator asked for them there. This cycle's screenshot 3 asked for the opposite, and the reason is now clearer: they are install facts, so they belong beside install path, components and GPU rather than trailing a list of models they describe only indirectly.

Storage renders on one line. The already-downloaded total became muted parenthetical text on that same line rather than a row of its own. It is still shown, because presenting only "~2 GB" after a 233 GB selection invites the opposite worry - that the selection was silently dropped.

### 2.2 Counters and category chips (T017)

**What happened**: The summary and the category headings shared one text level, so "Models: 7 selected (7 already downloaded, 0 to download)" read as though it were another category label. Screenshot 4's mockup separates them, and that is what the counter row does: three cells - SELECTED, READY, TO DOWNLOAD - at `FS_H2` above the category groups, which render unchanged beneath.

The counters are derived from the same per-id computation the category rows use, so they cannot disagree with what they summarize. A test asserts the three numbers against a known selection precisely because a summary that contradicts its own contents is worse than no summary.

### 2.3 Testing and stabilization (T018)

**What happened**: Seven cases in `TestReviewDensityV247` cover the one-line storage, the omitted already-downloaded clause when there is none, the counter row's presence and labels, counters agreeing with the categories, the counters' distinct font size, ordering above the categories, and an all-downloaded selection reading as a short run.

Eight existing tests encoded the pre-restructure contract and were updated rather than deleted: the `<tr>` counts now include the counter row, the "N selected" sentence assertions became counter assertions, and `test_estimate_sits_under_the_model_list` was inverted to `test_estimate_sits_in_the_facts_column`.

**Two failures were my own error and both are worth recording.** One test read `self._page(state)._facts_label.text()` without holding the page, and Qt deleted the underlying widget before the label was read. The fix for that then caused the second: holding page references made the full suite die at teardown with `Windows fatal exception: code 0x80010108` (COM `RPC_E_DISCONNECTED`) - exactly the trap v2.4.5 Phase 2 hit by storing a `QWidget` on a card record. The helper now returns extracted text rather than a page, so no Qt object outlives the test that made it.

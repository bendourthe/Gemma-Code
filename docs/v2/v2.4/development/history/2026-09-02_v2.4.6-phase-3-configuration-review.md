## 2. Chronological Steps

### 2.1 Unsloth Compatible is selected (T012)

**What happened**: `_apply_unsloth_host_lock` checks Unsloth and sets `install_unsloth` when the host is Compatible and the user has not touched the box. `_on_unsloth` sets `_user_touched_unsloth` so an uncheck survives `showEvent`. Incompatible still forces unchecked and locked. Help text drops "Off by default" on Compatible hosts.

### 2.2 VS Code Features checkbox and 1.136 (T013)

**What happened**: `SUPPORTED_VSCODE_MAX_EXCLUSIVE` is `1.137.0`. `SUPPORTED_VSCODE_MINORS` includes `(1, 136)`. Copy uses `1.134, 1.135, or 1.136`. The compact extension control moved into Configuration Features (checkbox plus detection, no nested card). Replace-copy stays on that one checkbox. The separate VS Code Extension Settings segment is gone. `engines.vscode` stays `^1.134.0` (vsce cannot take a compound range). Electron rebuild pin stays 42.8.1 (WN-2). Insiders/Cursor/Windsurf stay unsupported.

### 2.3 Remove Gemma preview and Video2X; categorize Review (T014, T015)

**What happened**: Configuration no longer renders Model/Temperature/Top-P/Top-K or the Optional video enhancement block. Review groups `selected_model_ids` by catalog tab order (Embeddings, Chat, Agentic, Image, Video, Audio, Document), omits empty groups, and keeps downloaded/pending marks. Unknown ids land under Other. Headless `--model` still renders by name. Facts card aligns to the top and uses a Maximum vertical size policy so it hugs content.

### 2.4 Testing (T016)

**What happened**: Qt and review tests cover Unsloth default-on, user uncheck, 1.136 enabled, absent Gemma/Video2X strings, Features parent for the VS Code checkbox, and Image heading containing `juggernaut-xl-v9` without mixing `gemma4:e4b`.

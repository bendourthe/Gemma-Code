# v2.4.1 correction Phase 6 - compact Agents workspace

## Outcome

Phase 6 closes T083-T088. Agents now waits for the live installed model catalog before showing its picker, resolves a deterministic ready model from the active session, saved favorite, installer recommendation, or canonical order, and does not let a later catalog response overwrite a manual choice. Workspace controls and Chat, Memory, and Activity share one responsive header, while workspace-grouped History is a compact collapsible section in the main pane instead of a permanent second rail.

## Model selection contract

- The static `DEFAULT_MODEL_ID` and fallback catalog rows are no longer visible picker values during hydration.
- A slow catalog displays `Loading models...`.
- Selection order is explicit valid session model, ready user favorite, installer `recommendedByTask.agentic`, then the first ready model in the installer snapshot order.
- Missing or unavailable recommendations fall through safely, and a manual selection is persisted as the agentic favorite.
- A late catalog refresh cannot replace a manual selection. If no ready model exists, session start is blocked with an actionable Settings message.

## Workspace layout and navigation

- Workspace chips and add, replace, and remove actions occupy the flexible left side of the header; the three tabs align right and wrap with the header at narrow widths.
- History uses the existing `FolderTree`, selection, refresh, archive, delete, cancel, and active-session reset callbacks, but now scrolls independently under the header and can collapse fully.
- Memory explains `Knowledge saved or indexed for these workspace folders.`
- Activity explains `Tools, approvals, and runtime events for this workspace.`
- Legacy `trace` links still migrate to Activity, while removed or unknown tab ids migrate to Chat.

# Development Log: Multi-Root Workspace Core and Security

**Date**: 2026-08-29
**Operator**: Benjamin Dourthe
**Assisted by**: Codex, GPT-5.6-sol
**Outcome**: Phase 6 is complete at the internal-compatible support tier. Coding sessions now persist a canonical multi-root workspace identity, headless and scheduled execution is confined to an immutable selected-root union, and the desktop shell has a least-privilege native multi-directory picker.

## Implementation

- Added `WorkspaceScope` with an order-independent root-set identity, ordered display roots, explicit primary root, display label, timestamps, Windows case normalization, realpath validation, a two-second canonicalization ceiling, OS-home default, and tolerant migration from legacy `workspacePath` records.
- Added an atomic workspace registry under the Nexus data home. Workspace storage completes before session allocation, so malformed or unavailable registry writes cannot silently start a process-cwd session.
- Extended coding start, list, resume, persisted-session, JSON-RPC, and JSON CLI contracts with `workspaceId`, `workspaceRoots`, and `primaryRoot` while retaining `workspacePath` input for one compatibility cycle. The production sidecar now wires the durable coding session store as well as the workspace registry.
- Snapshotted workspace scope into interactive and scheduled headless runs. Later array or UI changes cannot widen an active run. Relative paths and default terminal cwd use the primary root; absolute paths may target any selected root.
- Reworked headless file authorization and the shared VS Code path guard around realpath-aware union containment. Cross-root endpoint pairs require both source and destination to be selected. Removed roots, traversal paths, and symlink/junction escapes fail closed.
- Passed the full root set into the OS sandbox writable policy, per-root `.nexus/permissions.deny`, MCP registration and deny merging, deterministic provenance-labeled instruction discovery, document attachment parsing, and workspace-scoped memory ingest.
- Added Tauri's official dialog plugin with only `dialog:allow-open`, directory-only multi-select, serialized frontend requests, cancel-as-no-change behavior, and a Rust canonicalization command that validates existing absolute directories and deduplicates equivalents.
- Added the npm and Cargo dialog dependencies at resolved version 2.7.2. The desktop `Cargo.lock` is force-tracked for this application dependency even though legacy ignore rules exclude Cargo locks by default.

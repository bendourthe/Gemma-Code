## 2. Chronological Steps

### 2.1 Bump the media-runtime Diffusers pin (T014)

**What happened**: The plan named 0.37.1 because that is the version whose published docs mention `SanaVideoPipeline`. Documentation is not the same claim as "this is where it first appeared", so the actual wheels were inspected rather than trusted:

| Release | `SanaPipeline` | `SanaVideoPipeline` |
|---|---|---|
| 0.34.0 (current pin) | yes | no |
| 0.35.0 | yes | no |
| 0.36.0 | yes | **yes** |
| 0.37.0, 0.37.1 | yes | yes |

**0.36.0 is the earliest release that carries both.** The plan instruction on a compatibility conflict was to take the oldest release that exports the class, and taking it unconditionally is the smaller move regardless: two minor versions instead of three, on a pin that every Image and Video model on the host depends on.

The compatibility question was answered from the distribution metadata rather than assumed. 0.36.0 declares no hard `torch` or `transformers` dependency at all (both appear only under the `dev` and `test` extras), and its real requirements are `huggingface-hub>=0.34.0`, `safetensors>=0.3.1`, `Pillow`, `numpy`, `filelock`, `httpx<1.0.0`, `regex`, `requests`, and `importlib_metadata`. Nothing there conflicts with the existing torch 2.3.0 + cu121 stack, transformers 4.53.2, safetensors 0.5.3, Pillow 11.2.1, or numpy 1.26.4, and `requires_python >=3.8.0` covers the cp311/cp312 ABIs. No known gap was needed.

Both lockfiles moved together: `runtimes/diffusion/runtime-lock.json` and the `diffusion` block of `scripts/installer/build/versions.lock.json`. The existing `test_repair_lock_matches_installer_diffusion_lock` guard would have failed had only one moved. No other copy of the pin exists in the tree.

The import probe (`from diffusers import SanaPipeline, SanaVideoPipeline`) cannot be executed here: torch is not installed in this environment, and Diffusers resolves pipeline classes lazily, so the probe needs the full media venv. What was verified instead is stronger than a name lookup - the 0.36.0 wheel contains `diffusers/pipelines/sana_video/pipeline_sana_video.py`, `pipeline_sana_video_i2v.py`, and `models/transformers/transformer_sana_video.py`, and exports both class names from its top-level `__init__`. The live probe on the packaged NVIDIA host stays a last-phase operator item.

### 2.2 Honest import errors (T015)

**What happened**: The video loader already mapped a failed import to `diffusers-missing`, but its message was the exception type joined to the exception text - literally the raw `ImportError: cannot import name ...` string from screenshot 4, only with a kind attached. Image SANA had no guard at all: the `SanaPipeline` import sat bare inside `_load_text_pipe`, so a missing class fell through to the generic handler in `image_execute` and surfaced as an untyped `image runtime is not ready: ImportError: ...`.

Both now go through one `_import_diffusers_class(surface, name)` helper that raises `RuntimeNotReady` with kind `diffusers-missing` and a sentence naming the class, the version actually installed, and what to do about it. Naming the installed version matters because it is the single fact that separates "the pin is wrong" from "the model directory is incomplete" - two failures that otherwise read identically to an operator. Version lookup is itself wrapped, so the error sentence can never fail while being constructed.

`model-layout-invalid` for incomplete weight trees is untouched, and the 16 GB default video model stays `wan2.1-t2v-1.3b`.

### 2.3 Testing and stabilization (T016)

**What happened**: Four contract tests in `test_media_runtime_contract.py` assert both lockfiles pin at least 0.36.0, that exactly one `diffusers` entry exists and uses an exact-version operator (a range would let a future resolver silently drop the class again), and that the torch and transformers pins are unchanged by this bump. `MIN_SANA_VIDEO_DIFFUSERS` is a named tuple with the verification date in its comment, so a later reader can see what was checked and when.

Three runtime tests in `test_real_execute.py` inject a fake `diffusers` module reporting version 0.34.0: a missing `SanaVideoPipeline` and a missing `SanaPipeline` each produce `diffusers-missing` with the class name and version in the sentence and no `cannot import name` text, and a present `SanaVideoPipeline` is used with `WanPipeline` never called.

## 2. Chronological Steps

### 2.1 Center the hairline (T005)

**What happened**: The rule's own margin was already symmetric (`var(--space-1) 0`). The asymmetry came from the element below it: `FolderTree`'s header added `padding: var(--space-2) var(--space-3)`, so the gap under the rule was `space-1 + space-2` while the gap above it was `space-1` alone. Measuring the rule in isolation would have shown nothing wrong, which is why the previous cycle missed it.

The gap is now stated once. `Sidebar` exports `HISTORY_HAIRLINE_GAP` and applies it as `marginBlock` on the rule; `FolderTree`'s header declares `paddingTop: 0` after its shorthand so it contributes none of its own. Compact mode keeps its inline inset via `marginInline` so the short rule still does not overlap the icon rail.

### 2.2 Pull titles to the rail (T006)

**What happened**: Expanded chat rows rendered a `<span style={{ width: 12 }}/>` in the folder-chevron slot so chat labels would line up under folder labels. Combined with the row's `gap: var(--space-2)`, that put roughly 20px between the 4px selection rail and the title. The spacer is removed for chat rows; folder rows keep their real chevron.

A second, smaller offender was found while testing: the depth spacer `<span style={{ width: node.depth * 12 }}/>` renders even at depth 0, where a zero-width element still claims a flex `gap` slot. It is now rendered only when `node.depth > 0`, so a top-level chat title is genuinely the first thing after the rail.

### 2.3 Archive All and Delete All (T007)

**What happened**: Both actions sit on the existing header toolbar beside new-folder and new-chat, and both are disabled when the list is empty. Each opens one confirm portaled to `document.body`, the same host the per-row delete already uses, so the dialog is centered on the window rather than inside the sidebar column.

Two decisions worth recording. First, the target set comes from walking `tree` recursively, not from `flat`: `flat` holds only what is currently visible, so using it would have made "Delete All" silently mean "delete the rows I can see" and leave chats inside collapsed folders behind. A test covers exactly that case. Second, the id list is captured when the dialog opens rather than re-read on confirm, so a background refresh cannot widen a destructive action the operator has already read the count of.

The loop is sequential rather than `Promise.all` so a partial failure stops at the first bad id and surfaces one error, instead of leaving an unknown subset applied. Archive All is only offered when the client actually implements `archiveChat`.

### 2.4 Testing and stabilization (T008)

**What happened**: Eight cases in `FolderTree.test.tsx` cover the header padding, the title-next-to-rail position, the retained folder chevron, archive-all and delete-all each acting on the whole tree, the collapsed-folder reach, cancel as a no-op, and both actions disabled on an empty list. Archive and delete are told apart with spies, so Delete All cannot pass by archiving and Archive All cannot pass by deleting. One case in `sidebar-history-host.test.tsx` pins the symmetric rule margin.

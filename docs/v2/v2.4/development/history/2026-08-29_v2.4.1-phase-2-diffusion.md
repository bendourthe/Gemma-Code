## 2. Chronological Steps

### 2.1 Pinned host-specific artifact contract

Extended `scripts/installer/build/versions.lock.json` with supported Python ABIs, backend selection, exact runtime requirements, official PyTorch wheel URLs, filenames, byte sizes, and SHA-256 values for Windows and Linux NVIDIA paths, plus an explicit Apple MPS path. The PyInstaller spec validates and bundles the manifest as `installer-build/versions.lock.json`.

The provisioner resolves the active Python ABI before choosing artifacts. CUDA wheels are downloaded into cache paths keyed by SHA-256, resumed through `.partial` files, size- and hash-verified before pip receives them, retained for verified offline reuse, and rejected on checksum or size mismatch. Cancellation retains partial data for a later retry.

### 2.2 Active staged provisioning and truthful runtime state

`RuntimeProvisioner` now detects selected image or video tasks and invokes `DiffusionVenvProvisioner`. A matching environment fingerprint is reused only after a fresh smoke. A stale or missing environment is rebuilt in a staging directory and atomically swapped after success, preserving the prior healthy environment on failure. The frozen executable is never treated as a Python interpreter, preventing recursive `NexusSetup.exe -m venv` launches.

`runtime.json` schema 2 records diffusion status, backend, Python and torch versions, CUDA version, CUDA/MPS availability, GPU name, smoke timestamp, manifest fingerprint, provisioner version, typed failure code, and retryability. The legacy `diffusionPython` value is populated only for a ready runtime.

### 2.3 Sidecar fail-closed behavior

The sidecar accepts schema-v2 diffusion paths only when status and smoke evidence match the declared backend. Failed or malformed readiness sets `NEXUS_DIFFUSION_NOT_READY`; `runtimeFactory` returns an unavailable runtime with actionable copy for unsupported hardware, missing Python, failed integrity, offline download, cancellation, CPU-only torch, smoke timeout, or concurrent repair. In-memory and explicit development overrides remain available for tests and development.

### 2.4 Test isolation and native dependency repair

The first full desktop run found a local `better-sqlite3` binary compiled for Node ABI 146 while the active Node runtime required ABI 137. This was an environment mismatch, not a product failure. `npm rebuild better-sqlite3 --silent` repaired the local dependency without tracked file changes; the nine affected files then passed 62 tests, and the subsequent full desktop suite passed.

A focused installer run was stopped when an existing unit fixture reached the newly introduced live artifact seam. The fixture was corrected to mock verified cache retrieval, and every subsequent test run remained network-isolated.

## 6. Assumptions Made

- A selected catalog task of `image` or `video` requires diffusion provisioning.
- NVIDIA selections must not silently fall back to CPU torch.
- A stored path is not readiness evidence; schema-v2 smoke fields are authoritative.
- Node and chat are required core capabilities, while failed media provisioning is a contained, repairable capability failure.

The Constitution Check was re-run conceptually. No version constitution file exists, so the check remains skipped as documented in the approved plan.

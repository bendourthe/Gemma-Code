# v2.4.1 correction Phase 3 - media generation recovery

## Outcome

Phase 3 closes T062-T068 at the automated-contract level. Image Studio and Video Lab now share one typed runtime-readiness service, offer a bounded in-place repair action, preserve the pending prompt and attachments, and retry the same assistant turn once after repair. Default image and text-to-video models now install complete immutable Diffusers layouts instead of lone or incompatible checkpoint fragments.

## Runtime and model corrections

- The sidecar exposes `ready`, `repairable`, `repairing`, and `failed` states through one `MediaRuntimeService`, detects live versus interrupted repair ownership, launches the pinned in-place repair module once, reports progress, and supports cancellation and log-location access.
- The installer retains the diffusion interpreter and working directory in failed-but-repairable contracts. `runtimes/diffusion/repair.py` reinstalls exact packages from `runtime-lock.json`, runs import, CUDA/backend, and encoder smoke checks, and publishes readiness atomically.
- RealVisXL V5 and Juggernaut XL v9 now use complete fp16 Diffusers layouts at immutable revisions with exact file hashes. Wan 2.1 T2V now uses the official complete Diffusers repository at immutable revision `0fad780a534b6463e45facd96134c9f345acfa5b`; unsupported 8 GB and 12 GB default routes were removed, while the 16 GB recommendation remains.
- The Python executor distinguishes complete Diffusers layouts, standalone SDXL checkpoints, and invalid partial layouts. Wan text-to-video uses `WanPipeline`, enforces a `4k+1` frame count, writes through a unique partial path, finalizes with the pinned encoder, verifies the MP4 file-type box, and replaces the destination atomically.
- The Hugging Face preflight now honors the selectable-model boundary and traverses variant-backed weight manifests. This remediates the inherited false failures for Inkling and LongCat while excluding non-selectable ControlNet auxiliaries from the user-selectable release gate. The full live catalog preflight passes.

## Recovery UX and operator harness

- Runtime failures render an inline recovery card with the cause, repair progress, cancel, retry, and log-location actions. The pending animation remains outside the message bubble.
- A successful repair reuses the original assistant message id and creates neither a second user prompt nor a duplicate assistant turn. Failed repair preserves the original prompt and attachments.
- `scripts/installer/build/smoke-installed-media.ps1` launches the exact installed sidecar and calls the same IPC methods as the studios. It creates a unique disposable output root, validates PNG signature/decode/dimensions/non-zero variance and MP4 `ftyp`/codec/duration/dimensions/frame count, records SHA-256 and installer/runtime/catalog/GPU metadata, emits JSON, and exits non-zero if either artifact fails.

## Packaged field gate and CI impact

The implementation and installed-artifact harness are supported by automated contract tests. Actual CUDA model load, PNG creation, video generation, and encoding through the exact packaged installer remain not proven here and are the mandatory Phase 7 operator gate. Publication remains blocked unless that run produces both validated artifacts. This phase changes no remote pipeline configuration, creates one local commit, and does not push or start CI.

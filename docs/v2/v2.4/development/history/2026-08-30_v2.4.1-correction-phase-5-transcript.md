# v2.4.1 correction Phase 5 - transcript layout and token provenance

## Outcome

Phase 5 closes T076-T082. Provider request telemetry is now distinct from the token counts attributable to visible user, reasoning, and assistant output text. Transcript metadata appears inside each bubble above its content, reasoning remains collapsed above assistant output, ordinary text clicks no longer open a duplicate preview panel, and pending chat status has an inset responsive lane.

## Usage contract

- `RequestTokenUsageV1` stores provider request totals, including system context and history, with exact provider provenance and raw counters.
- `MessageTokenUsageV1` stores only text attributable to one visible message. The current local fallback uses the existing UTF-8 byte estimator and labels the result estimated instead of presenting provider request totals as message counts.
- User bubbles display input only and expose no hover breakdown. Assistant bubbles display reasoning plus visible output only; their hover detail never includes request input.
- The context meter still consumes the latest exact request snapshot, so the provider's full context total remains available without leaking into assistant bubble attribution.
- New usage envelopes persist through Chat SQLite, Studio SQLite metadata, and Coding JSON session files. Legacy flat fields remain readable for older records.

## Interaction and layout

- Time and token metadata are the first content row inside each message article.
- Provider-exposed reasoning stays in an independent collapsed disclosure immediately above the assistant bubble.
- Whole text messages are no longer buttons and do not open `PreviewPane`; media-specific image/video lightboxes remain available.
- Pure pending chat status is unbubbled, width-constrained, padded from the transcript edge, and uses border-box sizing with visible overflow.

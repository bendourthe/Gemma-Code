## 2. Chronological Steps

### 2.1 vscode-free allowlist (T018)

**What happened**: `core/registry/ownedSelection.ts` parses `~/.nexus/selected-models.json` and fail-closes to an empty owned set when the snapshot is missing. `core/registry/ownedAgentic.ts` intersects catalog agentic (`task === "agentic"` or `agentic === true`), owned ids, and InstalledProbe presence. Default is `recommendedByTask.agentic` when that id is owned (16 GB: `gemma-4-12b-it-gguf`). `modules/coding/config/settings.ts` re-exports the enum helpers. Plan path `src/config/settings.ts` does not exist.

### 2.2 Picker and `/model` (T019)

**What happened**: Command `nexus.coding.selectModel`, status bar, and Chat `/model` share the allowlist. Registered in extension-only, proxy (local snapshot, not the daemon placeholder), and safe-mode `DECLARED_COMMAND_IDS`. Empty owned set posts the Settings message. Unknown id posts a structured Settings error.

### 2.3 Hub loop stays on switch (T020)

**What happened**: `AgentLoop.setModelName` and `StreamingPipeline.setModelName` follow `nexus.llm.modelName`. Skills, hooks, ToolRegistry, ConfirmationGate, and pathGuard stay on the same loop. No network LLM providers.

### 2.4 Tests (T021)

**What happened**: Fixture leftover-coder is installed but unowned and absent from the enum. Empty snapshot is empty, not `ollama list`. Tool dispatch and ConfirmationGate remain after switching `gemma-4-12b-it-gguf` to `qwen2.5-coder:14b`. Full vitest: 5781 passed, 12 skipped. `tsc -b` clean.

## 2. Chronological Steps

### 2.1 Carry the report on state (T005)

**What happened**: `InstallerState` gained `installed_report` and `pending_models_gb`. `selected_models_gb` deliberately keeps its meaning as the full selection total, so no existing consumer silently changes behavior; the pending figure is a new, separate field.

The import produced a circular import immediately: `installer_state` imports `installed_models`, which imports `hf_weights_puller`, which imports `hf_auth`, which imports `installer_state`. Rather than weaken the probe's reuse of the puller's path helpers (Architecture Decision 3 exists to keep one definition of where weights live), the annotation moved under `TYPE_CHECKING` and the default became a factory doing a function-level import. The dataclass field is typed and the cycle is gone.

### 2.2 Downloaded pill (T006)

**What happened**: The pill is an additional chip in the card's existing wrapping name row, next to the size pill. It is deliberately not folded into `_card_status`, whose badge has a priority chain (Required > incompatible > Recommended > Compatible). Overloading it would mean a downloaded model that does not fit the host loses its incompatibility warning -- the case where that warning matters most. A test asserts both are present together on a 4 GB-VRAM host.

`_ModelCardState` gained a `downloaded` flag mirrored from the card, so callers can ask about the state without reaching into the widget tree.

### 2.3 Auto-selection on load (T007)

**What happened**: `refresh_from_state` now probes, then unions already-downloaded ids into the selection, then rebuilds. Two guards, both of which turned out to be load-bearing:

`_downloaded_autoselected` makes it a first-load action. `_user_touched` makes it defer to the user. The second guard was added because the existing suite caught its absence: `test_user_toggle_marks_touched_and_survives_refresh` deselects a model, refreshes, and expects it to stay deselected. Without the guard, auto-selection silently undid the user's edit. Deselecting an already-downloaded model to skip its verification pass is a legitimate thing to want on a reinstall, so the fix is correct behavior rather than a test accommodation.

Ids on disk but absent from the catalog are not injected into the selection, since the engine would be handed an id it cannot route.

### 2.4 Testing and stabilization (T008)

**What happened**: 11 cases in `test_typed_catalog_downloaded.py`, plus a change to the existing suite that matters more than the new tests.

**The probe made the suite host-dependent.** `test_user_toggle_marks_touched_and_survives_refresh` failed on this machine because the default probe reads the real model stores under the user's home, and `juggernaut-xl-v9` genuinely is downloaded here. The same suite on a clean CI runner would have passed. That is the flakiness class v2.4.4 shipped and had to fix in CI, so it was closed at the source: `TypedCatalogPage` takes an `installed_probe` callable, the existing test factory injects an empty report, and tests that care about detection inject their own.

Two of the new tests were initially vacuous and were rewritten. `test_downloaded_models_are_selected_on_load` used `wan2.1-t2v-1.3b`, which is already a tier default at 8 GB VRAM, so it would have passed with auto-selection entirely removed. Enumerating the test catalog's defaults per tier showed `qwen2.5-coder:7b` is a default at no tier, so both auto-selection tests now use it and one asserts a baseline page does NOT select it.

**A Qt teardown crash was introduced and removed.** An early version stored the `QWidget` on `_ModelCardState` so tests could find the pill. The full installer suite then died at 100% with `Windows fatal exception: code 0x80010108` (COM `RPC_E_DISCONNECTED`) -- widget references outliving `QApplication` teardown. The reference was removed rather than worked around; the pill is now tested by constructing a `_ModelCard` directly, which is a better-scoped unit test anyway. An intermediate attempt to name cards `modelCard-<id>` was also reverted: ids contain `:`, which Qt parses as a pseudo-state in a stylesheet selector.

## 5. Plan Discrepancies

- The plan did not anticipate an injectable probe. It became necessary once the default probe made an existing test host-dependent, and it is the same defect class as the v2.4.4 shuffle flake, so it was fixed at the source rather than worked around.

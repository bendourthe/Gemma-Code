# Development Log: Transcript Chrome and Reasoning Disclosure

**Date**: 2026-08-29
**Operator**: Benjamin Dourthe
**Assisted by**: Codex, GPT-5.6-sol
**Objective**: Make response generation visually quiet, make usage metadata compact and accessible, and show only explicit model-provided reasoning in a collapsed disclosure.
**Outcome**: Phase 3 is complete at the internal-compatible support tier. Pending assistant work no longer renders inside a message bubble. Completed user and assistant messages use distinct neutral surfaces, place time and compact token totals below the bubble, and expose the input/reasoning/output breakdown on hover or keyboard focus. Explicit provider reasoning is bounded, redacted, persisted separately across Chatbot, Agents, Images, and Videos, and collapsed above assistant output. Count-only reasoning never creates a disclosure.

---

## 1. Implementation

- `MessageBubble` now treats a content-free pending message as an accessible status rather than a response article. Partial streamed output remains a normal response bubble.
- Semantic bubble tokens provide a subtle user/assistant distinction without the downloaded-model green wash.
- `bubbleTokenMetadata` produces the italic `(X tokens)` label and a focusable detail string that distinguishes known, estimated, and unavailable values.
- `ReasoningDisclosure` is collapsed by default, keyboard operable, bounded to 65,536 characters, and rendered only for non-empty explicit reasoning text.
- Sidecar protocols gained a bounded `reasoning_delta` event and optional persisted `reasoningText`. Chat SQLite, coding JSON, and Studio SQLite retain the field independently from visible output.
- Reasoning is redacted before storage. Older coding session files and existing SQLite databases remain readable because all added fields and columns are additive and optional.

## 3. Coverage and Failure Behavior

- Explicit reasoning stream, count-only responses, redaction, bounded protocol validation, JSON schema-v2 loading, SQLite round trips, studio adapters, collapsed/expanded UI, keyboard focus, tooltip copy, neutral colors, and bubble-free pending states are covered.
- Empty, absent, or count-only reasoning produces no disclosure.
- Malformed or oversized reasoning events fail protocol validation. Stored reasoning is sanitized and truncated before persistence.
- Token fields that are unavailable remain labeled unavailable rather than being invented.

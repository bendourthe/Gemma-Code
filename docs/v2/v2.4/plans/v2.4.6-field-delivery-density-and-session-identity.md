v2.4.4 and v2.4.5 did not ignore these screenshots by accident. The operator then ran that wizard, saw the v2.4.5 Review downloaded-marks (so the wizard was new), launched the desktop, and saw the pre-density UI. That split is the first defect this plan fixes. After the payload is honest, every remaining screenshot is implemented in this cycle. Nothing in the operator list is deferred, parked as a known-gap, or marked "already done" because a prior plan ticked a checkbox.

The wizard and the desktop are one product. Phase 1 makes the installer embed and overwrite this tree's desktop and VSIX, and opens maximized. Phases 2-3 densify the wizard and put VS Code plus Unsloth on the Features list. No phase except the last pushes, opens a pull request, or starts remote CI. Each earlier phase ends with automated tests, session history, and one local commit. Package metadata stays 2.4.1 until `/update release`; the desktop still shows a build fingerprint so a 2.4.1 package cannot hide a stale payload.

## Why v2.4.4 and v2.4.5 looked ignored

This is the answer the operator asked for first. It is also the reason Phase 1 exists.

1. **The wizard and the desktop are not the same artifact.** `scripts/installer/build/build-windows.ps1` embeds a Tauri NSIS bundle from `desktop/src-tauri/target/release/bundle/nsis/` (or a downloaded `Nexus-Desktop_${Version}_x64-setup.exe`). Rebuilding only PyInstaller produces a new wizard (v2.4.5 downloaded-marks, two-column Review) while still installing whatever NSIS file was already staged. The operator screenshots prove that split: Review is the v2.4.5 wizard, Settings Details still print `ID:` / `Also agentic` / `Backend model:`, which v2.4.4 T025 deleted in source.

2. **Prior plans explicitly refused this work.** v2.4.3: "does not reopen the VS Code merge". v2.4.4: "does not reopen ... VS Code merge, installer two-column layout, Unsloth lock, or picker recommend order". v2.4.5: "does not reopen the v2.4.4 transcript, restyle, SANA-pin, liveness, or Settings work". Session rename, Stop on all four tabs, GPU occupancy, installer maximize, Setup compactness, Unsloth auto-check, VS Code-on-1.136, categorized Review, and removing the Gemma/Video2X Configuration block were never in those Goals.

3. **The written Goal sometimes contradicted the operator.** v2.4.3 AD7 and v2.4.4 AD10 moved origin, license, and long metadata *into* Details. Today's screenshot 6 asks to *delete* Details and keep a three-line card. Tests then pinned the old Details accordion (`settings-models-density.test.tsx` still requires Details). That is how a "density" phase can be green and still look like screenshot 6.

4. **Empty-state layout was not the layout the hairline tests used.** `FolderTree` only renders `copy.paneTitle` ("Chats") when the tree is non-empty. Screenshot 5 is the empty state: toolbar icons, "No chats yet.", no title. The hairline therefore sits against Videos with nothing named below it. v2.4.4 T005 equalized `marginBlock` assuming the Chats header existed.

5. **Tests asserted the wrong absence.** `ChatPage.test.tsx` comments that assistant token counts are omitted when the fake session reports no usage, and only asserts `message-tokens-` length `>= 1` (the user bubble). `estimatedMessageUsage` is computed, but a persist/reload or a mapping hole can drop `messageUsage` without failing CI. Screenshot 8 is that hole in the field.

6. **GPU Idle is a scheduler hole, not a dead nvidia-smi.** `GpuStatusFooter` shows Idle when `sample.idle` is true. `createTelemetryStream` sets idle from `scheduler().active === null`. Chat and many Image/Video turns never enqueue `GpuScheduler`, so the footer stays Idle. `nvidia-smi utilization.gpu` can also read 0 on this laptop even while VRAM moves; the sidecar query has no `C:\Windows\System32\nvidia-smi.exe` fallback (the installer GPU page does). The composer "0%" next to Context is context-window fill, not GPU; an empty "Hi" session at 0% is expected. The defect to fix is the sidebar GPU line.

7. **Juggernaut is a real catalog model, and Review already listed it.** `core/registry/catalog.json` id `juggernaut-xl-v9`. `recommended.json` uses it as the 8 GB and 12 GB image default; 16 GB image default is `realvisxl-v5`. v2.4.5 auto-selects anything already on disk; the host had `~/.nexus/models/weights` for Juggernaut (6.7 GB) and Review screenshot 4 column 2 includes `juggernaut-xl-v9`. The Image tab then resolved a default from `installedModelsForType` + `recommendedByTask.image` or `ready[0]`. An uncategorized Review made that selection easy to miss.

8. **Known-gaps recorded "not observed" and then the next plan moved on.** v2.4.4 MT-1 through MT-6 and v2.4.5 MT-1 are still open as packaged observation. A later plan that does not reopen those rows will look like the work was skipped. This plan treats an unobserved desktop screenshot as *not landed*, even if source and tests exist.

- Sidebar: hairline is equally spaced between Videos and the always-visible "Sessions History" title. New-folder and new-session icons sit on that title row, left-aligned after the title. Every chat-noun string is Session except the Chatbot tab label.

## Architecture Decisions

1. **A rebuilt wizard that installs a stale desktop is a failed build.** `build-windows.ps1` must run (or require) a current `desktop` `npm run build:shell` whose NSIS version and hash are written into `desktop-payload/manifest.json`. The frozen installer refuses to install desktop if the payload manifest is missing. The running app shows that fingerprint. Tests compare manifest version to the staged bundle, not to a hardcoded 2.4.1 string.

2. **First show is maximized.** `main.py` currently calls `window.show()`. Change the first presentation to `showMaximized()`. `show_and_raise` (tray reattach) stays `showNormal` only when the user had restored; a fresh launch is maximized. Title-bar maximize glyph stays in sync via the existing `changeEvent`.

3. **Setup compactness is layout, not fewer checks.** Prerequisites render in a two-column grid inside the card. Re-check is an icon button on the title row (`aria-label="Re-check"`). GPU card is one line: `{name} | Vendor: {vendor} | {N} GB VRAM`. Drop `layout.addStretch()` on Setup or give it a small maximum so the three sections pack to the top.

4. **Compatible Unsloth is selected.** `_apply_unsloth_host_lock` today only *clears* the box when incompatible. When host-ok, set checked and `state.install_unsloth = True` on first `showEvent` unless the user already unchecked (`_user_touched_unsloth`). Incompatible remains disabled and unchecked.

5. **VS Code is a Features row, default on for current stable.** Lift `SUPPORTED_VSCODE_MAX_EXCLUSIVE` past 1.136 (support current Microsoft stable; keep excluding Insiders, Cursor, Windsurf). Merge install/replace into one Features checkbox default-checked when `detect_vscode_cli().supported`. The separate "VS Code Extension Settings" segment and the Gemma sampling preview go away. Temperature 1.0 / Top-P 0.95 / Top-K 64 are engine defaults, not installer copy.

6. **Video2X copy leaves the wizard.** `INSTALLER_NOTE` is not helpful on Configuration. Settings > Video already owns the executable path. Delete the Configuration block.

7. **Review models are grouped by catalog section.** Use the same section order as the Models step (embed, chat/agentic, image, video, audio, document). Each group is a heading plus the existing two-column marks. Facts column stays path, components, GPU; no 50% empty min-height.

8. **The VS Code extension is the same local agent as desktop Agents, with a model picker.** `nexus.llm.modelName` default `gemma4:e4b` and the installer preview of a single Gemma tag are the lie on screenshot 3. Enumerate the AD-13 allowlist for agentic ids only. Default is `recommendedByTask.agentic` for this host (16 GB: `gemma-4-12b-it-gguf`) when that id is owned. Status-bar / command-palette switcher matches Claude Code's model switch, not a second runtime. Skills, commands, hooks, rules, and the agent loop already live in `src/` and `modules/coding/`; they must keep working when the model id changes. Out of scope: cloud Codex/Claude accounts, remote MCP marketplaces, and a new agent framework.

9. **Sessions History always has a header.** Empty and non-empty trees share one header: title "Sessions History", then left-aligned new-folder and new-session icons. Hairline `marginBlock` equals the gap from Videos to the rule and from the rule to that title. Do not hide the title when `isEmpty`.

10. **Chatbot tab stays Chatbot; every session noun is Session.** Replace `CHAT_FOLDER_TREE_COPY` and sibling copy (empty hint, CTA, delete/archive dialogs, aria, test ids' visible strings). Keep route `/chat`, module id `chatbot`, and the tab label. Flip tests that currently pin "No chats yet" / "Start a new chat" (`StudioHistoryPane.test.tsx`).

11. **Settings cards have no Details.** Delete the `<details>` block. Render the three-line compact card in AD/DoD. Star, downloaded check, and delete stay one `alignItems: center` row. Description is one rewritten sentence from catalog fields (multimodal + agentic + origin + context), not the current two-line plus Best-for list. Update `settings-models-density.test.tsx` so it fails if Details returns.

12. **Assistant token counts are mandatory chrome.** `bubbleTokenMetadata` already supports them. Field miss is persist/mapping plus a weak test. After every assistant turn, `messageUsage` from `estimatedMessageUsage` (or provider usage) must be on the in-memory message *and* the explorer record. Tests must `getByTestId('message-tokens-...')` on the assistant bubble. Unknown counts still omit rather than show 0.

13. **Picker allowlist is installer selection union Settings installs; order is recommend order.** `installedForTask` already has this rule, but `ownedIdSet(null)` returns null and the filter then keeps every `installed` model of that type, including Ollama leftovers and `source: "external"` tags the user never chose. Fail closed: no snapshot means no model rows (only Get more models). The allowlist is `orderedIds` (what the wizard wrote from the user's ticks, including v2.4.5 auto-ticks the user left checked) union `downloadedSinceInstall` (Settings > Models installs after setup). Deselecting a model in the wizard, or never installing it in Settings, removes it from every Chat, Agents, Image, Video, and VS Code selector. Settings > Models still lists the catalog so the user can add one. After the allowlist, sort with `recommendOrderForTask`. Chat uses the chat list; Agents uses agentic.

14. **Image default is the 16 GB recommended image model among owned ids.** `resolveDefaultId` must prefer `recommendedByTask.image` (`realvisxl-v5` on tier 16) when that id is owned. Juggernaut remains selectable only when it is in the AD-13 allowlist (installer tick or a later Settings install). On-disk weights without that membership do not put it in the Image picker and must not become the default. Do not keep `FALLBACK_MODEL` as a fake installed SANA on a live sidecar.

15. **Studio captions rotate; mapping.ts must not say Shaping.** `rotateCaptions={!studioPending}` already routes Image/Video to `useStudioCaptionRotator`. Packaged Shaping... is the old bundle plus `mapping.ts` labels still `"Shaping"`. Change those labels; assert ImageStudioPage pending text is one of `STUDIO_PENDING_CAPTIONS`.

16. **Stop is a first-class composer action on all four tabs.** `MediaComposer` `streaming` today only restyles Send. Add Stop that aborts the in-flight Chat/Agents session and cancels the Image/Video job (`activeJob` / queue cancel). Disabled when idle.

17. **Advanced settings sit on the Context/Model row.** Lift the Image and Video Advanced toggle into `ComposerContextRow` (Context | Model | Advanced). The expanded panel may still open above the composer; the toggle must not consume its own row.

18. **GPU busy tracks jobs, not only nvidia-smi percent.** Register Chat, Agents, Image, and Video in-flight work with the same snapshot `createTelemetryStream` reads. Query `nvidia-smi` with the installer System32 fallback. If a job is active and utilization is 0, show Busy (model name) rather than Idle 0%. VRAM free may still update from smi.

19. **A model on disk is not a selected model.** Probe-discovered weights, `ollama list` extras, Image `FALLBACK_MODEL`, and catalog-only rows are not selector rows. Tests must plant an installed id that is absent from the snapshot and assert it is missing from all four desktop pickers and the VS Code picker.

## Phase 1: Packaged Delivery and Installer Window

**Target persona**: A privacy-focused Windows user with a single consumer NVIDIA GPU (this host: RTX 3080 Ti Laptop, 16384 MB) who expects Chat chrome, sidebar history, Image follow-ups, Video generation, and Settings cards to stay usable and honest in one sitting.

**Observable definition of done**:

- Image/Video pending copy is one of Creating... / Crafting... / Generating..., picked per prompt (not Shaping...).
- Settings Models: category tabs and the search field share one row. Star, downloaded/check, and delete sit on one centered horizontal row. Card height hugs its content.
- Details shows fact pills (label visually distinct from value), then a Best for heading with strength bullets. No ID/task line, no "Also agentic", no repeated License, no Backend model line.

## Architecture Decisions

1. **Equal transcript gutters, not stacked insets.** Screenshot 1 is asymmetry, not only glow crop. User bubbles already sit `flex-end` with a max width. Assistant pending currently adds `paddingInline`, extra `paddingLeft` (`space-2` + `PENDING_PILL_INSET_PX`), and `AgentStateOrb` `marginLeft: 12`. Collapse to one transcript gutter token used on both sides of the pane. The pending pill starts on that left gutter. Glow lives inside the gutter (padding on the list, overflow visible on the row). Do not keep a second 12px pill margin.

2. **Hairline is vertically centered in the gap.** Today the rule uses `margin: var(--space-1) 0` while FolderTree's Chats header adds `padding-top: var(--space-2)`, so the Videos-to-line gap is smaller than the line-to-Chats gap. Equal padding above and below the 1px rule. Reduce FolderTree header padding-top so the title does not add a second top gap.

3. **Selected chat titles sit next to the rail.** Expanded chat rows reserve a 12px dummy span (folder chevron slot) plus `gap` plus `padding`. Drop the dummy span on chat rows. Keep the 4px `borderLeft` rail. Folder rows keep the chevron.

4. **Archive All / Delete All are header actions.** One confirm each, portaled to `document.body` like the per-row dialogs. They act on the chats in the current pillar tree (not other pillars, not already-archived Settings rows). Implementation loops the existing `archiveChat` / `deleteChat` clients. Empty list disables the actions.

5. **Restyle must change pixels, not only raise strength.** v2.4.3 already set `RESTYLE_IMG2IMG_STRENGTH = 0.7` and `restylePromptFor`. Screenshot 3 is an exact reprint, which is not explained by a mild strength miss alone. This phase traces mode, prompt, source digest, strength, and output digest through Image Studio, the sidecar, and `image_execute`. Fail closed if source bytes are missing. Never attach the previous PNG to the new assistant turn. Pass `generator`/`seed` into the pipeline (today `image_execute` ignores seed). Fix `strength=ctx.params.strength or 0.75` so a real 0 is not rewritten. Parser accepts trailing punctuation on "Make the puppy black". If img2img still returns a near-clone, raise restyle strength (target 0.85) and keep the identity prompt. Unit tests assert output hash != source hash on the restyle path (stub pipeline that echoes the source must fail).

6. **SANA families require a Diffusers pin that exports their classes.** Field error: `cannot import name 'SanaVideoPipeline' from 'diffusers'` in the packaged venv. Catalog layout and `sana_video_execute` are not the miss. `runtimes/diffusion/runtime-lock.json` and `scripts/installer/build/versions.lock.json` pin `diffusers==0.34.0`. Hugging Face documents `SanaVideoPipeline` on the 0.37.1 docs. Bump the lock to a verified release that imports both `SanaPipeline` and `SanaVideoPipeline` against the existing torch 2.3.0 + cu121 stack, or record a known gap if that pair cannot coexist. Missing class stays `RuntimeNotReady` kind `diffusers-missing` with a human sentence, never a raw ImportError traceback in the bubble. Image SANA is included in the same pin probe.

7. **Generation RPC must not run CUDA on the stdin loop.** `runtimes/diffusion/main.py` `dispatch` calls the handler to completion before reading the next line. `PipelineRunner.execute` / `VideoPipelineRunner` run `pipe(...)` inline, so Node `call("diffusion.video.text2video")` waits for the whole job, Python cannot emit heartbeats, and a 16 GB laptop GPU load then starves the compositor (Shaping freezes, shell unresponsive). Accept the job, return `jobId` immediately, run CUDA on a worker thread, emit progress notifications on stdout, and keep the stdin reader alive for `drainEvents` / cancel. The UI pending state lasts until complete or a written error. CSS animation plus progress events is the liveness signal. If the worker dies, fail closed in the transcript.

8. **Studio pending captions are Creating / Crafting / Generating.** Chat/Agents keep Thinking / Searching / Working / Solving. Image and Video pending shuffle the studio list once per prompt (same rotator pattern, different copy). No "Shaping...".

9. **Settings cards hug content; actions are one row; search shares the tab row.** `ModelCard` actions are a column (star top, check/trash bottom), which stretches the grid and leaves empty description space. One horizontal `alignItems: center; justifyContent: center` action row. No min-height on the card beyond padding. Category tabs and `SearchInput` sit on one wrap row (`models-chrome`). Hidden "Search" label stays for a11y.

10. **Details is pills plus Best for.** Drop `ID: ...; task:`, `Also agentic`, repeated `License:`, and `Backend model:`. Pills keep the v2.2.9 grammar but render `Company:` (muted/weight) distinct from `Google` (foreground). Best for is a heading plus a `<ul>` of `item.strengths`. Optional one-line Why this one may stay if it is not a restatement of the pills; default is omit when it only repeats strengths or license.

## Phase 4: SANA Family Diffusers Pin

**Goal**: The packaged venv can import `SanaPipeline` and `SanaVideoPipeline`, or the bubble names `diffusers-missing` without a traceback. CUDA work still does not run on an incomplete pin.
**Prerequisites**: Phase 3.
**Stability Gate**: Lockfiles and installer contract tests name a Diffusers version whose documented API includes `SanaVideoPipeline`. Runtime tests prove missing class -> `kind="diffusers-missing"` and present class -> SANA path not WanPipeline. A live NVIDIA SANA clip is last-phase only.
**Recommended model tier**: frontier
**Recommended effort level**: max
**Rationale**: Highest technical risk. A bad pin can break every Image/Video model on the host. Field screenshot 4 is this miss, not the v2.4.3 layout work.

### Sub-tasks

#### 4.1 - Bump the media-runtime Diffusers pin

**Objective**: Installer venv and `runtime-lock.json` agree on a release that exports SANA video.

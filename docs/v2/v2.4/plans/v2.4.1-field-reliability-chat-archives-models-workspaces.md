## Overview

This release is a field-repair and product-coherence cycle. The supplied installer log proves that Nexus Desktop 2.3.1, the sidecar health check, Node, runtime sources, the selected-model snapshot, and Nexus-Hub completed successfully. The unhandled failure starts at the optional Unsloth step because `UnslothVenvProvisioner._pins_path()` falls back to the checkout-relative `core/tuning/unsloth-pins.json`, while `scripts/installer/build/nexus-installer.spec` does not bundle that file or expose it through the frozen-resource resolver.

The image-generation failure has a separate root cause. The active `RuntimeProvisioner` copies `runtimes/` and writes `runtime.json`, but it never invokes the existing `DiffusionVenvProvisioner`. It therefore records `diffusionPython: null` on a clean host, even though the inactive `provisioner_dispatch.py` chain already knows how to create the environment. v2.4.1 reconnects the provisioner to the shipping path, downloads only the pinned platform payload needed by the host, verifies every artifact, and refuses to claim image readiness until a CUDA smoke test passes.

The desktop work is deliberately split by durable boundary. Transcript rendering becomes quieter without inventing or exposing reasoning that the local backend did not provide. Session archive state is persisted in each existing store and aggregated for Settings. Model ordering becomes a tested shared contract instead of two similar algorithms. Multi-root coding introduces an explicit workspace identity and union-of-roots path policy before changing the Agents UI.

## Goals First

**Target problem**: New users can reach a partially working desktop while the installer reports a terminal exception, Image Studio advertises downloaded models without a usable CUDA runtime, and session/model/workspace surfaces behave differently enough to undermine trust.

**Target persona**: A privacy-focused Windows developer or creator using local models on a consumer NVIDIA GPU, with the same contracts retained for supported macOS and Linux paths.

**Observable definition of done**:

- The installer shows a larger overall bar with a moving gradient, readable percentage, reduced-motion fallback, and unchanged smaller phase bars.
- A frozen installer resolves bundled Unsloth pins and contains optional-step exceptions without misreporting the whole installation as failed.
- Selecting an image or video model provisions a pinned diffusion environment; NVIDIA installs pass `torch.cuda.is_available()` before `runtime.json` marks CUDA image generation ready.
- The pending assistant animation has no message bubble; completed user and assistant bubbles use subtly different neutral backgrounds.
- Bubble metadata shows time at the left and italic `(X tokens)` at the right, with keyboard-accessible input/reasoning/output detail on hover or focus.
- Model-provided reasoning content, when available, is persisted separately and rendered collapsed above the response bubble; no disclosure appears when only a token count exists.
- Delete is explicitly irreversible, Archive is available beside Delete, both actions reset an active transcript only after storage succeeds, and Settings can restore archived chats grouped by Chatbot, Agents, Images, and Videos.
- Installer and Settings show the same selectable catalog roster in the same default order: recommendation tier first, release date newest first, then stable name order. Compatibility changes badges and actions, not visibility.
- Model cards always show a one-sentence description, storage-size pill, VRAM in the compatibility label, expanded technical details, and a muted downloaded state.
- Settings shows dynamic downloaded-model disk usage as a progress meter with free space and percentage, refreshing after model changes, window focus, and a bounded polling interval.
- Agents supports a native folder picker, one primary root plus additional roots, the OS home directory as the initial default, and sessions grouped under the normalized workspace in Chat History.
- Multi-root tools cannot read, write, execute, or traverse outside the selected root union, including through symlinks, relative traversal, or a conflicting requested working directory.
- The redundant Agents Sessions tab is removed; Chat, Memory, and Activity have clear labels and explanatory empty states.

## Architecture Decisions

1. **Slim, pinned runtime repair**: Reuse `DiffusionVenvProvisioner` from the active `RuntimeProvisioner`. Download a host-specific, versioned manifest with SHA-256 verification into the existing per-user cache. Never silently fall back from CUDA to CPU when a selected feature requires CUDA.
2. **Truthful runtime contract**: Bump `runtime.json` and record component status, smoke evidence, provisioner version, and actionable failure code. `diffusionPython` alone is not evidence of CUDA readiness.
3. **Provider-exposed reasoning only**: Add a separate optional reasoning stream/persisted field. Render it only when the model runtime supplies content or a provider-supplied summary. Token counts remain usage metadata.
4. **Archive in place**: Add nullable `archived_at`/`archivedAt` to existing session records. Default lists exclude archived rows. Restore preserves the original pillar and parent when possible.
5. **One catalog display contract**: User-selectable catalog rows are visible on both surfaces. Dependency-only rows remain in expanded component details. Discovered non-catalog weights remain in a clearly separated Settings-only section because they were not installer choices.
6. **Workspace identity by normalized root set**: A workspace id is derived from sorted, canonical, case-normalized roots. UI order retains the primary root, but identity does not change when chips are reordered.
7. **Union-of-roots authorization**: The primary root supplies the default working directory. Every filesystem or terminal path must resolve inside at least one selected root. Existing single-root sessions migrate to a one-element root array.

## Phase 1: Installer Completion and Progress UX

**Goal**: Make installation progress visually dominant and prevent the optional Unsloth provisioner from turning an otherwise successful install into an unhandled engine exception.
**Prerequisites**: Clean `develop`, the supplied installer log retained as field evidence, and a host-matched desktop payload for frozen tests.
**Stability Gate**: Frozen-resource probes find catalog, runtimes, and Unsloth pins; optional Unsloth failure produces an actionable failed sub-step while the completion page accurately distinguishes core success from optional failure; reduced motion is honored.
**Recommended model tier**: strong
**Recommended effort**: high
**Rationale**: The root causes are localized, but PyInstaller resource resolution and Qt animation lifetime require careful packaged testing.

### 1.1 -- Prominent overall progress widget (T001)

**Objective**: Give overall installation progress stronger hierarchy than phase bars.

**Prompt**:
> Create `scripts/installer/src/nexus_installer/widgets/overall_progress.py` and replace the generic overall `QProgressBar` in `pages/installing.py`. Use an 18-20 px track, readable `%p%` text, high-contrast foreground, and a timer-driven gradient offset while work is active. Keep subordinate phase/model bars at their current 4-8 px sizes. Stop timers when hidden or complete. When reduced motion is enabled, show the gradient without movement. Add a weighted progress aggregator whose stable denominator comes from the selected install steps; long downloads contribute byte progress when content length is known, and completed steps contribute their full weight. Preserve indeterminate behavior only before the first numeric event or for an individual unknown-length operation; once overall progress is known, clamp to 0-100, keep it monotonic for one install attempt, and expose it to accessibility APIs.

**Failure modes**: Missing or malformed progress events leave the last valid value and log a warning; a slow engine keeps the animation bounded without creating timers per event; concurrent phase events are serialized through the existing UI signal and cannot move overall progress backward unless the engine explicitly starts a new install attempt.

### 1.2 -- Frozen Unsloth pins resolution (T002)

**Objective**: Make `core/tuning/unsloth-pins.json` a required frozen resource with one resolver contract.

**Prompt**:
> Add `unsloth-pins.json` to `nexus-installer.spec` with a build-time existence and JSON-schema check. Extend `nexus_installer.registry_paths` with a generic frozen/check-out resource resolver and make `UnslothVenvProvisioner._pins_path()` use it. Remove the relative-CWD fallback. Add a frozen-mode test using a temporary `_MEIPASS` and a build-spec assertion. Do not duplicate pin content inside Python.

**Failure modes**: Missing or malformed pins fail the build before packaging; a missing frozen resource returns a typed optional-component failure rather than a raw `FileNotFoundError`; concurrent installer instances remain governed by the existing single-instance lock and never rewrite the pin file.

### 1.3 -- Optional-step containment and truthful completion (T003)

**Objective**: Keep optional Unsloth provisioning isolated from required desktop/runtime success.

**Prompt**:
> Refactor the install engine step runner so every step reports required/optional, terminal status, error code, and retryability. Catch unexpected exceptions at the step boundary, log a sanitized traceback, mark only that step failed, and compute final state from required-step success plus optional warnings. Unsloth remains opt-in. The completion page must say which optional component failed and offer retry/details; it must never display a clean-success claim if a required component failed. Preserve idempotent rerun behavior.

**Failure modes**: Malformed step results become failed steps with `INVALID_STEP_RESULT`; unavailable/slow dependencies time out with retry guidance; simultaneous cancel and exception resolve once, with cancellation winning before any new step starts.

### 1.4 -- Installer resource and UI tests (T004)

**Prompt**:
> Add Qt tests for overall size hierarchy, percentage text, monotonic updates, timer cleanup, and reduced motion. Add installer tests for checkout and frozen Unsloth resolution, malformed pins, optional exception containment, and accurate completion summaries. Add a build manifest probe that opens the produced executable's collected data manifest without launching external installers.

**Recommended model tier**: frontier
**Recommended effort**: max

## Phase 3: Transcript Chrome and Reasoning Disclosure

**Goal**: Make chat generation state, bubble styling, token metadata, and optional model-provided reasoning discreet and comprehensible across all pillars.
**Prerequisites**: Existing shared `MessageBubble`, `AgentStateOrb`, and usage-token contracts.
**Stability Gate**: Pending rows are bubble-free; completed messages have subtle role separation; token total and tooltip are accurate and accessible; reasoning is collapsed, separate, persisted, and absent when not supplied.
**Recommended model tier**: strong
**Recommended effort**: high
**Rationale**: Shared UI changes are moderate risk, while stream/persistence evolution needs backward compatibility across four tabs.

### 3.1 -- Bubble-free pending state (T012)

**Prompt**:
> Refactor `MessageBubble` and `AgentStateOrb` so an assistant pending message renders as an inline status row without article background, border, or padded bubble. The actual assistant bubble appears only when output content or a terminal error exists. Keep the accessible status announcement, cancellation state, retained animation cap, and reduced-motion behavior.

**Failure modes**: Missing status renders a stable generic generating label; a stalled stream keeps one status instance and no growing DOM; concurrent pending messages retain unique keys and do not share animation state.

### 3.2 -- Subtle semantic bubble colors (T013)

**Prompt**:
> Add neutral `--bubble-user` and `--bubble-assistant` tokens with a small luminance difference and measured text/border contrast. Apply them through shared classes rather than pillar-specific colors. Avoid green, cyan, or success-state washes. Verify high-contrast and reduced-transparency modes remain legible.

**Failure modes**: Missing theme tokens fall back to existing neutral surfaces; no external dependency is involved; simultaneous theme changes update both roles without transient unreadable inline styles.

### 3.3 -- Token metadata footer (T014)

**Prompt**:
> Replace verbose token prose with an outside-the-bubble metadata row directly below the bubble: time aligned to the start and italic `(X tokens)` aligned to the end. Total is the sum of reported input, reasoning, and output counts, without double-counting provider totals. Add a keyboard-focusable accessible tooltip with input, reasoning, and output details and unavailable labels where a provider omits a field. Mark estimates explicitly. Keep timestamps localized.

**Failure modes**: Malformed/negative counts are ignored; there is no remote dependency; late usage events update the existing footer atomically and never produce `NaN` or a decreasing final total.

### 3.4 -- Separate reasoning stream and persistence (T015)

**Prompt**:
> Extend the sidecar protocol with an optional `reasoning_delta` stream event and optional persisted `reasoningText`/provider summary field. Capture only a reasoning channel explicitly returned by the local runtime; never infer hidden chain-of-thought from ordinary output. Add bounded size, local redaction rules, schema migration, and hydration support for Chatbot, Coding, Image, and Video session records. Preserve count-only providers without creating fake content.

**Failure modes**: Malformed reasoning events are dropped and logged without corrupting output; a provider that omits or delays the channel still completes normally; concurrent reasoning/output deltas are ordered by stream sequence and persisted once on completion.

### 3.5 -- Collapsed reasoning disclosure (T016)

**Prompt**:
> Create `ReasoningDisclosure.tsx` above the assistant output bubble. Default it collapsed with a discreet chevron, `Reasoning`, and optional token count/duration. Expanded content is selectable, scroll-bounded, keyboard operable, and screen-reader labeled. Hide the control when there is no provider-supplied content. Errors in reasoning rendering must not hide the final response.

**Failure modes**: Missing/malformed content hides the disclosure; no external dependency is required; expansion state is local to each message and remains stable while late deltas append.

### 3.6 -- Testing and Stabilization (T017)

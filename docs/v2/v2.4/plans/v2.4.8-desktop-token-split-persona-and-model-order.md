## Overview

v2.4.7 shipped its installer for field testing (PR 63, merged to develop as `2b7b9811`). The operator then exercised the desktop app the installer delivers and returned five screenshots. Every one of them traces to a specific line in the tree, and two of them are correctness defects.

**The token defect.** Ollama's `eval_count` is the count of every token the model generated for the turn, thinking included. The sidecar reads that count as `outputTokens` and then adds a reasoning estimate on top:

```ts
// desktop/sidecar/src/serving/chatCore.ts:202-210
const thinkingReasoning = thinkingText.trim().length > 0
  ? Math.ceil(new TextEncoder().encode(thinkingText).length / 4) : null;
const reasoning = usage.reasoningTokens ?? thinkingReasoning;
return { inputTokens: usage.promptTokens, reasoningTokens: reasoning, outputTokens: usage.completionTokens };
```

The bubble label sums the two. Screenshot 1's reasoning text is 215 bytes, so the estimate is 54; Ollama's exact total for the whole turn was 72; the label showed 126 and the detail attributed 72 tokens to a nine-token reply. The reasoning tokens were counted twice, and the split was inverted. The reply text is available at the same call site and is never used.

The same shape of error exists for the OpenAI-compatible wire when a backend reports `reasoning_tokens`: OpenAI's `completion_tokens` includes reasoning, so returning both unchanged double-counts again.

**The dismissal defect.** `MediaComposer` toggles its overflow menu and mic menu with `useState` and closes them only from their own buttons. `ChatPage` does the same for the Persona popover. Nothing listens for a pointer outside the surface or for Escape, so the menu in screenshot 2 stays open across the rest of the session. The popover is a bare `<label>` and `<textarea>` with no font, color, radius, or padding tokens applied, which is why it reads as foreign.

**The title.** `CHAT_FOLDER_TREE_COPY.paneTitle`, `CodingPage` copy, and both `StudioHistoryPane` copies say `Sessions History`, and the header span renders it in `--fg-muted`. The nav links render `--fg-1` via `.nexus-nav-link` at `--text-sm`. One token and one word.

**The catalog order.** Installer `TYPE_TABS` is Embeddings, Document, Chat, Agentic, Image, Video, Audio. Desktop `CATALOG_TAB_DEFS` is Embeddings, Chat, Agentic, Image, Video, Audio, Document. The desktop comment says it mirrors the installer; it stopped doing so when the installer moved Document next to Embeddings.

**The card.** The installer card (`typed_catalog.py` `ModelCard`) tints its surface and border with the publisher's color, sets the name in that color, puts every fact pill on the name row with a steelblue Recommended pill, and hangs a size pill plus round compatibility and downloaded badges on the right. ## Architecture Decisions

1. **The provider total is the truth; the split is derived from it.** `eval_count` is exact and already covers thinking. When a backend reports a total and no explicit reasoning count, reasoning becomes `round(total * thinkBytes / (thinkBytes + replyBytes))` and output is the remainder, so the two always sum to the total and the ratio follows the text. The bytes/4 estimate survives only for the case where nothing was reported at all, which is the case it was written for.

2. **An explicit reasoning count is subtracted from the completion count.** OpenAI's `completion_tokens` includes reasoning. When both arrive, output is `max(completion - reasoning, 0)`. This is the same rule as decision 1 with the split supplied by the provider.

3. **The reply text reaches the split at the existing call site.** `turnUsageFromCollected(usage, thinkingText, replyText)` gains a third argument; `chatMessageHandler` already holds both strings. No protocol field changes, so persisted sessions and the IPC schema are untouched.

4. **One dismissal hook, three consumers.** `useDismissOnOutside(ref, open, onClose)` listens for `pointerdown` on the document and `keydown` Escape while open, and ignores events inside the ref. It lives in `desktop/src/shared/ui/` beside the other shared UI helpers. The overflow menu and mic menu attach it in `MediaComposer`; the Persona popover attaches it in `ChatPage`. The toggles keep their click handlers, so a click on the toggle still toggles.

5. **The popover is restyled with tokens, not redesigned.** Same anchor, same content, same behavior. The container takes the app's elevated-surface tokens and a shadow; the label takes `--fg-1` at `--text-sm` weight 600; the textarea takes the composer field styling (`--bg-1`, `--border-subtle`, `--radius-md`, `--font-sans`, `--text-sm`, `--fg-0`, padding).

6. **Sessions is a copy and color change only.** Three `paneTitle` strings become `Sessions`; the header span color becomes `--fg-1`. The `HISTORY_HAIRLINE_GAP` geometry, aria labels, `itemNoun`, and the Chatbot nav label are unchanged.

7. **The desktop tab order copies the installer's tuple.** `CATALOG_TAB_DEFS` becomes Embeddings, Document, Chat, Agentic, Image, Video, Audio. A shared fixture `tests/fixtures/v2.4.8-catalog-tab-order.json` is asserted from vitest and from installer pytest, following the `v2.2.9-catalog-tab-sort.json` precedent, so the two cannot drift again silently.

8. **Provider colors ship as a shared fixture.** `tests/fixtures/v2.4.8-provider-colors.json` carries the publisher-to-color map and the fallback. Installer pytest asserts `PROVIDER_COLORS` equals it; desktop imports the same values through a small `providerColors.ts` and asserts equality too. The installer's `FAMILY_TO_PUBLISHER` already has a desktop twin in `modelPills.ts`.

9. **The card mirrors the installer's grammar, and keeps its actions.** Name row: name in provider color, fact pills (`buildModelPills`, the same list the installer uses), then `Required` / `Recommended` (steelblue `#4682b4`) / `Tool calling verified`; right side: size pill in provider color, round compatibility badge, round downloaded badge (violet `#a78bfa`). Body: description, `Best for:` strengths, license note, `Why this one:` for recommended models. The action row (star, download or delete) stays because the desktop card can act and the installer card cannot. The compact `Requirements:` row and its separate `Compatible - N GB VRAM` badge are removed; the badge carries that text on its tooltip, as the installer does. Over-budget cards dim and take a dashed border, as the installer does.

10. **The selector uses the installer order, with the snapshot as a tie-break.** `QuickModelSwitcher` sorts its owned, on-tab models with `collapseAndSortModels({ hostVramGB, recommendOrder })`, which is the installer's `collapse_and_sort` and already the Settings order. Downloaded rows are never collapsed by family, so nothing disappears. `installedForTask` applies the same order when the snapshot carries no ranking, so `resolveDefaultId`'s `ready[0]` is the top recommendation. A stored favorite still wins.

11. **Every commit stages named paths only.** The uncommitted wizard-merge files stay uncommitted and unmodified.

## Phase 1: Token Split From the Provider Total

**Goal**: The bubble reports the provider's generated-token total exactly and splits it in proportion to the thinking and reply text.
**Prerequisites**: None.
**Stability Gate**: Tests prove a reported total with thinking text splits proportionally and sums to the total; an explicit reasoning count is subtracted from completion; no thinking text leaves output equal to the total; an unreported turn still yields the bytes/4 reasoning estimate with null output.
**Recommended model tier**: frontier
**Recommended effort level**: max
**Rationale**: This is a correctness defect in a number the operator reads on every turn, and the wrong fix (subtracting the estimate) would look right on one screenshot and be wrong on the next.

### Sub-tasks

#### 1.1 - Proportional split

**Objective**: `turnUsageFromCollected(usage, thinkingText, replyText)` derives reasoning and output from the reported total.

**Failure modes**: Zero-length thinking must not divide by zero. Rounding must keep `reasoning + output === total` exactly. An explicit `reasoning_tokens` must win over the proportion and be subtracted from completion, floored at zero. The unreported path must be byte-for-byte what it is today.

**Prompt**:
> In `chatCore.ts`, extend `turnUsageFromCollected` with an optional `replyText = ""`. When `usage.reported` and `usage.reasoningTokens` is null and thinking is non-empty, compute `reasoning = Math.round(completion * thinkBytes / (thinkBytes + replyBytes))` and `output = completion - reasoning`. When `usage.reasoningTokens` is a number, `output = Math.max(completion - reasoning, 0)`. Keep the unreported branch unchanged. Update the doc comment to state that Ollama's `eval_count` includes thinking.

#### 1.2 - Handler passes the reply

**Objective**: The handler supplies the reply text it already accumulated.

**Prompt**:
> In `chatMessageHandler.ts`, accumulate the visible reply text alongside `thinking` and pass it as the third argument to both `turnUsageFromCollected` calls.

#### 1.3 - Testing and Stabilization

**Prompt**:
> Extend `desktop/tests/serving-chatCore.test.ts`: the screenshot case (215 thinking bytes, 33 reply bytes, `eval_count: 72`) yields reasoning 63 and output 9; a reported total with no thinking yields reasoning null and output equal to the total; `completion_tokens: 10, reasoning_tokens: 6` yields output 4 (the existing expectation, now by subtraction); an unreported turn with thinking still yields the bytes/4 estimate. Run `npm run lint`, `npm run typecheck`, and `npm test` in `desktop/`. CI IMPACT: `ci.yml` already runs the desktop suite; no pipeline change. Session history `docs/v2/v2.4/development/history/2026-09-06_v2.4.8-phase-1-token-split.md`. One local commit staging only the named paths. Do not push.

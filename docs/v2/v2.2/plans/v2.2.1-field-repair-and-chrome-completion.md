**Goal**: After a v2.2.0 install the sidecar stays alive, the Pending approvals popover is always dismissable, every Settings tab uses the shared control primitives, and the sidebar is a compact icon rail with no User Profile row.

## Overview

v2.2.0 landed the plumbing and a first pass at shell chrome, then reported its eight phases complete in session history. A rebuilt installer on 2026-08-22 proved the cycle is not done in the field. Node 22.11.0 starts and then dies, so the next JSON-RPC write hits a closed stdin (Windows `ERROR_NO_DATA` 232). The Complete page prints `sidecar request error: The pipe is being closed. (os error 232) | stderr: [ / / Nodejs v22.11.0]`. Restart backend uses the same spawn path and cannot recover. Models stay at 0, Hub stays empty, and Approvals opens a red error card that cannot be closed.

The same session showed the chrome pass as incomplete. Settings Models restyled Type / Family / Status selects, then left Models Search as a native `input type="search"`. Skill Optimizer (and the rest of Settings) still uses flat unstyled text fields and gray buttons. The Approvals bell popover has no Close control, no Escape handler, and no click-outside listener, so once opened it follows the user across every tab. User Profile remains a sidebar row whose only job is to redirect to Settings. Compact mode exists but is not the default on a wide window.

This patch plan does not re-run the v2.2.0 eight-phase cycle. It closes the field gaps: keep the sidecar alive, make Approvals dismissable, finish the control sweep, and finish the sidebar contract the user already locked.

Success looks like: the next installer Complete page reports sidecar ok; opening Approvals and then clicking X, Escape, or outside closes it even when the sidecar is down; Skill Optimizer, Models Search, and every other Settings control match the already-styled selects; the sidebar is an icon rail with no wordmark and no User Profile item.

## Phase 1: Sidecar stays alive

**Goal**: The installed app's Node child is still running when the first JSON-RPC line is written, and a crash produces a readable reason instead of Windows 232.
**Prerequisites**: None.
**Stability Gate**: On this Windows host after rebuild, Complete shows sidecar ok (not os error 232); Restart backend is unnecessary because the child stays alive; `ipc_call("models.list")` returns catalog rows. A sabotaged native-addon tree still fails the health check, but the verdict includes the child exit code and a readable stderr tail (not three slash-joined fragments).
**Recommended model tier**: frontier
**Recommended effort level**: high
**Rationale**: Cross-layer packaging (Tauri resources, Rust spawn cwd, esbuild native copy, installer healthcheck formatting) with a field-proven crash and no existing test that the NSIS payload contains `better_sqlite3.node`.

### Sub-tasks

#### 1.1 - Ship the native addon with the Tauri resource tree

**Objective**: `sidecar/dist/node_modules/better-sqlite3` (plus `bindings` and `file-uri-to-path`) lands next to `main.js` in the packaged app, and spawn cwd is that directory.

**Failure modes**: Resource tree copies `main.js` but omits `node_modules` -> child throws at `GenerationIndex` import and exits before the first RPC; ABI mismatch vs bundled Node 22 -> rebuild against that Node and fail `build:sidecar` if the `.node` is missing; two concurrent spawns (startup + Restart) -> existing single-flight guard must still hold.

**Build class**: load-bearing.

**Prompt**:
> In the Nexus-AI repo, make the packaged sidecar able to `require('better-sqlite3')`. `desktop/sidecar/esbuild.config.mjs` already marks the addon external and copies it into `desktop/sidecar/dist/node_modules`. `desktop/src-tauri/tauri.conf.json` maps `../sidecar/dist` to `sidecar/dist`; confirm that glob includes `node_modules/**` (not only `main.js` / `wasm`). Add a packaging assertion that lists the NSIS/Tauri resource dir and requires `better_sqlite3.node` to be resolvable from `sidecar/dist/main.js`. In `desktop/src-tauri/src/sidecar.rs`, `Sidecar::spawn_with` currently does not set cwd; set it to `script.parent()` so Node's module lookup cannot miss the copied addon. Keep `NEXUS_CATALOG_PATH` and `catalog-load-failed`. Acceptance: healthcheck on this host is sidecar ok; a fixture that deletes only the native addon reproduces a crash whose stderr names better-sqlite3, not `[ / / Nodejs v22.11.0]`.

#### 1.2 - Do not write JSON-RPC to a dead child

**Objective**: Healthcheck and app spawn wait for liveness (or a recorded exit) before the first `models.list` write.

**Failure modes**: Child exits during the 500 ms wait -> surface `sidecar-exited:<code>` plus stderrTail, never write to a closed pipe; slow-but-alive start on a cold disk -> retry/backoff only while `try_wait` is None; `--healthcheck` stdin not piped -> do not treat it as a TTY; Restart backend must use the same `spawn_with` cwd/resources.

**Build class**: load-bearing.

**Prompt**:
> Treat the 2026-08-22 Complete-page 232 as the Phase 1 acceptance bug. In `desktop/src-tauri/src/sidecar.rs` and `lib.rs` `run_healthcheck`: after `Command::spawn`, wait until stderr shows a sidecar ready line or 500 ms of liveness (`try_wait` is None) before writing `models.list`. If the child has exited, fail immediately with `fail: sidecar-exited:<code>` plus the stderr tail; never map that to "no models installed". `sidecar.restart` must use the same spawn path. Acceptance: Restart backend on this machine either brings `models.list` back or Show details names the real crash; it must not remain "The pipe is being closed."

**Build class**: load-bearing.

**Prompt**:

Fix the verdict so a dead child is diagnosable: include `exitCode`, `nodePath`, `scriptPath`, and at least the last 20 stderr lines as a JSON array. Add installer pytest for verdict shape and the 232-style dead-child path. Acceptance: this host's next installer either prints sidecar ok, or prints a reason that names the missing file or thrown exception.

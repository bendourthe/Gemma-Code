**Seeded from**: operator product bar after v2.2.5 (within-session memory, history panes on Images/Videos matching Chatbot, quit/reopen restore). Not a comparison report.
**Goal**: Each Chatbot, Agents, Images, and Videos session keeps its own conversation (and last generated media) so a follow-up prompt uses that context, and reopening the same session after quitting the app continues as if it had not been interrupted. Images and Videos get a history pane with the same organize/rename/delete contract as Chatbot.

## Overview

Chatbot already has a folder/chat explorer and durable transcripts when the sidecar store is up. Image Studio and Video Lab are chat-shaped composers that keep messages in React state, so a quit, a remount, or even a follow-up without re-attaching the last PNG starts from empty context. Agents can list and resume session ids, but the visible turn list is not proven to reload after process restart.

This patch adds a shared studio-session contract (named sessions, folders, turns with createdAt, lastOutputRef on disk), wires FolderTree onto Images and Videos, makes an empty-attachment follow-up use the last usable output, and hydrates Agents and Chatbot after reopen. Delivery is the existing Tauri desktop app plus Node sidecar; no new installer surface. Success is the operator field checklist at the bottom: four tabs remember a session, Images/Videos organize like Chatbot, and a follow-up without re-attach edits the last picture (or fails honestly).

Context meters, date separators, bubble clocks, and per-bubble token counts are out of scope here (v2.2.7). Persist createdAt so that cycle can render clocks.

### Locked product decisions

- **Four sessioned tabs**: Chatbot, Agents, Images, Videos. Each has a left history pane (folders + named sessions) matching Chatbot organize/rename/delete.
- **Within-session memory**: the next prompt in a session sees prior turns. For Images, an empty-attachment follow-up after a successful generate uses the last usable assistant PNG as `sourceImage` (img2img / inpaint as intent requires). For Videos, a follow-up can condition on the last playable clip / last frame when the protocol already has `continueFrom` / `sourceImage`.
- **Quit/reopen**: selecting the same session after process restart reloads transcript, attachments (or persisted media paths), and the last-output pointer. In-memory React state alone is not enough.
- **Media on disk**: do not keep multi-megabyte PNG/MP4 only in SQLite blobs if a generations index path already exists; store job/output paths plus a thumbnail, and fail closed if the file is gone (honest "output missing", not a grey rectangle).
- **Do not re-run** v2.2.0-v2.2.5 as greenfield. Keep v2.2.4/v2.2.5 locks (cold start Chatbot, tab labels, peeking never loads weights, tools always on).
- **Shipping version**: do not bump root `package.json` (2.1.0) or `desktop/package.json` (1.5.0).
- **Do not disable** the Hub injection scanner.
- Context-window progress bars, date separators, bubble clocks, and per-bubble token counts are **v2.2.7**, not this plan. Persist `createdAt` here so v2.2.7 can render clocks.

## Phase 1: Shared Session Explorer Contract

**Goal**: Images and Videos can own named sessions in a FolderTree without forking Chatbot's SQLite chat schema into a second incompatible tree.
**Prerequisites**: v2.2.5 complete on `develop` (alias table, generate honesty).
**Stability Gate**: Unit tests create an `image` session, append a user turn + assistant media ref, list it back after a new store instance. Chatbot `chat.explorer.tree` tests still pass.
**Recommended model tier**: frontier
**Recommended effort level**: max
**Rationale**: Cross-pillar persistence, schema, and FolderTree reuse. High blast radius if Chatbot explorer regresses.

### Sub-tasks

#### 1.1 -- Studio session records (T001, T002)

**Objective**: Durable session + turn storage for image and video pillars.

**Failure modes**: Missing pillar: reject create. Corrupt JSON/SQLite row: skip that session, log, do not crash the tree. Concurrent rename+delete: delete wins, rename returns not-found.

**Build class**: load-bearing.

**Prompt**:
> Implement Nexus AI Studio v2.2.6 Phase 1.1 from docs/v2/v2.2/plans/v2.2.6-session-memory-and-studio-history.md. Follow AGENTS.md. Do not bump package.json. Do not re-run v2.2.5.
>
> Add a sidecar-backed store for Images/Videos sessions (folders, named sessions, turns with createdAt, lastOutputRef as a generations path or PNG/MP4 path, not a giant blob). Mirror the Chat explorer IPC shape (`tree`, `createChat`, `renameChat`, `deleteChat`, `appendMessage`, `listMessages`) under `studio.session.*` or `image.explorer.*` / `video.explorer.*`. Do not make `core/**` import `modules/**`. Chatbot keeps `chat.explorer.*`.

#### 1.2 -- Shared FolderTree wiring (T003)

#### 2.1 -- Persist image turns and last output (T004, T005)

**Objective**: Every user prompt and assistant PNG (or typed error) is stored on the active session.

**Failure modes**: Generate error: persist the error text, do not update lastOutputRef. File deleted: hydrate shows "output missing on disk". Sidecar down: do not claim saved.

**Build class**: load-bearing.

**Prompt**:

#### 2.2 -- Implicit last-image edit (T004)

**Objective**: Attach image, modify, then a new prompt without re-attaching edits the last generated image.

**Failure modes**: No lastOutputRef: txt2img as today. lastOutputRef unreadable: typed error, do not silent txt2img. User attached a new image: attachments win.

**Build class**: load-bearing.

**Prompt**:
> Implement v2.2.6 Phase 2.2. In `inferImageIntent` / `handleSubmit`, if attachments are empty and lastOutputRef is a usable image, treat as img2img (or inpaint if a mask is present). Tests for attach-modify-follow-up and for no-last-output txt2img.

### Why the app is not working as intended (root causes)

Mapped from the nine screenshots onto the tree. Support tier: **supported** where the file and call site were read in this session; **not proven here** where a live GPU or packaged Explorer launch was not repeated.

#### R1 -- Cold launch does not open Chatbot (screenshot 1, 5)

**Supported.** `desktop/src/main.tsx` restores `normalizeStoredRoute(readStoredRoute())`. `desktop/src/lib/persistence.ts` treats `/coding`, `/images`, `/videos`, and `/settings` as restorable. v2.2.3 BG-16 only normalized `/`, `/dashboard`, and garbage onto `/chatbot`. If the last session ended on Agents, the next launch opens Agents. The operator's rule is stronger: **every process start lands on Chatbot** because it is the top tab. Last-module restore is the opposite product.

`App.tsx` still `<Navigate to="/chatbot" />` for `/`, so a truly empty store is fine. The field failure is last-route restore, not the `/` redirect.

#### R2 -- Tab labels are still the old product names

**Supported.** `desktop/src/types/modules.ts` still ships `Local Chatbot`, `Agentic AI Coding`, `Image Studio`, `Video Lab`. Tests in `desktop/tests/shell-phase6.test.tsx` lock those strings. The operator wants **Chatbot**, **Agents**, **Images**, **Videos**.

#### R3 -- Gap above the first tab; collapse control is a top-right square (screenshot 1)

**Supported.** `desktop/src/components/Sidebar.tsx` renders the collapse `<button>` as the first flex child (`alignSelf: compact ? "center" : "flex-end"`), then `<nav>`. That button is the empty band above Chatbot. Brand was already removed in v2.2.0. The operator wants no gap, and a discrete pill on the **center of the right edge** of the pane (triangle left = collapse, triangle right = expand).

#### R4 -- Pickers list models that were not in this installation (screenshot 2)

**Supported, two stacked bugs.**

1. **Hardcoded fallback ids are not the installed set.** `desktop/src/modules/coding/models.ts` exports `DEFAULT_MODEL_ID = "gemma4:e4b"`. Chat and Agents initialize `useState(DEFAULT_MODEL_ID)`. Image Studio seeds `FALLBACK_MODEL` as SANA 1.5 1.6B (`ImageStudioPage.tsx`). Video has the same pattern. The visible `<select>` in `CompactModelSwitcher` then **displays** `ready[0]` when `value` is not in the installed list, **without calling `onChange`**. Screenshot 6 is the smoking gun: the dropdown shows LFM2.5 1.2B while send uses `gemma4:e4b`.

2. **`models.list` is a catalog-plus-probe, not "what this installer run selected".** `desktop/sidecar/src/models/modelsService.ts` reconciles the catalog against Ollama `/api/tags` and `~/.nexus/models/weights/*`. Leftover weights from a previous install, or a probe that marks extra catalog rows installed, appear in Image Studio. `installedModelsForType` only filters `installed && source !== "catalog-only"`. It does not intersect with `InstallerState.selected_model_ids`. The installer already records that ordered list (`scripts/installer/src/nexus_installer/installer_state.py`) and does **not** publish a runtime snapshot the sidecar reads.

There is no per-tab favorite. Recommended installer defaults are not the app's pre-selected ids.

`+ Get more models` already navigates to `SETTINGS_MODELS_PATH` (`/settings?tab=models`), but `SettingsPage` ignores the query string (`useState(initialTab)` with default `"models"`). Deep-link is DF-17. If Settings is already mounted on Skills, the query change may not switch tabs.

#### R5 -- Agents chrome is coding-specific and user-hostile (screenshots 4, 5)

**Supported.** `CodingPage.tsx` still paints a pink `h1` "Agentic AI Coding" (`color: "var(--accent-coding)"`). `ModelSelector` still renders `balanced scaffold (off)` and `tool-calling verified` badges. Chat still has an **Enable tools** checkbox default **false** (`ChatPage.tsx` `useState(false)`). The operator wants Agents to read as ChatGPT Work / Claude Cowork / Claude Code (coding and not-only-coding), no pink title, no jargon badges, and tools always on.

#### R6 -- "Hi" produces `gemma4:e4b is not installed` and no user bubble (screenshot 6)

**Supported. This is the P0 chat break.** `ChatPage.handleSubmit`:

1. Creates/opens a chat with `modelId` state, which is still `gemma4:e4b`.
2. Runs residency. `not-installed` appends an **assistant** banner and **returns**.
3. The user message is appended **after** that return (`appendMessage` of the user row is later in the same function).

So the transcript shows only the error, never "Hi". The dropdown lied about which model would be used.

Coding has the same `DEFAULT_MODEL_ID` seed and will fail the same way on a host that installed LFM2.5 and not Gemma 4.

#### R7 -- Image attach+generate yields a giant empty rectangle plus unexplained icons (screenshots 7, 8)

**Supported.**

- `MessageBubble` sizes media at `width: "48rem"`, `maxWidth: "100%"`, `minHeight: "8rem"`, `background: "var(--bg-2)"`. An empty or transparent PNG still occupies most of the pane. Pending studio messages use `minHeight: "12rem"`.
- Action row (Download, Copy workflow, Use prompt, Use seed, Use all, Remix, Use as source) renders whenever `m.media` is set. Screenshot 8 is that row under an empty shape, so `media` was set with a non-displayable src.
- v2.2.3 BG-24 claimed empty completes become written errors. Field evidence contradicts: the empty rectangle is still the dominant object. Either `complete.png` is a truthy empty/invalid payload, decode `onError` does not clear layout, or the pending placeholder never yields to an error bubble.
- `handlers.ts` still throws `NotImplementedError("image.generate")`. The UI path is `diffusion.txt2img` / `img2img`. A Python runtime that returns quickly with empty bytes still produces the screenshot 7 shape.
- There is no click-to-lightbox. The operator wants compact inline media, click opens a preview dialog with fullscreen plus copy/download.

Button semantics today (for the plan to document, not invent):

| Icon | Code name | What it actually does |
|---|---|---|
| Download | `image-download-*` | Writes the PNG bytes to a file |
| Two squares / JSON | Copy workflow | Copies Comfy-style workflow JSON, not the image |
| T | Use prompt | Puts the workflow prompt back into the composer |
| # | Use seed | Puts the workflow seed back |
| Layers | Use all | Restores prompt, seed, size, steps, cfg, sampler, model |
| Shuffle | Remix | Same as use-all plus a new random seed |
| Frame | Use as source | Seeds the next img2img from this PNG |

The operator asked for copy **image** (clipboard PNG) in the lightbox, not copy workflow as a primary action.

#### R8 -- Settings > Models is a filter form, not the installer catalog (operator request)

**Supported.** `ModelsSettings.tsx` is Type / Family / Status / Tier-fit dropdowns plus Installed / Available / External sections. The installer page (`scripts/installer/src/nexus_installer/pages/typed_catalog.py`) is Chat / Agentic / Image / Video / Audio / Document **tabs**, with the same descriptions, Best-for line, fact pills, Required/Recommended/Compatible badges, and hardware-disabled cards. The app page does not reuse that information architecture. Checkboxes in the installer should become Downloaded vs Download (disabled when the host cannot run the model).

#### R9 -- Skills Update now dies with `sidecar response timeout` (screenshot 9)

**Supported.** `desktop/src-tauri/src/sidecar.rs` waits **15 seconds** for every IPC reply. `skills.sync` runs `NexusHubSyncer.sync({ apply: true })`, which sparse-clones or tarball-fetches `bendourthe/Nexus-Hub` and scans the tree. That cannot finish in 15s on a cold network. The renderer maps `SidecarError::Timeout` to "sidecar response timeout". Auto-sync weekly is stored as `enabled: stored === true`, so the default is **OFF**. The operator wants the label **Auto-update to latest Nexus-Hub release**, default **ON**.

The red "The Nexus backend could not start" banner can also appear when `skills.list` / `skills.status` fail for the same timeout, even if the sidecar is alive.

### Structure / quality notes (review lenses, scoped to this failure surface)

- **Structure**: Pillar pages each own a copy of "load models, pick default, send". There is no shared `useInstalledCatalog(task)` that takes installer order + favorite. Settings Models does not share the installer's typed-catalog widgets. This duplication is why Chat, Agents, Images, and Videos can each lie differently.
- **Quality**: `CompactModelSwitcher` displaying `ready[0]` while parent state stays on `gemma4:e4b` is a classic view/state split. `FALLBACK_LLMS` marks every catalog LLM `installed: true` (`CodingPage.tsx`), so tests and ipc-unavailable mode teach the UI that Gemma 4 is installed.
- **Coverage**: Desktop vitest (v2.2.3 Phase 8: 1369 tests) never asserted "the selected option id equals the id passed to `chat.session.send`". It never asserted IPC methods that clone a git repo get a longer timeout. Image tests can pass with a fake `complete.png` of one byte.
- **Security**: No new outbound except Hub sync (already the skills path). Long-running sync must stay scoped to `~/.nexus-ai/catalog/` (existing `assertScopedCatalogRoot`). Do not raise the global 15s timeout for `models.list` / `chat.send`. Add a per-method timeout map instead. Do not log Hub tokens.
- **Changes vs v2.2.3**: Last-route restore, hardcoded `DEFAULT_MODEL_ID`, 15s global IPC, and 48rem media are leftover design, not unfixed typos. Treat them as product reversals, not drive-by edits.

## Locked product decisions

- **Cold start**: every new renderer process opens `/chatbot`. Do not restore `/coding` / `/images` / `/videos`. Restoring a Chatbot *thread* inside `/chatbot` is allowed. Settings is not a cold-start landing.
- **Tab copy**: Chatbot, Agents, Images, Videos. Routes stay `/chatbot`, `/coding`, `/images`, `/videos` unless a rename is cheaper than churn; labels change either way.
- **Agents positioning**: general computer-use / cowork agent that can code. Not a coding-only IDE. Do not retitle the module "Coding".
- **Tools**: always enabled for Chatbot and Agents. Remove the checkbox. Web search and other tools stay behind existing confirmation/sandbox gates, not behind a user toggle.
- **Picker source of truth**: intersection of (a) catalog entries for that tab's task, (b) actually on disk / in Ollama, (c) in the installer `selected_model_ids` snapshot **or** later downloaded from Settings. Leftover weights from a previous install that were not in this run and not later downloaded do not appear.
- **Order**: installer `selected_model_ids` order, then in-app downloads appended.
- **Default selection**: favorite for that tab if set and still installed; else the installer-recommended id for that tab if installed; else first in the ordered list. Never `gemma4:e4b` unless that id is actually installed.
- **Favorite**: at most one per tab, chosen in Settings > Models. Changing favorite updates the next cold start and the next empty-session picker, not an in-flight session mid-send.
- **`+`**: navigates to Settings > Models (URL-addressable tab). That page shows catalog + download, not a fake model id.
- **Inline media**: fit in one viewport (suggested max height ~40vh, max width of the bubble column). Click opens a modal preview (dialog, Esc closes, fullscreen control, Download, Copy image).
- **In-chat icon row**: Download and Copy image only. Prompt/seed/remix/use-as-source live in the preview dialog (or Advanced settings), with visible tooltips. Do not leave a row of unexplained glyphs under an empty box.
- **Empty generate**: assistant bubble is an error string, never a grey rectangle, never a 48rem empty `<img>`.
- **Hub auto-update**: default ON. Label: "Auto-update to latest Nexus-Hub release". Idle-time cadence may stay weekly; the copy must not say "sync" as if it were optional housekeeping.
- **IPC**: do not globally raise the 15s timeout. `skills.sync` (and only methods that clone/fetch Hub) get a long timeout or a job+poll protocol.
- **Shipping version**: do not bump root `package.json` (2.1.0) or `desktop/package.json` (1.5.0) unless asked. Plan version is v2.2.4.
- **Do not re-run** v2.2.0 / v2.2.1 / v2.2.2 / v2.2.3 as greenfield. Do not rebuild `NexusSetup.exe` unless the runtime snapshot write needs an installer hook; prefer writing the snapshot from the existing install summary onto disk at end of install **and** a one-time migration that reconstructs it from weights+Ollama if the file is missing (so current users are not stuck until they reinstall).
- **Peeking a tab still never loads weights** (v2.2.3 occupancy lock).

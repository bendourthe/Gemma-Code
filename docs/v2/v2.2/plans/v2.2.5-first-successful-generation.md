### Root causes (supported)

#### R1 -- Chatbot: two model-id namespaces (screenshot 3) -- P0

**Supported.** Catalog id for Gemma 4 12B is `gemma-4-12b-it-gguf` (`core/registry/catalog.json`, Ollama URL `ollama://gemma4:12b`). Chat picker lists that catalog id. Send calls `chat.session.start` with `chat?.modelId ?? modelId` (`desktop/src/modules/chat/ChatPage.tsx` `sendChatTurn`). Sidecar `ChatSessionManager.start` calls `requireModel` (`desktop/sidecar/src/coding/models.ts`), which looks up `ModelCatalog.listLlm()` (`core/registry/ModelCatalog.ts`). That LLM table still starts at `gemma4:e4b` and does not contain `gemma-4-12b-it-gguf`. Result: `(chat unavailable) sidecar request error: Unknown model id: gemma-4-12b-it-gguf`.

v2.2.4 Phase 3 appended the user bubble before residency returns. That is why "Hi" is visible. The session still dies on `requireModel`. Same class as v2.2.4 R4/R6 (dropdown vs send id), not closed for GGUF catalog ids vs Ollama tags vs the coding LLM table.

#### R2 -- Settings > Models cannot scroll (screenshot 1)

**Supported.** `desktop/src/pages/settings/ModelsSettings.tsx` `listStyle` is a flex column `ul` with no `overflowY`, no `flex: 1`, no `minHeight: 0`. `pageStyle` is also a flex column. `SettingsPage` shell is `flex: 1; flex-direction: column` with no overflow. Serving / Fine-tuning settings already use `overflowY: "auto"`. The Models list grows until the window clips it. Qwen 3.5 4B is cut off with no scrollbar.

#### R3 -- Qwen 3.5 4B shows Download after a successful-looking install (screenshot 1)

**Supported as a class of bugs; live Ollama tags not re-probed in this session.** Catalog id is `qwen3.5:4b`. Downloaded in Settings is `item.installed && item.source !== "catalog-only"`. Installed-ness is Ollama `/api/tags` intersect plus `~/.nexus/selected-models.json`. Likely stacked causes:

1. Installer family collapse can hide or skip the 4B pull once 9B fits (`catalog.json` differentiators text; `tier_defaults.py`).
2. Snapshot `orderedIds` may record a different sibling than the card the operator ticked.
3. Probe matches Ollama tags (`qwen3.5:4b`) while the card id or snapshot uses another spelling.
4. Pull appeared to finish in the wizard UI but Ollama never registered the tag.

v2.2.5 must treat snapshot + Ollama tags + catalog id as one residency contract, and show Downloaded only when the tag is actually present.

#### R4 -- Compatible plus Needs 20 GB VRAM (screenshot 2)

**Supported.** `recommendationKind()` in `desktop/src/shared/models/catalogTabs.ts` returns `required` / `recommended` from tags, else always `"compatible"`. Hardware fit is a separate `modelFitsHost` check. `ModelCard` still paints the Compatible badge while `RowActions` shows "Needs N GB VRAM". The installer `_card_status` in `typed_catalog.py` never returns Compatible when `fits` is false. Settings must use that same badge priority.

#### R5 -- Settings cards are not installer cards (screenshot 2)

**Supported.** `ListedModelDto` has description / strengths / license / size / VRAM. It does **not** marshal `releaseDate`, `origin`, or `uncensored` even though `catalog.json` has them. `modelsOnTab` filters only; it does not sort by recommended, then release date, then name. There is no shared card component with the Qt wizard. v2.2.4 Phase 5 shipped tabs + Download/Downloaded, not visual or metadata parity.

#### R6 -- Chat list: rename/delete only via context menu; no chats-pane pill (screenshot 3)

**Supported.** `FolderTree.tsx` documents right-click Rename/Delete, F2, and double-click rename. There are no per-row icon buttons. Left-click on an already-selected chat opens the chat; it does not enter rename. The main rail has an edge collapse pill from v2.2.4; the chats `aside` is a fixed 280px column with no twin pill.

#### R7 -- Image generation completes without bytes (screenshot 4); video same class

**Supported.** Sidecar `handlers.ts` throws `Image generation completed without image bytes.` when `result.pngBase64` is empty. The UI maps that to the screenshot 4 string. v2.2.4 Phase 4 made empty completes honest. It did **not** make diffusion return PNG bytes. Video analog: complete without `mp4Path`. Residual live-GPU remains DF-4 until a real generate on this host succeeds. This cycle's DoD requires that field proof, not another error-copy tweak.

#### R8 -- Hub Active 3.12.0; sync blocked by injection scanner (screenshot 5)

**Supported.** Installer `hub_catalog_provisioner.py` is offline-first: extract bundled snapshot, then optional `--sync-hub-catalog`. Tests and the frozen snapshot pin `v3.12.0`. That is why Settings shows Active 3.12.0. In-app Update hits `NexusHubSyncer` fail-closed `PromptInjectionScanner`. `HUB_SKILL_SCAN_ALLOWLIST` was reviewed against Hub **v3.10.0**. A 3.12.0 -> 3.19.2 diff (`+9 new, ~101 modified, -295 removed`) trips the scanner, so apply never happens. Do not disable the scanner. Refresh the allowlist against the new tag and make install + pack-time snapshot resolve **latest** when the network is available.

### Locked product decisions

- **Success bar**: at least one real Chatbot reply, one real Image Studio PNG, and one Video Lab clip (when video weights are installed) on the operator machine. Vitest-only honesty is not enough.
- **Single id space**: every picker, snapshot row, Ollama tag, `requireModel`, and Settings card resolve through one alias table. Catalog id, Ollama tag, and coding LLM id are aliases of the same model, never competing sources of truth.
- **Downloaded**: true only when the runtime (Ollama `/api/tags` or weights dir) actually has the artifact. Snapshot membership alone is not enough.
- **Badge priority** (installer `_card_status`): Required > does-not-fit (show the VRAM/RAM reason, never Compatible) > Recommended > Compatible.
- **Sort**: Recommended / Required first, then newer `releaseDate`, then display name. Match the installer.
- **Cards**: shared field set with the Qt catalog card (description, best-for, origin, release date, censored/uncensored, size, VRAM, license, badge, Download vs Downloaded). React will not iframe Qt; it must look the same.
- **Chat explorer**: right-click stays. Icon buttons are required. Second left-click on the selected chat enters inline rename. Chats pane collapse pill matches the rail pill pattern (`nexus-sidebar-collapse-pill`).
- **Hub**: fail-closed scanner stays. Allowlist is reviewed per Hub tag, not a blanket mute. Installer with network pulls latest; pack-time snapshot is rebuilt from that latest, not from a hardcoded 3.12.0. Offline install may extract the bundled latest-at-build snapshot, then refresh on first app Update.
- **Shipping version**: do not bump root `package.json` (2.1.0) or `desktop/package.json` (1.5.0). Plan version is v2.2.5.
- **Do not re-run** v2.2.0-v2.2.4 as greenfield. Keep v2.2.4 product locks (cold start Chatbot, tab labels, peeking never loads weights, tools always on).
- **Do not disable** the injection scanner to make Hub Update green.

**Prerequisites**: None.

**Recommended model tier**: frontier
**Recommended effort level**: max

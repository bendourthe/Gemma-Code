**Project**: Nexus AI Studio

**Seeded from**: operator request after v2.2.5/v2.2.6 (catalog context window on Models tabs; session context progress bar; date/time/token chrome on all four transcripts). Not a comparison report.
**Goal**: Every listed model shows its reported context window on the installer Models tab and desktop Settings Models tab. Each Chatbot, Agents, Images, and Videos composer shows a modern progress bar for how much of the active model's context the current session has used (input + reasoning + output). At 80% the UI suggests starting a new session. Transcripts show a once-per-day date heading (Day, Month Date, Year), a discrete time on every bubble, and a token count next to that time (input tokens on user prompts; reasoning + output tokens on model replies).

## Overview

Local models ship with short, different context windows. The installer can already chip a text model's in/out window when the catalog has numbers; desktop Settings Models does not show that field at all. None of the four composers show how full the active window is, and bubbles have no clock or token cost even though sidecar chat already reads Ollama usage.

This patch marshals catalog `contextWindow` onto both Models tabs, persists per-turn usage on v2.2.6 sessions, draws a shared meter under every composer with a non-blocking 80% new-session suggestion, and adds messenger chrome (once-per-day date, discrete time, tokens by role). Image/video rows often have a null LLM window; the meter then uses `visualTokenBudget` or hides rather than inventing 128k.

Success is the operator field checklist: real catalog numbers on installer and Settings, a rising meter that suggests a new session at 80% without wiping history, and transcripts that read with dates, clocks, and honest token counts (or "-" when unknown).

### Locked product decisions

- **Catalog context window**: installer Models tab and desktop Settings Models tab both show the reported window (same number the catalog already stores as `contextWindow`, plus in/out split when the installer already has it). Missing value: omit the chip or show "Context: not reported", never a fake 128k.
- **Session meter**: under the typing area on Chatbot, Agents, Images, and Videos. Fill is `usedTokens / contextWindow` as a percent. `usedTokens` is the running session total of input + reasoning + output (Ollama `prompt_eval_count` + `eval_count` plus thinking tokens when the backend reports them; estimate only when usage is absent, and label it Estimate).
- **80% suggestion**: non-blocking notification to start a new session. Do not auto-wipe the transcript. Do not block send.
- **Date heading**: once per calendar day in the transcript, English locale form `Weekday, Month Date, Year` (example: Sunday, August 23, 2026). Not once per bubble.
- **Time**: discrete modern text on every bubble (all four modes), local timezone, not relative "2m ago" as the only clock.
- **Tokens next to time**: user bubble = input tokens for that prompt. Assistant bubble = reasoning + output tokens for that reply. Hide or show "-" when unknown; do not invent 0.
- **Image/Video analog**: when `contextWindow` is null, use `visualTokenBudget` (or documented prompt+visual budget) as the denominator and say so in the meter aria-label. If neither exists, hide the bar and do not fake 100%.
- **Do not re-run** v2.2.0-v2.2.6 as greenfield. Keep prior product locks (cold start Chatbot, tab labels, peeking never loads weights, tools always on).
- **Shipping version**: do not bump package.json files.
- **Do not disable** the Hub injection scanner.

## 2. Chronological Steps

### 2.1 Canonical alias table (T001)

**Plan specification**: One module maps catalog id, Ollama tag, coding LLM id, and weights id. Duplicate aliases that mean two different runtimes fail at load. Unknown ids never fall back to `gemma4:e4b`. Chat-only rows still resolve to an Ollama runtime id.

**What happened**: Added `core/registry/modelAliases.ts` over bundled `catalog.json` plus `ModelCatalog.listLlm()`. Gemma 4 12B, Qwen 3.5 4B/9B, LFM2.5, and the Image/Video picker ids all resolve. Dual-tier Nemotron native and expert-offload share `nemotron-3.5-lightning:30b`; that is the same runtime, so the table keeps both catalog ids and maps the shared tag to the first row. A true collision (same alias, different runtime ids) still throws `DuplicateModelAliasError`.

**Key files changed**: `core/registry/modelAliases.ts`, `core/tsconfig.json` (`resolveJsonModule`), `tests/unit/core/registry/modelAliases.test.ts`

### 2.2 requireModel and installed probe (T002, T004)

**Plan specification**: Session start and residency use aliases. Snapshot membership is not proof of bytes.

**What happened**: Sidecar `lookupModel` / `requireModel` go through `lookupAlias` then `toSidecarRuntime`. Unknown ids throw `Unknown model id` plus a Known aliases preview. Installed probe ORs `isInstalledByAliases` so a catalog card is installed when any alias is in Ollama `/api/tags` or the weights tree.

**Key files changed**: `desktop/sidecar/src/coding/models.ts`, `core/registry/installedProbe.ts`, `desktop/tests/coding-models.test.ts`, `desktop/tests/installedProbe.test.ts`

### 2.3 Chat and Agents send fold (T003, T005)

**Plan specification**: Picker value stays the catalog id. `chat.session.start` and coding session start send the folded runtime id.

**What happened**: `ChatPage` and `CodingPage` pass `foldModelId(...)` into session start. Stale `chat.modelId` values fold on send. Empty installed list still shows the Hi bubble and does not start (v2.2.4 lock).

**Key files changed**: `desktop/src/modules/chat/ChatPage.tsx`, `desktop/src/modules/coding/CodingPage.tsx`, `desktop/tests/ChatPage.test.tsx`, `desktop/tests/chat-session.test.ts`

## 4. Decisions

- Shared Ollama tags on dual-tier siblings are one runtime, not a catalog-load failure. Lookup of the tag returns the first catalog row; each row still lists the tag in `aliases` so the installed probe marks both cards when the tag is on disk.
- Chat-only Gemma 4 12B has `codingAvailable: false` and inferred gemma prompt/tool formats. Coding `SIDECAR_MODELS` is still `ModelCatalog.listLlm()` only.
- Default `/api/chat` on this Gemma 4 12B build fills `message.thinking` and can leave `message.content` empty. The chatbot handler streams `content` only. Field proof used `think:false` to get visible assistant text. Mapping thinking tokens into the Chatbot bubble is residual, not part of the id fold.

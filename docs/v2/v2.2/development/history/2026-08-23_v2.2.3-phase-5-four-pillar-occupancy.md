## 2. Chronological Steps

### 2.1 Read-only scheduler occupancy IPC

**Plan specification**: Expose the Studio `GpuScheduler` active job through a new protocol method; the unrelated cron scheduler is not an occupancy source.

**What happened**: `generation.scheduler.snapshot` now returns the scheduler's typed active, queued, and foreground state. The handler resolves the existing Studio runtime and never mutates the queue or loads a model.

**Key files changed**: `desktop/sidecar/src/protocol.ts`, `desktop/sidecar/src/handlers.ts`

### 2.2 App supplies real policy inputs

**Plan specification**: Use telemetry `vramFreeGB`, not total VRAM, pass the scheduler active job to both Studios, and stop Image from silently defaulting to the low diffusion tier.

**What happened**: App tracks total and free VRAM separately, polls the new scheduler snapshot, passes the active job and free VRAM to all four modules, and passes `classifyDiffusionTier(hostVramGB)` to both Studio pages. A shared renderer-session set preserves Remember across route remounts without persisting consent.

**Key files changed**: `desktop/src/App.tsx`, `desktop/src/shared/models/schedulerResidency.ts`, `desktop/src/shared/models/useModelResidency.ts`

### 2.3 Four submit gates and one-shot approval

**Plan specification**: Chat and Coding must match Image and Video: classify on submit, render the shared dialog, and do not dispatch until the user decides.

**What happened**: Chat and Coding now store the pending prompt before any session send. All four pages derive the incumbent from the active scheduler job, treat missing target sizing as unknown rather than zero, and render a refusal when a model is unavailable. The existing Studio re-entry pattern was corrected: resolving Switch bypasses classification once, so an unchecked Remember box cannot reopen the same dialog.

**Key files changed**: `desktop/src/modules/chat/ChatPage.tsx`, `desktop/src/modules/coding/CodingPage.tsx`, `desktop/src/modules/image/ImageStudioPage.tsx`, `desktop/src/modules/video/VideoLabPage.tsx`

## 5. Plan Discrepancies

The existing Image and Video code did not actually preserve Remember across route remounts because each page owned a separate hook, and Switch without Remember could reopen the dialog on re-entry. Phase 5 added a shared App-session memory set and a one-shot approved resume to satisfy the stated session and dispatch behavior.

---

## 6. Assumptions Made

- **The Studio scheduler is the canonical occupancy snapshot for this phase**: this follows the verification addendum and avoids confusing the cron-style AgentRunScheduler with GPU work.
- **An active job without a model id still represents an incumbent**: the adapter uses an internal sentinel for policy comparison while the dialog says "The current model".
- **Missing model VRAM is not zero**: an unknown catalog estimate cannot justify silent co-residency.

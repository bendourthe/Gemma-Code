# Session History - v2.2.1 Phase 1: Sidecar stays alive

**Date**: 2026-08-22
**Plan**: `docs/v2/v2.2/plans/v2.2.1-field-repair-and-chrome-completion.md`
**Phase**: 1 - Sidecar stays alive

## What this session set out to do

Stop the 2026-08-22 Complete-page failure (`The pipe is being closed. (os error 232) | stderr: [ / / Nodejs v22.11.0]`). Node was starting, then dying, then the next JSON-RPC write hit a closed stdin.

## What landed

- `Sidecar::spawn_with` sets cwd to `script.parent()` so `better-sqlite3` resolves next to `main.js`.
- After spawn, wait for `[nexus-sidecar] ready` on stderr or 500 ms of liveness (`try_wait` is None) before any RPC write.
- A child that exits becomes `sidecar-exited:<code>` plus the stderr tail, never a Windows 232 wrapping a dead pipe.
- `--healthcheck` verdict JSON always includes `exitCode`, `nodePath`, `scriptPath`, and the last 20 stderr lines.
- Installer formatter skips blank fragments and never joins three lines with `" / "`.
- Sidecar `main.ts` prints the ready marker after stdin is wired. Import-time crashes never reach it, which is the intended dead-child path.
- Packaging assertion: Tauri maps the whole `sidecar/dist` tree; when `dist/main.js` exists, `better_sqlite3.node` must sit next to it.
- `installer-tests.yml` path filters include `desktop/src-tauri/**` and `desktop/sidecar/**`.

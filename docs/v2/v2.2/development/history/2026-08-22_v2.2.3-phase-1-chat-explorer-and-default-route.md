## 2. Chronological Steps

### 2.1 Promise-safe explorer adapter

**Plan specification**: Reconcile the explorer type families, map every FolderTree call onto a promise-safe client, cache tree-backed lookups, and retain the synchronous in-memory test client.

**What happened**: `AsyncChatExplorerClient` now describes values that may be immediate or promised. The IPC adapter supplies `listTree`, object-form `createFolder`, cached `getFolder`, `getChat`, and `ancestors`, delegated or cached search, and cache invalidation after mutations. FolderTree uses `resolveMaybe` for reads and writes, so a rejected IPC request becomes a one-line tree error rather than an uncaught render failure.

**Key files changed**: `desktop/src/modules/chat/types.ts`, `desktop/src/modules/chat/chatExplorerClient.ts`, `desktop/src/modules/chat/ipcChatExplorerClient.ts`, `desktop/src/modules/chat/FolderTree.tsx`, `desktop/src/modules/chat/ChatPage.tsx`

**Troubleshooting**: No implementation failure occurred during this continuation. The earlier single-file test failure report was a concurrent-Vitest contention artifact; the required solo full suite passed.

### 2.2 Route containment and first-launch route

**Plan specification**: Add a module-level error boundary, redirect `/` to `/chatbot`, and normalize missing, Dashboard, and invalid persisted routes while preserving real module routes.

**What happened**: `ModuleErrorBoundary` wraps the routed module pane and remounts per pathname. ChatPage completes the `minHeight: 0` flex chain. `normalizeActiveRoute` makes Local Chatbot the first-launch fallback while keeping Dashboard explicitly reachable at `/dashboard`.

**Key files changed**: `desktop/src/components/ModuleErrorBoundary.tsx`, `desktop/src/App.tsx`, `desktop/src/lib/persistence.ts`, `desktop/src/main.tsx`

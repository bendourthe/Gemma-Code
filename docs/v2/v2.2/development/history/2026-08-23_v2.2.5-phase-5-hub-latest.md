## 2. Chronological Steps

### 2.1 Latest Hub at pack and install (T017)

**Plan specification**: Pack-time and networked install pull latest. Stop treating `v3.12.0` as the production pin in tests. Inject a fake latest. Document the snapshot tag in the manifest. Latest tag API fail: fail the pack job rather than silently ship 3.12.0.

**What happened**: `build-hub-snapshot.py` resolves latest via GitHub (or `NEXUS_HUB_LATEST_TAG`). `--require-latest` is the default. A catalog whose `nexus-hub-version.json` does not match latest exits 1 and writes no archive. `--allow-stale` is the explicit escape. Windows/macOS/Linux pack scripts clear `hub-snapshot/` on that failure so a stale 3.12.0 tarball is not embedded; the installer still builds and syncs at install time. Provisioner and desktop Hub tests now use injected `v9.9.9`.

**Key files changed**: `scripts/installer/build/build-hub-snapshot.py`, `build-windows.ps1`, `build-linux.sh`, `build-macos.sh`, `hub_catalog_provisioner.py`, installer and desktop Hub tests

### 2.2 Scanner allowlist for the new tag (T018, T019)

**Plan specification**: Re-review `HUB_SKILL_SCAN_ALLOWLIST` against the latest Hub tag. Do not disable the scanner. Fixture that used to block now applies iff each suppression is justified; a planted jailbreak still blocks.

**What happened**: GitHub `/releases/latest` for `bendourthe/Nexus-Hub` on 2026-08-23 is **v3.19.2**. Existing nine (skill, rule) waivers still name paths that exist in that tag. Exported `HUB_ALLOWLIST_REVIEWED_TAG = "v3.19.2"`. Production scanner still uses the allowlist only for the trusted Hub source. Tests: allowlisted `security/ai-attack-patterns` snippet passes; `security/unreviewed-injection` planted jailbreak blocks. Untrusted `SkillInstaller` still has no suppressions.

**Key files changed**: `core/skills/hubSkillScanAllowlist.ts`, `tests/unit/core/skills/PromptInjectionScanner.test.ts`

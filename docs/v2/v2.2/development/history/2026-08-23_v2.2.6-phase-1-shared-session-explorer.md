### 2.3 Testing and stabilization (1.3)

**Branch**: `develop` | **PR**: none | **Merged to**: n/a

**Plan specification**: Create an image session, append user + assistant media ref, list after a new store instance. Chat explorer regressions.

**What happened**: Root tests cover two-instance round-trip, pillar isolation, empty rename, delete-then-rename, corrupt JSON skip, blob reject, sidecar ops. Desktop tests cover history pane present, injected session title, sidecar-down empty hint, FolderTree default copy unchanged.

**Troubleshooting**:
- **Problem**: Desktop history pane tests rendered `folder-tree-empty` ("Start a new session") even after `InMemoryStudioExplorerClient.createSession(...)`.
- **Attempted**: Confirmed `mapTree` already maps `sessions` to `chats`. Sidecar-down path was already correct (no FolderTree).
- **Root cause**: `studioClientAsChatExplorer` marked every method `async` and `await Promise.resolve(...)`, so FolderTree `resolveMaybe` took the Promise path. Initial state is EMPTY_TREE; tests asserted on the first paint.
- **Resolution**: Adapter methods stay synchronous when the inner client is synchronous (`wrap` only then-ables). IPC clients still return Promises.
- **Problem**: `StudioSessionStore` two-instance test failed on Windows `rmSync` EPERM because the second store was still open in `finally`.
- **Resolution**: Close `second` before `rmSync`. Swallow leftover EPERM on Windows WAL handles.

**Verification**: Commands and counts in section 3.

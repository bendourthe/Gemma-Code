## 2. Chronological steps

### 2.1 Snapshot on disk

**Plan specification**: Write ordered selected ids at end of install. Sidecar `models.list` exposes the snapshot. In-app downloads append. Missing file migrates from currently installed ids without hiding installer models if no snapshot exists yet.

**What happened**: `desktop/sidecar/src/models/selectionSnapshot.ts` reads and writes `~/.nexus/selected-models.json`. `appendDownloadedId` is a no-op when the file is absent. `models.list` returns `selection` without calling migrate (so handler tests do not write homedir). The installer `write_selection_snapshot` hook writes the same schema next to `runtime.json`.

**Key files changed**: `desktop/sidecar/src/models/selectionSnapshot.ts`, `desktop/sidecar/src/handlers.ts`, `desktop/sidecar/src/protocol.ts`, `scripts/installer/src/nexus_installer/engine/runtime_provisioner.py`

### 2.2 Shared picker policy

**Plan specification**: Installed-only, installer order, favorite then recommended then first. Compact switcher must not display ready[0] while parent state stays on another id.

**What happened**: `selectionPolicy.ts` owns the intersect and default. `QuickModelSwitcher` calls `onChange(ready[0])` when `value` is missing. Chat and Agents resolve default after `list()`. Images and Videos pass `ownedIdSet(lastSelection)` into `installedModelsForType`. Favorites live in `localStorage` under `nexus.ui.favoriteModel.<task>`.

**Key files changed**: `desktop/src/shared/models/selectionPolicy.ts`, `desktop/src/shared/models/QuickModelSwitcher.tsx`, `desktop/src/shared/models/installedFeed.ts`, Chat / Coding / Image / Video pages, `desktop/src/pages/settings/ipcModelsClient.ts`

### 2.3 Fallback rows are not installed

**Plan specification**: Do not mark catalog Gemma 4 as installed when IPC is down.

**What happened**: Chat and Agents `FALLBACK_LLMS` now set `installed: false`. Tests that send inject an explicit installed fixture.

**Key files changed**: `desktop/src/modules/chat/ChatPage.tsx`, `desktop/src/modules/coding/CodingPage.tsx`, `desktop/tests/ChatPage.test.tsx`, `desktop/tests/CodingPage.test.tsx`

### 2.4 Settings URL tab (DF-17)

**Plan specification**: `?tab=models` must switch the Models tab when Settings is already mounted.

**What happened**: `SettingsPage` uses `useSearchParams`, honors `tab` on mount and on query change, and writes `tab` when the user clicks a Settings tab.

**Key files changed**: `desktop/src/pages/settings/SettingsPage.tsx`, `desktop/tests/SettingsPage.test.tsx`

## 4. Decisions and deviations

- Favorites stay in `localStorage` this phase; sidecar `settings.get` is still unimplemented. Phase 5 can star a favorite in Settings UI on top of the same keys.
- `models.list` does not call `loadOrMigrate`, so a host with leftover weights and no snapshot still sees the probe set until they reinstall or we add a one-shot migrate on sidecar boot. That is the documented migration window, not silent catalog leakage once a snapshot exists.
- Image/Video ipc-unavailable still seed a local FALLBACK row so existing studio tests keep a model id. Sidecar-down continues to show empty + banner.

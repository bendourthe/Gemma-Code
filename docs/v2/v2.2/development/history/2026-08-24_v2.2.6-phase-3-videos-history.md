## 2. Chronological Steps

### 2.1 Persist video turns (3.1)

**Plan specification**: Mirror Phase 2 for VideoLabPage. Persist outputPath. Follow-up without a new photo may set continueFrom or sourceImage only when the existing video protocol already supports it. Missing mp4: error text, not a complete with empty path.

**What happened**: VideoLabPage auto-creates a named session on first send when sidecar is up / an explorer is injected. persistTurn no-ops when sidecar is down. Completes persist mp4Path when it is a real path, never a data: blob. Errors persist text and do not move lastOutputRef. studioTurnsToChatMessages gained mediaKind so hydrated clips render as video.

### 2.2 Implicit last-clip follow-up (3.1)

**Plan specification**: Empty attachments after a successful generate may condition on the last playable clip when continueFrom already exists. Do not invent continueFrom. User photo attachments still win (image2video).

**What happened**: continueFrom already existed for intra-job segment chaining (priorJobId, lastFramePath, segmentIndex, segmentCount). In-session follow-ups with no photo attach that object using the last complete job id and last mp4 path. After remount, priorJobId is not in the session schema, so a follow-up is a new text2video. Unreadable lastOutputRef fail-closes with UNREADABLE_OUTPUT_TEXT.

### 2.3 Tests (3.2)

Implicit continueFrom + persist, remount hydrate, missing-file hydrate. Existing text2video tests still pass.

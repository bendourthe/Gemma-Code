## 2. Chronological Steps

### 2.1 Apply with quarantine (T011, T012)

**Plan specification**: Quarantine high-severity skills, apply the rest, set Active to latest. Keep `PromptInjectionScanner`. "Sync blocked" only for hard fail-closed cases. Pack-time snapshot still refuses stale 3.12.0. Do not allowlist a planted jailbreak. Re-review the allowlist stamp against GitHub latest.

**What happened**: After scan, `quarantineHighSeveritySkills` moves each high-severity skill dir from staged `skills/` to `catalog/quarantine/<relPath>/` and writes `quarantine/index.json`. `--apply` then swaps the staged catalog including quarantine. `scan.decision === "block"` no longer skips the swap. Scanner throw or a quarantine-move throw deletes staging and does not apply. Module-level `syncFlight` coalesces overlapping `sync()` calls across `new NexusHubSyncer({})` instances. Allowlist re-stamped `HUB_ALLOWLIST_REVIEWED_TAG = "v3.20.1"` (GitHub latest on 2026-08-24); existing nine (skill, rule) waivers unchanged; planted jailbreak not added. `ipcSkillsClient.syncNow` throws only when `blocked && !applied`. `skills.sync` summary includes `; quarantined N`. `readHubCatalog` walks nested Hub folders and lists quarantine index rows as `active: false` with `quarantine.decision === "block"`. Installer CLI treats applied-with-quarantine as success. `nexus skills sync` no longer exits 1 on scanner findings when apply still ran.

**Key files changed**: `core/skills/NexusHubSyncer.ts`, `core/skills/hubSkillScanAllowlist.ts`, `desktop/sidecar/src/handlers.ts`, `desktop/sidecar/src/protocol.ts`, `desktop/sidecar/src/skills/hubSkillReader.ts`, `desktop/sidecar/src/cli/hubCatalogCli.ts`, `desktop/src/pages/settings/ipcSkillsClient.ts`, `bin/nexus.mjs`

## What was implemented

- **4.1 (T009)**: The combined "GPU or diffusion weights unavailable" string is no longer the only failure message. `RuntimeNotReady` now carries a `kind`; `classify_runtime_not_ready()` in `runtimes/diffusion/pipelines/base.py` probes in a documented deterministic order (torch/CUDA state in the diffusion venv first, then weights for the model id, then diffusers import, then a generic wiring fallback) and reports exactly one kind:
  1. `cuda-torch-missing`: "image runtime is not ready: no CUDA torch in the diffusion Python environment (torch is missing or a CPU-only build); app telemetry can still show NVIDIA VRAM because Ollama can use the GPU while this environment stays CPU-only"
  2. `weights-missing`: "image runtime is not ready: weights for model {model_id} not found at {models_root}/weights/{model_id}" (names the id and the path)
  3. `gpu-not-available`: "image runtime is not ready: GPU not available (CUDA torch is installed but no usable CUDA device was detected)"
  Video variants are identical with "video" in place of "image". `video_base.py` delegates to the same classifier. `real_execute.py` raises the typed kinds from its accelerator/weights checks and documents the Ollama-vs-venv telemetry trap.
- Sidecar `resultGuard.ts`: any `ok:false` runtime message passes through verbatim; the old combined constants remain only as last-resort fallbacks for envelope-less empty/1x1 payloads and are never a collapse target.
- Fail-closed posture unchanged; `NEXUS_DIFFUSION_ALLOW_STUB` stays pytest-gated; DF-4 stays open (no claim of a working generate).

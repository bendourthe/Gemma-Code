# Development Log: v2.2.5 Phase 2 - Diffusion actually returns bytes

**Date**: 2026-08-23
**Operator**: Project owner
**Objective**: Image Studio returns usable PNG bytes (or a typed pre-complete GPU/runtime error). Video Lab does the same for `mp4Path`. Empty "completed without image bytes" on a healthy path is P0.
**Outcome**: SANA catalog ids call the registered Python methods. The Node dispatcher rejects empty, 1x1, and `ok: false` payloads before `complete`. Production hosts without GPU or weights fail closed instead of returning a stub 1x1 PNG. Live GPU generate was not run this session (DF-4).

---

## 1. Starting State

- **Branch**: `develop`
- **Plan reference**: `docs/v2/v2.2/plans/v2.2.5-first-successful-generation.md`
- **Prior session reference**: `docs/v2/v2.2/development/history/2026-08-23_v2.2.5-phase-1-unify-model-ids.md`

Python `txt2img` / SANA handlers used a 1x1 PNG stub. `isUsableImageBase64` rejects 1x1, so the UI said the job completed without image bytes. The Node dispatcher called method `txt2img` even for SANA catalog ids. The dispatcher ignored `ok: false` and forwarded empty `pngBase64`. Video stubs returned `mp4_path=None`. `select_executor` was decided at import time on the video module (a leftover override after the lazy dispatcher).

## 2. Chronological Steps

### 2.1 Image generate path (T006, T008)

**Plan specification**: Successful jobs always have image bytes. Failures happen before `complete`. Log backend stderr on empty complete. Keep `isUsableImageBase64` in the UI.

**What happened**: Added `desktop/sidecar/src/diffusion/route.ts` (`foldRequestModelId`, `resolveImageMethod`, `requireSourceImageBytes`) and `resultGuard.ts`. `buildJobRequest` folds the picker id, routes SANA/INT4/Sprint to `sana.txt2img` / `sana_int4.txt2img` / `sana_sprint.txt2img`, and throws `IMAGE_RUNTIME_NOT_READY` on empty or 1x1 PNG. Python `select_executor` is lazy: real GPU path, pytest stub, or fail-closed. `real_execute.py` loads `~/.nexus/models/weights/<id>/` with `local_files_only=True`. ImagePromptForm folds `modelId` on send.

**Key files changed**: `route.ts`, `resultGuard.ts`, `dispatcher.ts`, `runtimeClient.ts` (`lastStderr`), `handlers.ts`, `runtimes/diffusion/pipelines/base.py`, `real_execute.py`, per-pipeline `register()`.

### 2.2 Video analog (T007)

**Plan specification**: Video complete without `mp4Path` is the same class as empty PNG. Alias-fold the picker id.

**What happened**: `buildVideoJobRequest` uses `resolveVideoMethod` (SANA-Video -> `diffusion.video.sana.*`) and `requireUsableVideoPath`. Removed a leftover import-time `select_executor` at the bottom of `video_base.py` that overrode the fail-closed dispatcher. VideoPromptForm folds `modelId`. No video weights were generated on this host; the typed not-ready path is the field contract when GPU/weights are missing.

**Key files changed**: `videoDispatcher.ts`, `video_base.py`, video pipeline registers, `VideoPromptForm.tsx`.

## 4. Decisions

- Production must not emit the 1x1 CI stub. Pytest / `NEXUS_DIFFUSION_ALLOW_STUB` still use it so JSON-RPC round-trips stay green without torch.
- INT4 img2img is refused at the Node route, not after a Python 1x1.
- Dual `select_executor` on `video_base.py` was a defect: the second definition always stubbed. Only the lazy dispatcher remains.

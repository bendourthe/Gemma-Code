## 2. Chronological Steps

### 2.1 Explicit workspace selection and persistence

**Plan specification**: Send the already-supported `workspacePath` on `coding.session.start`; refuse an omitted path rather than using the install directory; use either a fully installed native dialog plugin or a persisted text field.

**What happened**: CodingPage now displays a workspace field in its header, persists it through `desktop/src/lib/persistence.ts`, and refuses to start an agent session while the field is empty. The runner no longer falls through to `process.cwd()` and rejects relative or parent-traversing roots.

**Key files changed**: `desktop/src/lib/persistence.ts`, `desktop/src/modules/coding/CodingPage.tsx`, `desktop/sidecar/src/coding/headlessAgentRunner.ts`

### 2.2 Invoked-command and workspace prompt enrichment

**Plan specification**: Resolve command or skill bodies sidecar-side, include workspace `AGENTS.md` and `.nexus` rules, skip scanner-blocked bodies without aborting the base turn, and never inject the entire Hub catalog.

**What happened**: `headlessRunEnrichment.ts` detects a known non-built-in slash command, reads only its Hub Markdown file, strips frontmatter, scans the body, and passes an allowed body through `skillBody`. Workspace instructions and sorted Markdown rules become scoped system instructions. Unknown commands and built-in collisions continue without Hub injection.

**Key files changed**: `desktop/sidecar/src/coding/headlessRunEnrichment.ts`, `desktop/sidecar/src/coding/headlessAgentRunner.ts`

### 2.3 Shared lifecycle and scheduled composition

**Plan specification**: Use the same enrichment for interactive Coding and `AgentRunScheduler`, and wire a vscode-free HookBus lifecycle position or record a residual.

**What happened**: Interactive and scheduled runs call the same enrichment and lifecycle wrapper. The main sidecar creates one telemetry-backed HookBus. Start, user-prompt, skill-entry, end, stop, and reflection events fire; reflection includes the user/tool/assistant transcript and explicit paths written by file mutation tools. Hook failures log and do not abort the turn.

**Key files changed**: `desktop/sidecar/src/coding/scheduledHeadlessRunner.ts`, `desktop/sidecar/src/coding/headlessRunEnrichment.ts`, `desktop/sidecar/src/main.ts`

### 2.4 Per-workspace deny enforcement

**Plan specification**: Honor `.nexus/permissions.deny` on the sidecar headless tool path and fail closed when policy parsing fails.

**What happened**: The shared sidecar tool factory reads the current tool context's workdir policy before execution, evaluates the tool against every relevant argument subject, and returns a written refusal before mutation. Missing policy is inert; malformed or unreadable policy fails closed for the attempted tool.

**Key files changed**: `desktop/sidecar/src/coding/sidecarHeadlessTools.ts`

## 5. Plan Discrepancies

The older prompt described loading a matching SkillCatalog body, but the verified tree exposes Hub command Markdown bodies as the established extension-host directive and returns only descriptors over IPC. Phase 6 resolves that command body sidecar-side and passes it through the existing `skillBody` prompt section. No new body IPC was needed.

---

## 6. Assumptions Made

- **The persisted text field is the cycle's workspace picker**: this is the plan-approved alternative to adding Cargo, JavaScript, capability, and Rust registration for a native dialog plugin.
- **Renderer built-ins keep precedence**: a same-named Hub file cannot reinterpret a built-in command such as `/plan`.
- **Workspace rules are local Markdown**: root `AGENTS.md`, `.nexus/rules.md`, and sorted `.nexus/rules/*.md` are included when present; missing files are omitted.
- **Explicit file tool calls define reflection writes**: write, create, edit, and delete paths are recorded; arbitrary filesystem mutations hidden inside terminal commands are not inferred.

# v1.0.0 -- Distribution channels

**Audience**: release operator, CI maintainer.
**Plan reference**: [phase-11-hardening-and-release.md](plans/phase-11-hardening-and-release.md) sub-task 11.7.

Two surfaces ship in v1.0.0: the Windows desktop installer (primary) and the VS Code Marketplace extension (Coding pillar only; thin-adapter rewrite staged for v1.1.0).

---

## 1. GitHub Releases (primary, Windows installer)

### 1.1 Trigger

A push of an annotated tag `v1.0.0` to `main` triggers the existing semantic-release workflow at `.github/workflows/release.yml`, which in turn calls into `.github/workflows/installer-build.yml` to build the Windows installer.

```bash
git tag -a v1.0.0 -m "$(cat <<'EOF'
Nexus 1.0.0 -- the first production release.

Four-pillar local-first AI workstation:
- Agentic AI Coding
- Local Chatbot Explorer
- Image Studio
- Video Lab

See CHANGELOG.md and docs/v1.0.0/release-notes.md for the full surface.
EOF
)"
```

The release operator pushes the tag only after the Phase 11.9 final stabilization pass is green:

```bash
git push origin v1.0.0
```

### 1.2 Artifacts

- `Nexus-1.0.0-Setup.exe` -- the Authenticode-signed NSIS outer installer, attached to the GitHub Release.
- `Nexus-1.0.0-Setup.exe.sha256` -- companion checksum file (generated by the CI step).
- Source tarball + zip (auto-generated by GitHub from the tag).

### 1.3 Release description

The GitHub Release body is populated from `docs/v1.0.0/release-notes.md` (the user-facing notes). The semantic-release plugin auto-generates a per-commit summary; the Phase 11 release-notes content overrides it via `.releaserc.json`'s `@semantic-release/github` plugin config (operator pastes the release-notes content into the Releases UI manually if semantic-release does not pick it up cleanly).

### 1.4 SmartScreen reputation

A freshly-signed EV cert starts with zero SmartScreen reputation; on the first ~hundreds of downloads, users see the "Verified publisher" line plus a "More info" warning. Reputation accrues automatically as installs complete without rollback. Operator action OA-02: monitor the install-completion telemetry (none ships in v1.0.0; for v1.0.0, monitor the GitHub Release download count and any user-reported install issues via Issues).

## 2. VS Code Marketplace (Coding pillar -- thin variant)

### 2.1 What ships under the Marketplace listing

The v1.0.0 Marketplace VSIX is the existing `gemma-code` extension (publisher: `gemma-code`) with two updates:

1. The extension's `package.json` version bumps to match the parent project (`1.0.0`).
2. The listing description updates to surface the desktop-daemon dependency and the graceful fallback to extension-only mode.

The full thin-adapter rewrite -- where the extension delegates every panel + every tool call to the desktop daemon over JSON-RPC -- is staged for v1.1.0 (per known-gap 2.P1.J / 3.P1.O). v1.0.0 ships the daemon-discovery hook (`desktop/src/desktop/daemonDiscovery.ts`) so the activation path is in place, but the extension still hosts the in-process engine when the daemon is not running.

### 2.2 Publish workflow

```bash
# In repo root.
npm install
npm run compile      # produce out/extension.js
vsce package         # produce gemma-code-1.0.0.vsix
vsce publish         # push to the Marketplace (requires PAT)
```

The Personal Access Token lives in the operator's keychain; for CI publishing, store as GitHub secret `VSCE_PAT` and gate the publish step on tag-push.

### 2.3 Listing description (v1.0.0 update)

The Marketplace listing description gets a new top paragraph:

> **New in 1.0.0**: Nexus is now a full desktop product with four modules (Coding, Chat, Image, Video) -- the VS Code extension provides the Coding pillar only. When the Nexus desktop daemon is running, the extension delegates every chat, memory, and tool call to it for a unified workspace experience. When the daemon is not running, the extension falls back to in-process LLM hosting (the same v0.x behaviour as before). Download the full Nexus desktop installer at https://github.com/bendourthe/Nexus-AI/releases.

### 2.4 Renaming to `nexus-coding` (v1.1.0)

The breaking-change story (manifest IDs change from `gemma-code.*` to `nexus.coding.*`, the package name changes from `gemma-code` to `nexus-coding`, the publisher changes accordingly) is bundled into v1.1.0 so it happens in a single Marketplace re-publish. The v0.x listing under `gemma-code` continues to receive critical security patches until v1.2.0 to give users a migration window.

## 4. Ollama-style direct-download

Out of scope for v1.0.0. The Nexus Windows installer is self-contained; an Ollama-style direct binary (no NSIS, no wizard) is a v1.1.0+ exploration if there is demand for headless / CLI-only install.

# v1.6.0 -- Known Gaps, Deferrals, and Carryovers

**Status**: in-progress (Phases 1-3 closed 2026-06-15). v1.6.0 is the "aisuite harness adoptions + Nexus-AI interactive guide" cycle ([plans/adoption-aisuite-harness.md](plans/adoption-aisuite-harness.md), derived from [comparison-aisuite.md](comparison-aisuite.md)). Phase 1 ships the user-directed headline artifact: the self-contained, offline Nexus-AI interactive guide ([../../../../guides/interactive-guide/nexus-ai-guide.html](../../../../guides/interactive-guide/nexus-ai-guide.html)) -- a 7-page user guide reusing the Nexus-Hub interactive-guide design tokens and constellation background (AS001 + AS002, delivered 2026-06-14), now CI-guarded for offline integrity + reduced motion (AS003, closed 2026-06-15). Phase 2 ships A4: the standalone shareable session/trace viewer ([../../../../modules/coding/observability/TraceHtmlExport.ts](../../../../modules/coding/observability/TraceHtmlExport.ts) + a `nexus trace export` CLI subcommand), a self-contained offline HTML export reusing the Phase 1 design tokens and the `InteractiveArtifact` sanitisation rules (AS004, closed 2026-06-15). Phase 3 ships A1: session-state artifact dehydration -- large message fields (>20KB) are moved out-of-line to a content-addressed, redaction-on-write artifact store under `<nexusHome>/session-artifacts/` and rehydrated on resume, with a one-way v1->v2 migration and a pre-migration-tolerant read path (AS005, closed 2026-06-15). Remaining phases: A2 trace nesting (4), A3 adapter registry (5, backlog), and the FINAL Nexus-Hub sync + acceptance gate (6). This file is appended phase-by-phase; items move to `## 2. Resolved` when closed; the `## 3. Summary` is recomputed each pass.

### Phase 3 follow-ups (forward-tier, not defects)

| ID | Sev | Cat | Description | Suggested next step |
|---|---|---|---|---|
| `AS005.P3.A` | P3 | DF | The `ArtifactStore` is content-addressed and append-only: when a session is overwritten or deleted, the artifacts it referenced are not garbage-collected, so orphaned blobs can accumulate under `<nexusHome>/session-artifacts/`. This mirrors how `CommandCompressor` tee files were initially append-only before `pruneOldTees` was added; the dehydration store ships without an equivalent sweep because session deletion is not yet a surfaced operation and content-addressing means re-saved identical content dedupes rather than duplicates. Tier: dehydrate/hydrate + migration `supported`; orphan reclamation `future`. | When a session-delete surface lands (or as a periodic sweep at sidecar startup, mirroring `CommandCompressor.pruneOldTees`), add a mark-and-sweep that walks live session refs and unlinks unreferenced artifacts. |
| `AS005.P3.B` | P3 | MT | Dehydration operates at whole-message granularity (any message string over the byte threshold) rather than on structured named sub-fields, because the Coding-pillar session persists each turn as an opaque string (`messages: string[]`), not a record with discrete `stdout`/`stderr`/`diff`/`patch`/`content` fields. The `kind` is inferred from content instead. This matches the source comparison's "large message fields (>20KB)" description, but if message turns later become structured records, per-field dehydration (and a precise `kind`) would be tighter. Tier: whole-message dehydration `supported`; per-named-field dehydration `future`. | If/when the session message shape becomes a structured record, extend `dehydrateMessages` to walk named fields and dehydrate each over-threshold field independently, carrying the field name as `kind`. |

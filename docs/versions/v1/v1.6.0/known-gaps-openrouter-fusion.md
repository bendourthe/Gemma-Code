# v1.6.0 (openrouter-fusion) -- Known Gaps, Deferrals, and Carryovers

**Status**: COMPLETE (Phase 5 of 5 closed 2026-06-17; all five phases landed). This is the gap ledger for the **local panel + judge-fusion** companion plan ([plans/adoption-openrouter-fusion.md](plans/adoption-openrouter-fusion.md), derived from [comparison-openrouter-fusion.md](comparison-openrouter-fusion.md)). It is kept **separate** from the sibling [known-gaps.md](known-gaps.md) (which is owned by the aisuite-harness plan and already closed) because the two plans run as distinct ledgers in the same cycle; this file is seeded in Phase 1 because the implement-phase post-phase sequence appends gaps every phase. Phase 1 shipped F1: a `fuse` skill emitting the structured judge-fusion schema and an upgrade of `council`'s synthesis to the same analysis vocabulary. Phase 2 shipped F2 + F5: a `FusionAgent` (the judge, consuming the F1 schema) and a `PanelExecutor` that fans one prompt across N distinct registry models (sequential fan-out MVP) and fuses the survivors, with the judge hardened as an untrusted-input boundary (candidate text redacted + treated as data, single-judge SPOF documented) and panelists granted no per-panelist tools. Phase 3 ships F3: `GpuScheduler.enqueuePanel` admits a bounded panel as one scheduler job that runs concurrently when summed VRAM fits free VRAM and **degrades to sequential** when it does not (no OOM, no rejection), under a hard panel-size cap, with `ModelPinRegistry.holdForPanel` keeping the panel's models resident for the run and releasing them after. Phase 4 ships F4: a local A/B harness (`PanelAbHarness`) that measures a small-model panel against the single best resident model on coding tasks; an opt-in `nexus.llm.panelRouting` routing heuristic (`PanelRouter` + the pure `decidePanelRoute`) that escalates a reliability-flagged task to the panel; and the Phase 3 co-residency primitive wired into `PanelExecutor` (optional `concurrency` backend through `GpuScheduler.enqueuePanel`, closing OF007.P3.A's parallelised-run-path gap). Per the no-degradation gate the routing default ships **opt-in (off)**: the A/B has not been run against live local models in this environment, so no measured net win exists to flip it (recorded as `OF010.P4.A`). Phase 5 (FINAL) ran the whole-plan acceptance gate -- all six definition-of-pass items verified, no feature code changed -- and closed the plan: OF013 (acceptance gate, recorded in Section 4 below), OF014 (docs: this ledger finalized; README/ARCHITECTURE/CHANGELOG narrative + the npm version tag are semantic-release-owned and cut on merge to `main`, matching the sibling aisuite-harness Phase 6 and every P1-P4 DEVLOG note), OF015 (Nexus-Hub touchpoint assessed -- not warranted, recorded as `OF015.P5.A`).

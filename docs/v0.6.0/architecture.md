# Gemma Code v0.6.0 -- Architecture

This document captures the v0.6.0 architecture: the consolidation cycle that closed Attack Path A, ratcheted four module-boundary baseline exceptions to zero, decomposed the two god-class panel modules, and resolved every documented-but-not-implemented claim that survived v0.5.0. It supersedes [docs/v0.5.0/architecture.md](../v0.5.0/architecture.md) for v0.6.0 and complements [ARCHITECTURE.md](../../ARCHITECTURE.md) (which stays version-neutral). Companion analysis: [docs/v0.6.0/analysis.md](./analysis.md).

The user-visible delta in v0.6.0 is **none direct**. The internal-developer-visible delta is large: ~1,800 lines of god-class code split into focused modules; four `BASELINE-2026-04-25; ratchet by v0.6.0` exceptions removed; two circular cycles untangled; the predictive-cache surface deleted; documentation/code drift in `architecture.md` resolved; five new ADRs (0006-0010).

---

## 1. Identity and canonical directives

Unchanged from v0.5.0. `AGENTS.md` is the sole canonical agent directive; the meta-test at `tests/unit/docs/AGENTS-md.test.ts` enforces it. The Module Authorship Contract still defines the rules for adding modules.

What changed:

- The `docs/v0.5.0/architecture.md` permission-tier table was a hand-written copy of `PermissionTiers.ts`. v0.6.0 Phase 5 sub-task 5.4 replaces it with a `<!-- BEGIN:TOOL-PERMISSION-TABLE -->` / `<!-- END:TOOL-PERMISSION-TABLE -->` marker block driven by [scripts/generate-tool-permission-table.mjs](../../scripts/generate-tool-permission-table.mjs). The CI job `npm run perm-tier:check` fails the build if the doc and source disagree. The same pattern guards `docs/index.md` via `npm run catalog:check`.
- The v0.4.0 ship date in `CHANGELOG.md` was corrected from `2026-04-22` to `2026-04-25` (the actual commit date of `ef6d8b3`).
- The `docs/v0.5.0/architecture.md` reference to `tests/unit/meta/no-claude-md.test.ts` (which never existed under that path) was corrected to `tests/unit/docs/AGENTS-md.test.ts`.

## 2. Harness layer

The harness layer continues to be agent-agnostic. v0.5.0 Phase 8 introduced the four Node ESM scripts under `scripts/hooks/`; v0.6.0 makes the MCP-side of the harness narrower:

- **MCP allowlist (new in v0.6.0).** When `gemma-code.mcpServerMode = "stdio"` is enabled, the server registers only tools listed in `gemma-code.mcpExposedTools`. Default: `["read_file", "list_directory", "grep_codebase"]` (read-only). Operators broaden by editing the setting; the server does not auto-expose write or shell tools.
- **MCP peer attribution (new in v0.6.0).** `ToolRegistry.execute` accepts an optional `source: 'local-agent' | 'sub-agent' | 'mcp'`. `McpServer.dispatch` passes `'mcp'`; `SubAgentManager.spawn` -> child loop passes `'sub-agent'`; the local agent passes `'local-agent'` (the default). `ConfirmationGate` reads `source` and rewrites the prompt: `"External MCP client wants to ..."` for MCP, `"The verification sub-agent wants to ..."` for sub-agents, default phrasing otherwise.

See [pen-test F-004](./review/penetration-test.md) for the original finding.

`src/tools/ToolCatalog.ts` continues to enumerate every tool. The discovery meta-tool `get_tool_schema` lives there.

### Permission-tier floor (new in v0.6.0)

`getPermissionTier()` now clamps `permissionOverrides` so any tool whose baseline tier is `CONFIRM` or `DANGEROUS` cannot be lowered to `AUTO_APPROVE`. A workspace `.vscode/settings.json` with `{"gemma-code.permissionOverrides": {"run_terminal": 0}}` is silently neutralized at the read side; the agent still prompts; a deduped warning fires once per `(toolName, override)` pair.

See [ADR-0007](../adr/0007-permission-tier-floor.md) for the rationale (closes Attack Path A's auto-approve leg) and [tests/integration/permission-overrides-clamp.test.ts](../../tests/integration/permission-overrides-clamp.test.ts) for the regression contract.

### Filesystem path-guard (new in v0.6.0)

Every filesystem tool handler routes path resolution through `pathGuard.resolveInsideWorkspace`. The lexical `resolveWorkspacePath` helper that previously coexisted in `filesystem.ts` is deleted. The guard is realpath-aware, with an ancestor-walk for non-existent leaves so writes through symlink-parented paths still resolve correctly.

See [ADR-0006](../adr/0006-unified-path-guard.md) (closes Attack Path A's symlink leg) and [tests/unit/tools/handlers/filesystem-symlink.test.ts](../../tests/unit/tools/handlers/filesystem-symlink.test.ts) for the regression contract.

### v0.5.0 tool-surface parameters

Unchanged. The new `dry_run`, `format`, `max_bytes`, `range_start/end`, `max_results/next_offset` parameters introduced in v0.5.0 phases 2 and 6 remain the canonical tool-surface ratchet. The error-message AST meta-test (`tests/unit/tools/errors.test.ts`) still locks every error path's `Usage:` hint behind a property test.

## 4. Cache stack

The cache stack is unchanged in shape but reduced in surface area. The `+--- Predictive layer ---+` block from v0.5.0's diagram is gone (see [ADR-0009](../adr/0009-predictive-cache-decision.md)).

```
+-----------------------------------------------------------------------+
|  In-process LRU (50 entries / 1 MB)        ToolOutputLru              |
|  - decoupled eviction policy via Evictor   src/storage/eviction/      |
|  - default LRU; LFU / ARC / W-TinyLFU /                              |
|    Clock pluggable via gemma-code.cacheEvictionStrategy              |
+-----------------------------------------------------------------------+
                          |
                          v
+-----------------------------------------------------------------------+
|  Persistent SQLite cache       ToolOutputCache                        |
|  <workspace>/.gemma-code/tool-output-cache.sqlite (chmod 0o600)       |
|  - keyed by (absolute_path, mtime_ms, size_bytes)                    |
|  - content_brotli BLOB (Brotli-compressed payload)                   |
|  - excerpt TEXT (first 4 KB; FTS5-indexed for keyword fallback)      |
|  - embedding BLOB (Float32; nomic-embed-text or heuristic)           |
|  - embedding_provenance TEXT ('ollama' | 'heuristic')                |
|  - accessed_at INTEGER NOT NULL DEFAULT 0    [v0.6.0: true LRU]      |
|  - capacity 500 entries; LRU eviction on insert                      |
+-----------------------------------------------------------------------+

+-----------------------------------------------------------------------+
|  WebResponseCache              src/tools/handlers/webCache.ts         |
|  <workspace>/.gemma-code/web-response-cache.sqlite (chmod 0o600)      |
|  - fronts web_search; TTL-based eviction                             |
+-----------------------------------------------------------------------+
```

### True LRU on `ToolOutputCache.prune()` (new in v0.6.0)

v0.5.0's `prune()` ordered by `stored_at ASC` (FIFO) despite the docstring claiming LRU. Phase 5 sub-task 5.5 added an `accessed_at` column with backfill from `stored_at`, made `lookup()` bump it on every cache hit (both LRU front and SQLite-row hit branches), and changed `_enforceCapacity()` to order by `accessed_at`. The hot-vs-cold regression test in [tests/unit/storage/ToolOutputCache.test.ts](../../tests/unit/storage/ToolOutputCache.test.ts) pins the new behavior. Migration idempotency is verified by [tests/integration/tool-output-cache-migration.test.ts](../../tests/integration/tool-output-cache-migration.test.ts) (4 cases including close+reopen).

### Per-provenance threshold elevation (new in v0.6.0)

`searchByEmbedding` applies a per-row threshold based on `embedding_provenance`. Heuristic-tagged rows must clear `0.95`; ollama-tagged rows (and legacy NULL, treated conservatively as the higher-quality tier) clear `0.85`. Two new settings -- `gemma-code.ollamaEmbeddingThreshold` (default 0.85) and `gemma-code.heuristicEmbeddingThreshold` (default 0.95) -- expose the dial without forcing a rebuild.

See [ADR-0010](../adr/0010-threshold-elevation-decision.md) for rationale and [tests/integration/heuristic-fallback.test.ts](../../tests/integration/heuristic-fallback.test.ts) for the three real tests that replaced the v0.5.0 `it.todo` placeholders.

### Predictive cache deletion (new in v0.6.0)

The `PredictiveCache` module, its tests, its bench, and the `gemma-code.predictiveCacheEnabled` setting are deleted. The opt-in ARIMA pre-warmer was never wired into `ToolOutputCache.lookup()` or any runtime; v0.6.0's "no new product surface" constraint made wiring it indefensible. See [ADR-0009](../adr/0009-predictive-cache-decision.md).

## 5. Memory subsystem

Memory layering, retrieval contract, and N-corroboration rule are unchanged from [ADR-0002](../adr/0002-memory-subsystem-layering.md). What changed in v0.6.0:

- `MemoryShared.types.ts` extracted to break the `MemoryStore <-> MemoryConsolidator` circular import (Phase 4).
- `MemoryConsolidator.consolidate` is wrapped in `GraphMemory.transaction()` (Phase 7 sub-task 7.3). A 10K-event stress run drops from tens of thousands of fsyncs to one transactional commit -- ~1.3 s wall time, locked in by [tests/integration/memory-consolidator-large.test.ts](../../tests/integration/memory-consolidator-large.test.ts).

## 6. Sub-agent isolation

Unchanged from [ADR-0004](../adr/0004-sub-agent-isolation-contract.md). What changed:

- `SubAgentSpawner` interface extracted to break the `SubAgentManager <-> SubAgentTool` circular import (Phase 4).
- MCP and sub-agent dispatches are now distinguishable in the confirmation prompt (Phase 1 sub-task 1.3); see Section 2.

## 7. Panel decomposition

`GemmaCodePanel.ts` decomposed from a 1,724-line god class into four modules:

- **`GemmaCodePanel.ts`** -- composition root (lifecycle + wiring graph). 935 lines.
- **`ChatController.ts`** -- chat flow (submitUserMessage, cancelInFlight, approveStep, plan detection, memory injection). 215 lines.
- **`ChatCommandHandlers.ts`** -- 12-command slash dispatcher. 518 lines.
- **`ChatWebviewHost.ts`** -- webview surface lifecycle (sidebar `WebviewView` + optional editor `WebviewPanel`). 119 lines.

`panels/webview/index.ts` decomposed at the source level into `scaffold.ts` (50 lines), `styles.ts` (689 lines), `bodyMarkup.ts` (72 lines), `runtime.ts` (796 lines). The original `index.ts` is a 12-line back-compat re-export shim.

The plan target was < 400 lines for `GemmaCodePanel.ts`; the achieved 935 is a partial deviation. The remaining bulk is constructor wiring + init factories that would require re-architecting the `OllamaClient` injection pattern to extract; tracked as v0.7.0 follow-up. 59 new unit tests landed across the three new modules with 86%-99% coverage per file.

See [ADR-0008](../adr/0008-panel-decomposition.md) for full rationale, and [docs/v0.6.0/development/history/2026-05_phase-6-panel-decomposition.md](./development/history/2026-05_phase-6-panel-decomposition.md) for the implementation log.

## 8. Module-boundary contract

`configs/dependency-cruiser.cjs` ships v0.6.0 with **zero `BASELINE-2026-04-25` annotations** and zero per-rule path exception lists. All four exceptions removed in Phase 4:

| Exception (v0.5.0) | Closure (v0.6.0) |
|---|---|
| `secretPaths` + `Compressor` lived under `tools/handlers/` despite being utilities | Moved to `src/utils/` |
| `EmbeddingClient` consumed `OllamaHttp` directly | Consumes the abstract `LLMClient` port; `GemmaRuntime.getOllamaClient()` is the composition root |
| Panels routed storage access directly | Routed through `messages.ts` (closed during Phase 6 panel decomposition) |
| `agents -> tools/handlers/subAgent` | Closed via `SubAgentSpawner` interface extraction |

`npm run deps:check` reports `0 errors, 0 cycle warnings, 121 modules / 432 dependencies` on the v0.6.0 main branch.

See [docs/v0.6.0/development/history/2026-04_phase-4-module-boundary-ratchet.md](./development/history/2026-04_phase-4-module-boundary-ratchet.md) for the implementation log.

## 9. Defense-in-depth ratchets (Phase 3 summary)

Closed in v0.6.0 Phase 3:

- `fetchWithSsrfGuard` enforces a 5 MB body cap on outbound HTTP responses (pen-test F-002).
- `npm audit` CI gate elevated from `--audit-level=high` to `--audit-level=moderate` for production deps. Non-blocking dev-dep `audit-ts-dev` job (Phase 7 sub-task 7.2) covers full dep graph with 30-day artifact uploads.
- Cache-probe fingerprint switched from MD5 to SHA-256 (pen-test F-005).
- ESLint rule blocks `innerHTML` string concatenation in webview runtime; only the DOMPurify-sanitised path is approved (pen-test F-006).
- Example webhook URLs in comparison docs obfuscated to `https://example.invalid/<redacted>` placeholders (pen-test F-011).

## 10. Test pipeline

Phase 2 made the test pipeline trustworthy. CI verifiably fails on test failures; the v0.5.0-era native-cleanup segfault during process teardown no longer masks the exit code. The 12 token-estimation tests in `tests/unit/chat/ContextCompactor.test.ts` are now property-based against the `tiktoken` cross-check helper (Phase 2; closes known-gaps 1.1).

Stryker mutation pass (Phase 7 sub-task 7.6) achieved 50.64% overall / 58.92% covered mutation score on a focused runner over `tests/unit/guardrails/**`, `tests/unit/tools/handlers/**`, and `tests/unit/utils/secretPaths.test.ts`. Survived mutants in `policy.ts` (static lookup table), `ActionClassifier.ts`, and `terminal.ts` (regex/string variants) are knowingly left in place; the next quarterly Stryker pass should re-evaluate.

Coverage CI gate now reads `coverage/coverage-summary.json` (Phase 7 sub-task 7.1): `.total.lines.pct >= 80`, `.total.branches.pct >= 75`. The lcov regex scrape is gone.

# Plan - Agent-State Motion Identity for the Desktop Shell

**Project**: Nexus AI Studio
**Version**: v1.17.0 (ships as the next 2.x semantic-release)
**Slug**: ui-motion-identity
**Filename**: v1.17.0-adoption-ui-motion-identity.md
**Plan Type**: Feature / Enhancement (adoption)
**Created**: 2026-07-23
**Seeded from**: [../comparisons/v1.17.0-comparison-ui-motion-identity-and-tokenizer.md](../comparisons/v1.17.0-comparison-ui-motion-identity-and-tokenizer.md)
**Goal**: Make the Nexus desktop shell feel unmistakably modern and pleasant by reverse-engineering all three effect libraries (thinking-orbs, border-beam, metal-fx) into an internal motion system with one job each - orbs express agent state, the beam expresses surface liveness, metal expresses a premium hero action - wired onto the existing Tailwind v4 design tokens, with no new frontend dependency, coordinated so only one motion competes per surface, and hardened for reduced-motion.

## Overview

This milestone operationalizes the (revised) adoption plan from the thinking-orbs + border-beam + metal-fx + gigatoken comparison. The comparison found that Nexus already ships a deliberate ambient identity (forced-dark, a cyan/blue glow layer, a signature gradient, an animated constellation background via `desktop/src/components/ConstellationBackground.tsx`, and four locked per-module accent colors in `desktop/src/styles/tokens.css`), but its *interaction* motion is thin: agent activity is signalled by ad-hoc loaders (`LocalModelStatus.tsx`, `LocalModelStatusDock.tsx`, panel spinners, `GenerationCanvas.tsx`), focus/streaming surfaces are mostly static, and premium actions rely on the gradient alone. The three libraries map cleanly onto those three thin layers.

Per the maintainer's decision, all three are adopted and reverse-engineered (no `npm install`), each given a single semantic job so a maximalist look stays coherent rather than noisy: **orbs = agent state** (A1, flagship), **beam = surface liveness** (A2), **metal = hero action** (A3). Two calibration decisions are locked in: metal is used on hero controls only (send button, primary Generate, New session), and the ambient glow/constellation **recedes when a surface has an active effect** so motion never stacks. A cross-cutting foundation-and-coordination item (A4) provides the shared motion tokens, a centralized `prefers-reduced-motion` mechanism, the recede-when-active primitive, and the final one-motion-per-element + battery/perf audit.

Delivery stays entirely within Nexus's existing frontend stack: the Tauri 2.x + React 19 + Vite + Tailwind v4 desktop shell (`desktop/src/`), its design tokens (`desktop/src/styles/tokens.css`, `globals.css`), and its component tree (`desktop/src/components/`). No architecture is imported: the three effect libraries are not added as dependencies (N1), their non-Nexus palettes (ocean/sunset/gold/silver/chromatic) are not used (N3), metal-fx is confined to hero controls rather than a blanket treatment (N2), and gigatoken is not adopted at all (N4/N5: Python-only against a JS token path, per-request rather than bulk workload, incomplete Windows testing against a Windows-first product with an OS-parity principle). Success looks like: a single on-brand motion vocabulary expresses agent activity across coding, chat, image, and video; the input composer, active-model dock, and generation canvas feel alive on focus/streaming/rendering; the send, Generate, and New-session controls get a premium tactile ring; the ambient glow gracefully steps back on active surfaces; and every motion degrades cleanly under `prefers-reduced-motion`.

This is a shell-only cycle placed as a standalone v1.17.0 because v1.15 (in flight: installer + studio-chat) and v1.16 (planned: serving gateway + OCR) are committed to other themes.

## Phase 1: Motion Foundation (A4-foundation)

**Goal**: Provide the shared primitives every effect depends on - motion tokens, a centralized `prefers-reduced-motion` mechanism, and a recede-when-active primitive that lets the ambient glow step back on active surfaces - so no effect ships uncoordinated or inaccessible.
**Prerequisites**: None. Ships first because it unblocks Phases 2-4.
**Stability Gate**: Motion tokens (durations, easings, state-accent aliases mapped to the locked accents/gradient) exist in `desktop/src/styles/tokens.css` and resolve via Tailwind v4 `@theme inline`; a single `useReducedMotion` hook + a CSS media block centralize reduced-motion, and the existing motion surfaces (constellation, generation canvas, floating logo) are refactored onto it with no change to their current reduced-motion outcome; a recede-when-active primitive (a shared state/context + a CSS affordance) exists that a surface can use to signal "I have an active effect, dim the ambient glow near me"; tests cover the hook and the token presence.
**Recommended model**: Mid tier, medium effort - claude-sonnet-5 (medium). Rationale: low-novelty foundation/token work over an existing layer; value is in centralization and coordination, not invention. Re-confirm against the then-current model set at implementation.

### Sub-tasks

#### 1.1 - Shared motion tokens

**Objective**: Centralize motion values as design tokens A1-A3 consume.

**Prompt**:
> Extend `desktop/src/styles/tokens.css` with a motion-token group mirroring the existing token style (documented, grouped, consumed via Tailwind v4 `@theme inline`): durations (fast/base/slow), standard easings, and state-accent aliases that map to the existing `--accent-coding`, `--accent-chatbot`, `--accent-image`, `--accent-video`, and `--grad-signature`. Do NOT introduce new palettes. Keep everything additive; nothing in the existing token set changes. Acceptance: the motion tokens exist, resolve in the shell through the Tailwind theme, and reuse the locked accent/gradient tokens.

---

#### 1.2 - Centralized reduced-motion mechanism

**Objective**: One reduced-motion source of truth for CSS and JS-driven motion.

**Prompt**:
> Centralize `prefers-reduced-motion` handling. Add a `useReducedMotion` hook (subscribes to `matchMedia`, SSR/jsdom-safe) and a single CSS media block in `desktop/src/styles/globals.css`. Refactor the existing per-surface checks in `desktop/src/components/constellation.ts`, `ConstellationBackground.tsx`, `GenerationCanvas.tsx`, and `FloatingLogo.tsx` to use the shared mechanism WITHOUT changing their current reduced-motion outcome (animation fully paused/reduced, not merely slowed). Acceptance: reduced-motion is centralized; every existing animated surface halts under `prefers-reduced-motion: reduce`; prior behavior is preserved where it was already correct.

---

#### 1.3 - Recede-when-active primitive

**Objective**: Let a surface with an active effect dim the ambient glow near it, so motion never stacks.

**Prompt**:
> Implement a lightweight recede-when-active primitive: a shared React context (or a small store) that tracks which surface currently has an active orb/beam/metal effect, plus a CSS affordance the ambient layer (`ConstellationBackground` / radial-glow) reads to reduce its intensity around or during an active-surface effect. Keep it declarative (a surface wraps itself or sets a flag when it activates an effect) and cheap (no per-frame work in the ambient layer beyond an opacity transition). Do not wire every surface yet - that is Phase 5; here, deliver the primitive plus one reference integration to prove it. Acceptance: when the reference surface marks itself active, the ambient glow measurably recedes and restores on deactivate, with a smooth transition and no layout shift.

---

#### 1.4 - Testing and Stabilization

**Objective**: Cover the foundation; wire CI.

**Prompt**:
> Add tests: a unit test for `useReducedMotion` (correct value + updates on `matchMedia` change via the shell's jsdom setup); a test that a representative animated component halts under reduced-motion through the shared mechanism; a test that the motion tokens resolve; a test that the recede-when-active primitive toggles the ambient intensity flag on activate/deactivate. Run `npm run test:shell` + `npm run lint --workspace @nexus/desktop`; iterate to green. Update CI to cover `desktop/src/styles` + the touched components (path filters, concurrency cancel-in-progress, dependency caching). Do not proceed to Phase 2 until stable. After tests pass, run `/generate-session-history` for Phase 1.

## Phase 2: Agent-State Orbs (A1, flagship)

**Goal**: A single internal component expresses agent activity as on-brand motion, mapped to Nexus's pillars and activities, replacing today's ad-hoc per-surface loaders.
**Prerequisites**: Phase 1 (motion tokens + reduced-motion + recede primitive).
**Stability Gate**: An internal agent-state motion component renders the mapped states, at a larger hero size and a small inline size, using only Nexus accent/gradient tokens; it honors reduced-motion (static fallback) and pauses offscreen; the primary agent surfaces (coding activity, chat streaming, one media-generation surface, and the model-status dock) render it in place of their prior ad-hoc loader; unit tests cover state selection, sizing, and reduced-motion.
**Recommended model**: Mid-strong tier, high effort - claude-sonnet-5 (high). Rationale: design-sensitive frontend motion (a distinctive, non-generic look matched to the locked identity) with a cross-cutting state->activity mapping; moderate complexity, no security surface. Re-confirm against the then-current model set at implementation.

**Objective**: Fix the vocabulary of states and how they map to Nexus's pillars and agent activities.

**Prompt**:

#### 2.3 - Adopt it on the primary agent surfaces

**Objective**: Replace ad-hoc loaders on the main surfaces with the unified component.

**Prompt**:

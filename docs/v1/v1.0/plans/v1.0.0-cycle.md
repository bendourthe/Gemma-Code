# Plan - Nexus v1.0.0 Cycle (Desktop-App Pivot)

**Project**: Nexus (formerly Gemma Code)
**Version**: v1.0.0
**Slug**: v1.0.0-cycle
**Plan Type**: Hybrid - Feature/Enhancement (extending the Gemma Code engine) + Initial-build (three greenfield modules: Chatbot Explorer, Image Studio, Video Lab)
**Created**: 2026-05-17
**Goal**: Pivot the repository from a single VS Code agentic-coding extension into a native local-first desktop application with four generative pillars (Agentic AI Coding, Local Chatbot Explorer, Image Studio, Video Lab), an installer that carries CUDA/Python/Node/Ollama/models end-to-end, a `nexus skills sync` upstream from DevAI-Hub, and live GPU/VRAM telemetry - all running on a single laptop GPU and shippable as Nexus 1.0.0.

## Overview

Nexus v1.0.0 is the largest cycle this repository has run. It rebrands Gemma Code, extracts its existing engine (AgentLoop, ToolRegistry, four-layer memory, plan mode, skill catalog, MCP, trace dashboard, curator, hardware tiers) into a module behind a clean boundary, wraps that module in a Tauri-based native desktop shell, and adds three greenfield pillars: a folder-organized chat explorer, an Image Studio (txt2img / img2img / inpaint / outpaint / LoRA / ControlNet), and a Video Lab (LTX-Video / SVD / CogVideoX). A shared core (ModelRegistry, MemoryHub, TelemetryBus, SkillCatalog, SettingsStore, GpuScheduler) sits underneath the four modules. A new single-binary installer carries CUDA, a Python venv with the diffusion stack, Node, Ollama, the top recommended models, and a frozen DevAI-Hub skill baseline so a fresh laptop is fully operational after one wizard run. A `nexus skills sync` command pulls future DevAI-Hub updates without manual copy-paste.

Phase sequencing follows the AGENTS.md MCP Registry Policy decision tree (reverse-engineer-first). Every ComfyUI capability adopted is built as a Nexus-native module, not vendored - ComfyUI's GPL-3.0 license combined with the project's "originality over wrappers" principle makes vendoring a non-starter. DevAI-Hub is the one explicit upstream link, justified by being the project lead's own work and intentionally maintained as a feeder catalog.

Three constraints are non-negotiable across every phase: (1) **single-GPU ceiling** - everything must work on an RTX 3070-4090-class consumer GPU; (2) **local-first** - no outbound calls without explicit opt-in; (3) **installer carries the burden** - when the wizard finishes, every pillar runs on first launch with no `pip install` / `npm install` / `nvidia-smi` scavenger hunt.

This plan ingests 4 load-bearing items carried forward from `docs/archive/versions/v0/v0.9.0/known-gaps.md`: `[v0.9.0:10.N.A]` ModelPinRegistry wiring (folded into Phase 5 ModelRegistry), `[v0.9.0:10.N.Q]` IdleTimeScheduler wiring (folded into Phase 3 Coding module extraction), `[v0.9.0:10.N.R]` lazy-import utility split (folded into Phase 2 core extraction), and `[v0.9.0:10.N.T]` per-file coverage backfill of panel files (superseded by the Tauri shell rewrite in Phase 1). The remaining v0.9.0 P3 items are all operator-driven (live Ollama benches, synthetic PRs) and roll forward into `docs/versions/v1/v1.0.0/known-gaps.md` once the cycle opens.

## Phase 1: Shell foundation - Tauri + design tokens + dashboard skeleton

**Goal**: Stand up the `nexus-shell` Tauri app with the sidebar + 2x2 dashboard cards + Local Model Status placeholder, and prove the IPC contract to a Node sidecar.
**Prerequisites**: None (greenfield).
**Stability Gate**: `npm run dev:shell` opens a native window on Windows / macOS / Linux that renders the mockup layout and roundtrips a `ping` IPC call to the Node sidecar.

See [phase-01-shell-foundation.md](phase-01-shell-foundation.md) for the full sub-task breakdown and executable prompts.

## Phase 2: Rebrand sweep + shared-core extraction

**Goal**: Rename all forward-facing identifiers (settings keys, storage paths, code namespaces, CLI binaries) with a one-cycle compat shim; carve the existing `src/` into `core/` + `modules/coding/`.
**Prerequisites**: Phase 1 (shell needs the new namespace to import from).
**Stability Gate**: All 1932 historical `Gemma-Code` mentions are either renamed or explicitly preserved in `docs/v0.X.0/development/history/`; `npm test` is green; `~/.gemma-code/` -> `~/.nexus/` migration runs idempotently; the legacy `gemma-code.*` settings keys still resolve through the compat shim with a single-line deprecation log.

See [phase-02-rebrand-and-core-extraction.md](phase-02-rebrand-and-core-extraction.md).

## Phase 3: Agentic AI Coding module + multi-LLM + thin VS Code adapter

**Goal**: The engine runs as the desktop Coding module via shell IPC, supports Llama 3 / Qwen 2.5 / Gemma 4 as backends, and the VS Code extension is reduced to a thin adapter that proxies to the desktop daemon.
**Prerequisites**: Phase 2.
**Stability Gate**: From the dashboard, "Open Code Assistant" launches the Coding module; an end-to-end "fix the failing test in `tests/unit/<file>.test.ts`" task succeeds against each of the three model backends; the legacy `gemma-code` VS Code extension still works against the new daemon. `[v0.9.0:10.N.Q]` IdleTimeScheduler wiring closes here.

See [phase-03-coding-module.md](phase-03-coding-module.md).

## Cross-cutting constraints (apply to every phase)

1. **Local-first**. No outbound network call without explicit user opt-in. Installer-time model downloads and `nexus skills sync` are the two opt-in exceptions; both are user-initiated.
2. **Single-GPU ceiling**. Every benchmark and acceptance test runs on an RTX 4070-class machine (12 GB VRAM) as the baseline tier. RTX 3070 (8 GB) is the lower tier with reduced defaults; RTX 4090 (24 GB) is the upper tier with raised defaults.
3. **Originality over wrappers**. Per AGENTS.md MCP Registry Policy: local-only > LLM-native skill > reverse-engineered internal module > trusted-vendor wrapper > drop. Every external pattern adopted (ComfyUI's smart offloading, model-paths-as-config, latent previews, workflow-in-PNG) is reverse-engineered into a Nexus-native module - we do not vendor ComfyUI (GPL-3.0).
4. **DevAI-Hub is the one explicit upstream**. All other external dependencies are evaluated against the decision tree.
5. **Test discipline**. Each phase ends with a Testing and Stabilization sub-task that runs unit + integration + (where relevant) golden-task + bench gates. No phase advances until its gate is green.
6. **Atomic commits per sub-task** unless the user explicitly requests a bundled commit (matches v0.9.0 Phases 2-6 known-gap pattern).
7. **Coverage gate**. `lines >= 80`, `functions >= 80` (per the v0.9.0 Phase 7 hardening). New modules ship at >= 80 from day one.
8. **No telemetry**. No usage analytics, no crash phone-home, no remote logging. Local-only trace dashboard with secret-path redaction.
9. **Compat shims expire after one cycle**. The `gemma-code.*` settings shim, `~/.gemma-code/` migration shim, and `gemma-check` -> `nexus-check` CLI alias all log a deprecation warning in v1.0.0 and are removed in v1.1.0.

## Items explicitly NOT in scope for v1.0.0

- **Audio generation pillar**. Deferred to v1.1.0+ (Stable Audio / ACE Step are mature but a fifth pillar bloats the v1.0.0 surface).
- **3D generation pillar**. Deferred to v1.2.0+ (Hunyuan3D 2.0 is interesting but requires a separate viewer and a different VRAM profile).
- **Node-graph workflow editor**. Deferred to v1.1.0 as Image Studio's "Advanced" tab; forms-driven UX is the v1.0.0 default per the ComfyUI comparison.
- **Public custom-node / custom-skill marketplace**. Out of scope. DevAI-Hub is the sole upstream; users can author local skills.
- **Multi-user / team / cloud-sync**. Out of scope. Nexus is a single-user laptop app.
- **AnimateDiff** (deprecated per the ComfyUI comparison), **Mochi**, **HunyuanVideo** (>24 GB VRAM requirements push beyond the single-GPU ceiling).
- **Civitai / HuggingFace browser integration**. The Settings model browser uses a curated Nexus registry; ad-hoc URLs are paste-and-verify, not browse-from-app.

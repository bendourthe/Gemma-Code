# Plan - Nexus v1.1.0 Cycle

**Project**: Nexus
**Version**: v1.1.0
**Slug**: v1.1.0-cycle
**Plan Type**: Hybrid -- Feature/Enhancement (carryforward closures + Image/Memory/Installer upgrades) + Initial-build (Nexus VS Code extension, OS-aware installer, hardware-aware model picker)
**Created**: 2026-05-18
**Goal**: Close the v1.0.0 architectural carryforward cluster (shared-core build, sidecar IPC widening, storage-path rename), ship the **Nexus VS Code extension as a desktop add-on**, deliver the **cross-OS installer** with hardware detection and hardware-aware multi-model picker, and absorb the two new external lenses -- **agentmemory** (hybrid memory retrieval, 12-hook lifecycle, session replay) and **NVIDIA SANA** (default image model upgrade, 4K, video tier).

---

## Overview

v1.1.0 is the **stabilization-plus-expansion** cycle that follows v1.0.0's pivot. The v1.0.0 cycle landed all 11 phases and shipped a working four-pillar desktop app, but it deliberately deferred 46 architectural items into a "shared-core build" cluster (see [docs/versions/v1/v1.0.0/known-gaps.md](../../v1.0/known-gaps.md) Section 4.2). v1.1.0 closes that cluster as Phase 1 and then layers on five user-visible upgrades on top:

1. **Nexus VS Code extension as a desktop add-on** -- a multi-model successor to Gemma Code, replacing the legacy in-process engine with a thin adapter that proxies to the desktop daemon. Plan mode, auto mode, memory, skills, sub-agents, sessions, slash commands -- all served by the daemon, all using local models, multiple selectable (not just Gemma 4).
2. **OS-aware cross-platform installer** -- the existing Windows-first wizard becomes the **canonical cross-platform installer**, auto-detecting host OS (Windows / macOS / Linux), provisioning the right tools per platform (CUDA on Win/Linux NVIDIA, Metal Performance Shaders on Apple Silicon, ROCm-aware fallback on Linux AMD), and offering the Nexus VS Code extension as an opt-in add-on.
3. **Hardware-aware recommended-models picker** -- the v1.0.0 picker becomes a **typed catalog UI** (text / image / video / audio tabs, latest-top recommended auto-ticked, per-model metadata: size on disk, hardware compatibility, release date, censored/uncensored, in-context / out-context windows, multi-modality, uncensored flag), with **free-disk-space awareness** and a **10 GB OS reserve** that disables model selection that would breach the floor.
4. **Memory upgrade lens (agentmemory)** -- hybrid retrieval (BM25 + dense + graph via RRF), local embeddings (`all-MiniLM-L6-v2` bundled in installer), Ebbinghaus decay, 12-hook lifecycle bus, session replay timeline, `/recall` / `/remember` / `/forget` slash commands, memory provenance, opt-in contradiction resolver.
5. **Image / Video upgrade lens (NVIDIA SANA)** -- SANA-1.6B as new default 1024px image model (~2x faster than SDXL Turbo, Apache-2.0 weights), Sana-Sprint as "Fast Preview" speed tier (0.3 s on RTX 4090), SANA 2K/4K behind `DiffusionTier` gating, SANA-Video 2B as the "Fast 720p" video tier, SANA-ControlNet, Flow-DPM-Solver sampler.

The cycle ingests **65 carryforward items** from `docs/versions/v1/v1.0.0/known-gaps.md` Section 4.2 (46 architectural) and Section 4.3 (3 deferred-to-v1.1.0), plus **12 operator-action carryforwards** that remain operator-driven (`operator-actions.md` OA-01 through OA-12; some defer to v1.0.1+), plus **all 10 P0/P1 + 2 P2 agentmemory items** and **all 8 P0/P1 + 2 P2 SANA items** from the new comparisons. The decision tree from [AGENTS.md](../../../../AGENTS.md) drives sequencing: reverse-engineerable items land first; nothing new requires an external runtime that survives past install time.

Three constraints stay non-negotiable: (1) **single-GPU ceiling**, (2) **local-first** (no outbound runtime calls without opt-in), (3) **installer carries the burden**. v1.1.0 adds a fourth: (4) **OS parity** -- every claim that works on Windows also works on macOS (Intel + Apple Silicon) and Linux (x86_64), or is explicitly documented in the per-platform notes.

## Phase 14 -- Cross-OS installer (Windows + macOS + Linux) with hardware + disk-aware model picker

**Goal**: Turn the v1.0.0 Windows-only installer into the canonical **cross-platform installer**. Auto-detect host OS, provision platform-correct tooling (CUDA on Windows + Linux-NVIDIA, Metal Performance Shaders on Apple Silicon, ROCm-aware fallback on Linux-AMD, CPU-only fallback elsewhere), offer the Nexus VS Code extension as an opt-in add-on, and deliver the **hardware-aware multi-model picker** with **free-disk-space awareness**.

**Prerequisites**: Phase 11 (Nexus VS Code extension exists to be offered), Phase 12 + 13 (SANA weights are in the catalog).

**Stability Gate (macOS Apple Silicon)**: Fresh macOS Sequoia VM, no Homebrew tooling installed; the installer detects "macOS 14.x arm64 + M2 Pro", switches to Metal Performance Shaders provisioning, downloads the same models (no CUDA libraries), installs Ollama for macOS via the official binary, completes wizard, dashboard renders.

**Stability Gate (Linux)**: Fresh Ubuntu 24.04 VM with an NVIDIA RTX 3060; installer detects, provisions CUDA, downloads models, installs Ollama via the official Linux script, completes wizard, dashboard renders. Same VM with an AMD RX 7600 instead detects no NVIDIA driver, offers the ROCm-aware path (or CPU-only fallback if ROCm not present), provisions accordingly.

**Stability Gate (disk-aware)**: With 90 GB free, the user ticks four models totalling 60 GB; the picker disables every checkbox that would push total selection beyond `90 - 10 = 80 GB`. The "Storage" footer always shows `free / total` and a per-selection delta.

**Stability Gate (model metadata)**: Each model card shows: name, type (Text / Image / Video / Audio), size on disk, hardware compatibility check ("Compatible" / "Requires more VRAM" / "Requires more RAM"), release date, in-context / out-context windows (for text models), multimodality flag, censored / uncensored flag. The latest-top recommended models are auto-ticked per type.

## Risks

| Risk | Mitigation |
|---|---|
| Shared-core build introduces import-resolution regressions across 517 test files | Phase 1's first commit is the build infra only; the rename cascades land in subsequent commits behind the same green CI |
| Default image model swap (SDXL Turbo -> SANA-1.6B) surprises existing users | Release notes carry side-by-side samples; SDXL Turbo stays in the catalog as an opt-in alternative |
| Local embedder weights (~80 MB) increase installer payload | Mitigated by the cross-OS installer's selective download UX; the weights ship in the "Recommended" preset only |
| macOS / Linux installer payloads are larger than Windows (no compression vs NSIS) | Document per-OS payload size in installer-architecture-v1.1.0.md |
| `nunchaku` / SVDQuant license (S4) | Phase 12 sub-task verifies the license is Apache-2.0 or MIT before adoption; if not, S4 drops to v1.2.0 |
| Marketplace re-publish of `nexus-coding` could break user keybindings | Compat shim in Phase 1 maps `gemma-code.*` keybindings to `nexus.coding.*` with a single-line deprecation log; transition note in the legacy listing |
| ROCm support on Linux AMD is more variable than CUDA | Installer offers ROCm provisioning where the driver permits; falls back to CPU-only with a clear surface |
| Hybrid retrieval cost on first session | The BM25 index is warm-built on first launch (background worker); cold-first-query falls back to substring retrieval gracefully and warm-rebuilds within 5 s on a 10k-entry corpus |
| Disk-reserve heuristic (10 GB) is too aggressive on small SSDs | Make the reserve configurable via `nexus.installer.diskReserveGB` (default 10); document the default in the installer's "Storage" page |

## Definition of Done

- All 15 phases land green on Windows + macOS + Linux CI
- Shared-core build is the canonical import path for sidecar code
- Sidecar IPC is channel-based for streaming events (no polling loops in production paths)
- `nexus-coding` is on the VS Code Marketplace
- The Nexus VS Code extension boots against the desktop daemon, exposes plan / auto / memory / skills / sub-agents / sessions / slash commands, and lets the user pick any installed local model
- The cross-OS installer wizard finishes on a clean Windows 11 VM, a clean macOS Sequoia VM, and a clean Ubuntu 24.04 VM, in each case leaving the user with a working four-pillar Nexus app
- The recommended-models picker greys out additions that would breach the 10 GB OS reserve, shows hardware-compatibility per model, and auto-ticks the latest-top per type
- SANA-1.6B is the new default 1024px image model; Sana-Sprint is the "Fast Preview"; SANA-Video 2B is in the Video Lab catalog; the `runtimes/diffusion/pipelines/sana*.py` modules are exercised by the Phase 12 + 13 stability tests
- Memory retrieval is hybrid (BM25 + dense + graph via RRF); the local embedder is bundled; `/recall`, `/remember`, `/forget`, `nexus memory audit`, `nexus memory export` are wired
- All v1.0.0 carryforward items in the Section 4.2 cluster are closed (or explicitly re-deferred with a recorded reason)
- v1.1.0 release notes + CHANGELOG + RTM smoke + signing / notarization complete; the v1.1.0 known-gaps file is finalized at cycle close

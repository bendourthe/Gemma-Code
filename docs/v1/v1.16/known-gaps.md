Note (Phase 1): the plan's sub-task 1.3 says the OpenAI routes are "backed by ... `OllamaClient.ts`, `LmStudioClient.ts`, and any `localAdapters` runtime". They are backed by those *runtimes*, reached through the new vscode-free `ServingAdapter` seam (`desktop/sidecar/src/serving/adapters.ts`) rather than by importing those two modules - see LSO.P1.B for why. The seam reads the same `nexus.llm.localAdapters` manifest shape and enforces the same loopback rule, so a user-registered runtime (including the MLX server the Phase 5.1 docs will describe) is servable with no further code.

Note (Phase 1): the loopback predicate was extracted from `LocalAdapterRegistry.ts` into `modules/coding/llm/loopback.ts`, which the registry now re-exports. This keeps ONE definition shared by the outbound adapter check and the inbound bind check - a rule that drifted between "endpoints we will call" and "addresses we will bind" is how a local-first product would accidentally expose a model server. `tests/unit/llm/loopback.test.ts` asserts the re-export is the same function object.

Note (Phase 1): `shell-build.yml`'s path filter gained `modules/**` because the sidecar bundle now imports from that tree. Cost stays bounded - PRs still run ubuntu-only and the macOS (10x) + Windows (2x) matrix is still gated to push-to-main.

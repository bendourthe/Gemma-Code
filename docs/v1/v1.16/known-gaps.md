The seam reads the same `nexus.llm.localAdapters` manifest shape and enforces the same loopback rule, so a user-registered runtime (including the MLX server the Phase 5.1 docs will describe) is servable with no further code.

This keeps ONE definition shared by the outbound adapter check and the inbound bind check - a rule that drifted between "endpoints we will call" and "addresses we will bind" is how a local-first product would accidentally expose a model server. `tests/unit/llm/loopback.test.ts` asserts the re-export is the same function object.

Note (Phase 2): a bug introduced by Phase 1 was found and fixed here (**LSO.P2.X**, closed same-phase, listed for the record rather than as an open item). `desktop/tests/servingRuntime.test.ts` used `Parameters<typeof createServingRuntime>[0]["models"]`, which does not typecheck because that parameter is optional (`| undefined`). The desktop `npm run typecheck` script therefore failed on commit `67257df`, and `shell-build.yml` runs that script - so Phase 1's CI would have gone red. The Phase 1 report claimed the typecheck gate was clean; that check had been run before the test file existed, and afterwards only vitest (which does not typecheck) and eslint were re-run. Fixed with `NonNullable<Parameters<...>[0]>["models"]`. Process lesson: `tsc --noEmit` must be re-run after adding test files, not only after touching source.

Note (Phase 2): CI needed no change. `shell-build.yml` already watches `desktop/**`, `core/**`, and `modules/**` (the last added in Phase 1), which covers every surface this phase touched on the desktop side, and `ci.yml` runs unfiltered so it covers the `core/`, `modules/`, and `src/` changes. Concurrency cancel-in-progress, npm caching, and the push-to-main gating of the expensive OS matrix were all already in place. Verified rather than assumed.

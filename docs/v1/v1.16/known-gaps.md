Note (Phase 3): the plan's 3.1 asked for a recorded portability decision. **Both** models ship rather than one: **RapidOCR PP-OCRv4** (Apache-2.0, ONNX, CPU, ~20 MB, `requiredVramGB: 0`) is the portable tier that makes document parsing work on every supported OS, and **Unlimited-OCR 3B** (MIT, CUDA-only per its model card, `trust_remote_code`, `requiredVramGB: 12`) is the quality tier for capable NVIDIA hosts. Surya 2 was evaluated and rejected on licensing: GPL-3.0 is copyleft, whereas the shipped pair is Apache-2.0 + MIT. This satisfies the OS-parity principle in-cycle instead of deferring a portable fallback, which is what the plan offered as the minimum.

Note (Phase 3): supply-chain controls for the `trust_remote_code` model are three-layered and enforced, not advisory. A new `source.revision` field pins a 40-hex commit sha; `validateSpec` (TS) and `load_weights_manifest` (Python) BOTH refuse a `trustRemoteCode` entry that lacks one, and both reject a branch or tag name since those are mutable. `model_preflight` probes the same pinned commit the download targets, so a reachability check cannot pass against `main` while the pinned commit is gated. The model loads with `local_files_only=True` inside the sandboxed Python runtime only - never in the Node sidecar or the renderer.

Note (Phase 3): `tests/python/` gained its first CI job ever. The ~135 diffusion-runtime tests from v1.0.0 Phase 6 had never run in CI (a grep across all workflows returned nothing); the new `test-python-runtimes` job now covers both runtimes on a bare runner with no GPU, no weights, and no torch - which also keeps the "engine unavailable on this host" path continuously tested.

Note (Phase 4): a bug introduced during this phase was found and fixed before commit (**LSO.P4.X**, closed same-phase, recorded for the process lesson). The first version of the headless guard wrapper enforced permission tiers unconditionally. Because every write/terminal tool on that surface is CONFIRM or DANGEROUS and no host supplies a `confirm` callback, that refused essentially every agent action - 10 existing tests failed, and in production it would have disabled the headless coding agent entirely. Redesigned so the secret-path check stays unconditional (it refuses nothing legitimate) while tier enforcement waits for a host callback. Lesson: when adding a gate to a surface that never had one, check what the gate's default verdict does to existing traffic before assuming fail-closed is the safe choice.

Note (Phase 4): the canonical permission-tier data moved to a new vscode-free `modules/coding/guardrails/permissionTierMap.ts`, which `PermissionTiers.ts` re-exports. `PermissionTiers.ts` reaches `vscode` transitively (via `utils/logger` and `src/tools/handlers/terminal`), so the headless surface could not import it - and keeping a second copy of the tier map is exactly how two surfaces drift apart. This is the same class of extraction as the Phase 1 loopback predicate, and it was caught the same way: by checking the transitive import graph before wiring, not after the bundle broke. `scripts/generate-tool-permission-table.mjs` now parses the new file; `security:check` verifies the generated SSOT still matches. A hand-transcription error in the extracted map (three tiers wrong) was caught by diffing the parsed maps programmatically rather than by eye.

Note (Phase 4): `parse_document` had to be made TRIMMABLE. `MAX_TOOL_COUNT` is 15 and built-ins were previously never trimmed, so adding a 25th catalog entry pushed the untrimmable core to 16 and broke the prompt-budget cap in two e2e tests. It now trims after MCP tools and BEFORE `codegraph_*`, on the reasoning that losing symbol navigation hurts the default coding path more than losing document OCR does.

Note (Phase 3): two pre-existing installer tests (`test_ollama_installer.py::TestExtractTarZst`) fail locally on a missing `zstandard` module. Verified pre-existing by stashing this phase's changes and re-running. CI installs it via `uv sync`, so this is a local-environment artifact, not a regression.

Note (Phase 2): CI needed no change. `shell-build.yml` already watches `desktop/**`, `core/**`, and `modules/**` (the last added in Phase 1), which covers every surface this phase touched on the desktop side, and `ci.yml` runs unfiltered so it covers the `core/`, `modules/`, and `src/` changes.

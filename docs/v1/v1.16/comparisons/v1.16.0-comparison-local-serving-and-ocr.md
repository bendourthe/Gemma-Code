## Section 1: Executive Summary

This report compares **Nexus** (this repo: a local-first desktop AI Studio, "Your Local AI Studio. Four Pillars, One Desktop, Zero Tokens Billed", formerly Gemma Code) against two external sources that both sit squarely inside Nexus's local-first thesis:

1. **Nativ** (`Blaizzy/nativ`), a native macOS app that runs, serves, monitors, and connects MLX models locally, exposing OpenAI- and Anthropic-compatible loopback endpoints so external coding tools (Claude Code, Codex, Cursor) can consume its local models.
2. **Baidu Unlimited-OCR**, a 3B open-weights (MIT) vision-language OCR model for one-shot long-horizon document/PDF parsing, "aiming to push Deepseek-OCR one step further".

The two sources probe two different Nexus gaps. Nativ probes an **architectural** gap: Nexus is a local-model *consumer* (its `LocalAdapterRegistry` speaks Ollama/OpenAI protocols as a client, and its MCP server exposes read-only tools) but it is not a local-model *provider* -- it has no `/v1/chat/completions` or `/v1/messages` gateway that would let the user's other agent tools reuse Nexus's already-downloaded local models. Unlimited-OCR probes a **capability** gap: Nexus ships open models for image generation (SANA), video (SANA-Video / Wan), ASR (faster-whisper), and TTS (kokoro), but has no document-OCR / PDF-parsing capability at all.

The analysis surfaces **6 adoption candidates** and **5 explicitly-rejected items**. The flagship candidate (A1) is a loopback OpenAI/Anthropic-compatible serving gateway: it is the exact inverse of the v1.6.0 `localAdapters` client, it is on-brand ("Zero Tokens Billed" extended to the user's whole toolchain), and it is local-only by construction (loopback-bound, zero-outbound). The OCR candidate (A5) adds a genuinely new pillar-adjacent capability using the same catalog + Python-sidecar spine that already runs SANA/Whisper/Kokoro, but it carries real supply-chain and portability constraints (CUDA-first, `trust_remote_code=True`) that gate *how* it ships.

**Overall recommendation: selectively adopt.** Both sources are MIT, reputable, and zero-outbound at their core, so adopting their *patterns* introduces essentially no new trust surface. Adopt the serving gateway and the OCR capability as reverse-engineered internal builds on Nexus's existing spine; adopt the metrics and library-UX cues as extensions of in-flight work; keep MLX support as an opt-in loopback `localAdapters` target (documented, not built). Do not adopt nativ's Swift/SwiftUI macOS-only shell, its macOS-26 / Apple-Silicon-only floor, a bundled first-class MLX runtime, or Unlimited-OCR as a default/hard dependency.

## Section 3: Capability and Architecture Comparison

### 3a. Nexus vs. Nativ (same domain: local model runner)

| Aspect | Nexus (current) | Nativ (external) | Delta |

**Key contrast:** Nexus and nativ are the same *kind* of artifact (a local-model runner with an embedded Python server), pointed in opposite directions. Nexus's v1.6.0 work made it a flexible local-model *client* (register any loopback runtime via a manifest). Nativ's defining feature is the *server* side of that same coin (front your local models behind standard OpenAI/Anthropic APIs). Building that inverse is the single highest-value idea in this comparison.

## Section 4: Gap Analysis

### 4a. Present in External, Missing in Nexus (adoption candidates)

**From Nativ (architecture / serving):**
- **Loopback OpenAI/Anthropic-compatible serving gateway (A1, flagship).** Let external coding tools point at Nexus's already-downloaded local models via `/v1/chat/completions`, `/v1/messages`, `/v1/models`. Nexus has the client (`localAdapters`) and a tools-only MCP server, but no inference gateway.
- **Per-model performance analytics in the UI (A2).** Tokens/sec, time-to-first-token, memory footprint, cache stats per model, surfaced in the Traces panel.
- **MLX reachable as a first-class documented option (A3).** Not a new runtime -- mlx-vlm's server (or LM Studio's MLX mode, or nativ itself) is already consumable today by registering a loopback `localAdapters` manifest with `protocol: "openai"`. The gap is documentation + a macOS Apple-Silicon smoke path, not code.
- **Model-library discovery/management + quick-switch cues (A4).** Extends the v1.15 Phase 4 Models page and a possible quick model-switch affordance.

**From Unlimited-OCR (capability):**
- **Local document-OCR / PDF-parsing capability (A5).** A new catalog model + sidecar handler + a "parse document -> text/markdown" action, following the exact SANA/Whisper/Kokoro pattern.
- **Document-parse as a coding-agent tool + optional memory ingestion (A6).** Once A5 exists, expose it as an agent tool (drop a PDF/screenshot into context) and optionally feed parsed text into the memory subsystem.

### 4b. Present in Nexus, Missing in External (strengths to preserve)

- **Four pillars on one cross-OS desktop.** Nativ is chat/serve only and macOS-only; Unlimited-OCR is a single model. Nexus spans coding + chat + image + video with a Tauri cross-OS shell and OS-parity principle.
- **Protocol-pluggable local-client registry with a hard loopback guard** (`LocalAdapterRegistry.ts`): a manifest-only path to add any loopback runtime, with non-loopback endpoints rejected citing the MCP Registry Policy.
- **Four-layer hybrid-retrieval memory** (BM25 + dense + graph via RRF), GPU-tier scheduler, SSRF guard with per-hop DNS re-validation, permission tiers with floor-clamping, mutation testing, golden-task eval. None of these have a counterpart in either source.
- **Reverse-engineer-first governance** (AGENTS.md MCP Registry Policy) that keeps every addition local-only by construction.

### 4c. Present in Both (quality comparison)

| Capability | Nexus | External | Who does it better |
|---|---|---|---|
| Consume local models | Ollama + LM Studio + pluggable loopback adapters | Nativ: MLX only | Nexus (protocol-agnostic, cross-OS) |
| Embedded Python + server lifecycle | Diffusion/video sidecar | Nativ: NativServerKit | Comparable |
| Run open models locally | SANA / Whisper / Kokoro via catalog + sidecar | Unlimited-OCR via transformers/vLLM | Comparable pattern; Nexus lacks the OCR content (A5) |
| Model management UI | Models page (in-flight v1.15 P4) | Nativ: model library + menu bar | Nativ is more mature today -> A4 |

## Section 9: Risks and Explicit Rejections

**General considerations:**
- **Import behaviors, not architecture.** Every candidate is reimplemented in Nexus's existing TypeScript sidecar + Python-runtime + catalog spine. Do not import Swift, SwiftUI, NativServerKit, or a bundled MLX runtime.
- **A1 adds the only new inbound surface.** It must bind loopback only (reuse the `LocalAdapterRegistry` loopback guard), default off, require a local token, expose *only* inference (never file/tool access), and enforce request/size limits. Never bind `0.0.0.0`.
- **A5's model code is executable.** `trust_remote_code=True` runs repo Python; pin a specific revision, run only in the sandboxed sidecar, and prefer a portable open OCR model for non-CUDA / Apple-Silicon / CPU hosts so OS parity is not silently broken.
- **Report the OCR claim honestly.** "100-page PDF in one pass" is bounded by a 32K generation window over 300-DPI page images; document the real behavior, not the headline.

### Items explicitly NOT recommended for adoption

- **N1 -- Nativ's Swift/SwiftUI native macOS app shell.** Nexus is a Tauri cross-OS app with an OS-parity principle. A macOS-only Swift shell conflicts by construction. Adopt the *serving pattern* (A1), not the shell. **Rejected** (architectural).
- **N2 -- macOS 26 + Apple-Silicon-only floor.** Directly violates OS parity ("every claim that works on Windows also works on macOS Intel + Apple Silicon and Linux"). **Rejected** (architectural).
- **N3 -- Bundling mlx-vlm as a first-class Nexus runtime.** A dedicated MLX runtime was already dropped in the v1.12 comparison (D4) as "irrelevant to an Ollama/GGUF product". Keep MLX as an opt-in loopback `localAdapters` target (A3). **Rejected** (prior art + supply chain).
- **N4 -- Shipping Unlimited-OCR (or any OCR model) by default or as a hard dependency.** 3B VRAM cost, CUDA-first, `trust_remote_code`. Must be optional, user-pulled, and GPU-tier-gated. **Rejected as default**; accepted as optional (A5).
- **N5 -- Running `trust_remote_code=True` against a floating revision, unsandboxed.** If A5 ships Unlimited-OCR, pin to a specific commit/revision and run only inside the sandboxed Python sidecar. The naive "just set `trust_remote_code=True`" path is **Rejected** (supply-chain); it is a hard condition on A5.

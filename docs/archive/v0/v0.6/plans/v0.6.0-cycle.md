## Hard Constraints

1. **No new product surface.** v0.6.0 is a hygiene/ratchet release. Every feature toggle exposed in v0.5.x stays exposed; nothing new is added unless it directly closes a finding.
2. **Backwards-compatibility is not a goal.** When a setting is renamed or removed (e.g. legacy `gemma-code.gpuTier`), references update; no compatibility shims are left behind. AGENTS.md rule preserved.
3. **No backsliding on v0.5.0 discipline.** AGENTS.md is canonical; conventional commits enforced; SHA-pinned actions; ASCII-only commit messages.
4. **No item that requires LSTM, multi-provider proxying, distributed cache, or any item explicitly marked out-of-scope in [docs/archive/versions/v0/v0.5.0/architecture.md](../../v0.5/architecture.md) Section 12.**
5. **Definition of Done for v0.6.0**: zero P0 findings, zero P1 findings carried into v0.7.0, all four `BASELINE-2026-04-25` exceptions removed from `configs/dependency-cruiser.cjs`, all 12 token-estimation tests passing or rewritten, `tests/golden/baselines/v0.4.0.json` + `v0.6.0.json` exist and the regression check passes, `tests/benchmarks/baselines/v0.6.0.json` exists, the `>=40% token savings vs. v0.4.0` claim is either verified or retracted from CHANGELOG.

## Overview

The v0.6.0 cycle is **not** a feature release. It is the consolidation cycle that pays down v0.5.0's documented technical debt, closes the single chained P0 security finding, and unifies the path-guarding contract across the tool surface. The cycle is intentionally sequenced so that the security chain closes first (Phase 1), the test pipeline becomes trustworthy second (Phase 2), and the deep restructuring (panel split, dependency-cruiser ratchet) lands in the middle (Phases 3-5) when the test pipeline can catch regressions. Polish, ADRs, and the release gate close the cycle.

The user-visible delta in v0.6.0: **none direct**. Indirect: the agent's filesystem operations cannot be tricked by symlinks; the `permissionOverrides` setting is bounded so tier-2 tools cannot drop below tier 1; MCP confirmation prompts say which peer is asking; outbound HTTP fetches reject responses larger than 5 MB; CI catches moderate-severity npm audit findings; the CHANGELOG token-savings claim is either verified or honestly retracted.

The internal-developer-visible delta is large: ~1,800 lines of god-class code split into focused modules; four module-boundary baseline exceptions removed (CI now enforces the long-term contract for every layer); two circular dependencies untangled; the predictive cache layer either wired-and-tested or deleted; documentation/code drift in `architecture.md` resolved.

Success is measured through three artifacts: (a) `tests/golden/baselines/v0.6.0.json` and a regression delta against `v0.4.0.json`, replacing the unverified v0.5.0 claim with a measured number; (b) `tests/benchmarks/baselines/v0.6.0.json` proving no regression past the Phase 12.6 thresholds (hooks p99 < 50 ms, tool-execution p99 within +5 ms vs. v0.5.0); (c) a clean `dependency-cruiser` run with zero baseline exceptions and zero circular-dependency warnings.

## Phase 1: Security chain closure

**Goal**: Break Attack Path A (hostile workspace -> symlink + permissionOverrides downgrade -> RCE) by fixing both ends of the chain. Add MCP peer-attribution as a small, paired hardening.

**Prerequisites**: None.

**Stability Gate**:
- All filesystem tools (`read_file`, `write_file`, `edit_file`, `create_file`, `delete_file`, `list_directory`, `grep_codebase`) route path resolution through `pathGuard.resolveInsideWorkspace` (realpath-aware).
- A new test `tests/unit/tools/handlers/filesystem-symlink.test.ts` proves every filesystem tool refuses a workspace-internal symlink that resolves outside the workspace root.
- `permissionOverrides[name]` cannot drop a tier-2 tool below tier 1; a regression test in `tests/integration/permission-overrides-clamp.test.ts` proves it.
- MCP-originated tool calls produce a confirmation prompt whose text identifies the source (`"External MCP client wants to ..."` rather than `"The agent wants to ..."`).
- Full Vitest suite green; no new lint errors; `npm run deps:check` passes.

## Phase 3: Defense-in-depth ratchets

**Goal**: Land the medium-severity hardening items: bound outbound HTTP body size, tighten npm audit gate to moderate, replace SHA-1 with SHA-256 in the cache fingerprint, add an ESLint rule against `innerHTML` concatenation, obfuscate example webhook URLs in docs.

**Prerequisites**: Phase 2 (test pipeline is now trustworthy).

**Stability Gate**:
- `fetchWithSsrfGuard` rejects responses larger than 5 MB (configurable); a regression test asserts this against an MSW mock that streams 10 MB.
- `npm audit --production --audit-level=moderate` returns zero findings; the `hono` patch is absorbed.
- `Compressor.ts:112` uses SHA-256.
- ESLint rule fails on `\.innerHTML\s*=\s*[^=]+\+` patterns; existing webview code is refactored to either use a helper or `createElement`+`textContent`.
- Example Slack webhook URLs in `docs/archive/versions/v0/v0.5.0/plans/routa-harness-adoption.md` are obfuscated to `hooks.slack.example`.

### Sub-tasks

#### 3.1 -- Bound `fetchWithSsrfGuard` response body size

**Objective**: Close pen-test F-002 / Attack Path C. Prevent memory-exhaustion DoS via crafted large responses.

**Prompt**:
> In [src/utils/ssrf.ts:124-164](../../../../src/utils/ssrf.ts#L124-L164), add an option `maxBodyBytes` to `SsrfFetchOptions` defaulting to 5 MB. In `fetchWithSsrfGuard`, after the redirect chain settles, inspect the `Content-Length` header; if set and > maxBodyBytes, throw `Response body too large: ${len} bytes (max ${maxBodyBytes})`.

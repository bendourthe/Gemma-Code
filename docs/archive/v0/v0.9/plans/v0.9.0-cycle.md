## Originality and locality posture (read first)

Gemma-Code is an **original** project. No code is copied from upstream OpenHuman or any other inspiration source; every adopted pattern has been **reverse-engineered** from public docs and behaviour into a local, vendor-neutral artifact under Gemma-Code's own conventions and naming. This plan does not introduce any of the following:

- No calls to OpenHuman cloud or the OpenHuman product API.
- No `.claude/mcp.json` entry pointing at `openhuman.readme.io/mcp` or any other remote HTTP MCP.
- No Sentry / Prometheus / ElevenLabs / OpenAI / Anthropic / vendor telemetry exporters.
- No CodeRabbit Pro retrigger script, no CodeRabbit API call, no third-party PR-review-as-service.
- No OpenHuman Skills registry submodule, no Python `.venv` for skill execution.
- No 118-vendor OAuth integration layer (Gmail, Slack, Notion, Calendar, Drive, Linear, Jira, Stripe, etc.).
- No Whisper / ElevenLabs voice stack, no mascot, no Google Meet agent, no Remotion video pipeline.
- No outbound auto-fetch loop, no Memory-Tree-as-replication, no Obsidian-wiki-as-replication, no TokenJuice replication.

The only external commands invoked by anything in this plan are `git`, `gh` (user-installed; talks to GitHub for the user's own repo `bendourthe/Gemma-Code` -- intrinsic data destination, not third-party processor), `npm`, and `python diff-cover` (a local CLI tool installed only on CI runners). Inference remains local-only via `ollama` on `127.0.0.1:11434` or LM Studio on `127.0.0.1:1234`. Telemetry stays on disk under `~/.gemma-code/` with the optional OTLP exporter remaining opt-in.

This posture is the project's design centre, not a footnote. Every sub-task below is verified against it. The "Items NOT adopted" appendix at the bottom of this plan lists the 13 OpenHuman surfaces that fail this test, with the MCP Registry Policy bucket each rejection cites.

## Overview

The v0.9.0 cycle has three overlapping mandates: **(a)** close out the 37 open items the v0.8.0 cycle landed in [docs/archive/versions/v0/v0.8.0/known-gaps.md](../../v0.8/known-gaps.md) Section 10.1; **(b)** wire the v0.8.0 pure modules (Gemma 4 channel parser, HybridRanker, IntuitionCache, ReflectJob, WorkflowDetector, ModelPinRegistry, ToolCallStreamParser, tool-call-bytes LRU) into the production code paths they were designed for; and **(c)** ship the dev-loop ergonomics inspired by the [docs/archive/versions/v0/v0.8.0/comparison-openhuman.md](../../v0.8/comparison-openhuman.md) audit, each reverse-engineered into a local Gemma-Code artifact. Phase sequencing follows three layered priorities: foundational fixes first (so the test harness is reliable for the rest of the cycle), then deferred-from-v0.8.0 wirings (because those modules already exist and unit-test green), then the openhuman-inspired adoptions in MCP-Registry-Policy reverse-engineer-first order (skill-native before re-full), then curator/UX/CI follow-ups, then cycle close.

Phase 1 unblocks the v0.8.0 Windows segfault in vitest teardown (10.O.D / 10.O.N) by bumping vitest to a Windows-stable version or env-gating the two affected suites; raises the memory-consolidator stress threshold or splits it into `bench:integration` (10.O.E); and produces an operator-action checklist for the eight items the agent is not authorized to drive (live-Ollama capture, mutation re-run, pen-test re-run, release tagging). Phase 2 lands nine production wirings (10.O.K, M, S, T, U, V, W, Y, Z) -- each consumes a pure module already shipped in v0.8.0 and adds the call-site that v0.8.0 deferred for safety. Phase 3 ships five zero-code skill-native artifacts: an enriched `review-pr` SKILL, two Claude-Code subagents (`pr-manager`, `taskmaster`), a `ship-and-babysit` slash command that polls Gemma-Code's own CI (not CodeRabbit, not OpenHuman cloud), and a beginner contributor doc. Phase 4 ships four internal RE builds: cross-platform `npm run debug ...` test wrappers, a `diff-cover` 80%-on-changed-lines CI workflow, a pre-push auto-fix-retry hook, and `npm run work <issue>`. Phase 5 ships four more RE builds: `npm run deep-work` worktree lifecycle, PR template + checklist gate, `npm run agent-batch`, and `npm run review` PR-lifecycle CLI (with explicit overlap analysis vs. ship-and-babysit). Phase 6 lands the curator/scheduler/UX polish backlog (10.O.F, H, I, J, L, O, P, Q). Phase 7 implements the v0.8.0 post-CI audit follow-ups (10.O.AB-AG), starting with the Node 24 actions upgrade ahead of the 2026-09-16 GitHub deadline. Phase 8 closes the cycle.

What success looks like at the end of v0.9.0: all 37 v0.8.0 open items either resolved, explicitly closed in the Resolved table, or transferred to v0.10.0 with a written justification; v0.8.0/known-gaps.md `Status: finalized`; v0.9.0/known-gaps.md authored; `npm run lint && npm run check && npm test && npm run deps:check && npm run catalog:check && npm run perm-tier:check && npm run bench` all green on Windows + Linux; CI matrix runs Node 22 + Node 24; the diff-cover gate enforces 80% on changed lines; SECURITY.md and AGENTS.md still reflect the offline-first / vendor-neutral posture; no outbound runtime call has been added to the production code paths. This plan ingests **37 items carried forward from prior known-gaps files** -- see sub-tasks tagged `[from v0.8.0 known-gaps: 10.O.<X>]`.

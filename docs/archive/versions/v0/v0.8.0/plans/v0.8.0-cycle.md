**Project**: Gemma-Code

## Overview

v0.8.0 is the **wrappers-and-artifacts** cycle. The comparison against seven external sources (hermes-agent, jola.dev M4, learn-harness-engineering, antirez/ds4, awesome-hermes-agent, omlx, plannotator) surfaced ~38 adoption candidates. Gemma-Code already has the *primitives* in place (4-layer memory, 6-stage compaction, hardware tiers, OTLP, mutation testing, Plan mode, MCP, sub-agents, **HNSW vector index shipped in v0.7.0 Phase 7**, **`bin/gemma-check.mjs` deterministic-checks CLI + 4 rules shipped in v0.7.0 Phase 6**, **`BackgroundWorkers.ts` audit-worker + testgaps-worker shipped in v0.7.0 Phase 7**). v0.8.0 turns those primitives into a productized experience by adding the discrete harness artifacts (`feature_list.json`, `init.sh`, `clean-state-checklist.md`, `evaluator-rubric.md`), the prefix-cache-preserving memory snapshot semantics, the plannotator-grade plan-mode review UX, a prompt-injection scanner at memory boundaries, a hybrid RRF scoring layer **on top of the existing HNSW index**, a second LM Studio inference backend on Apple Silicon, a single `--trace` bug-report primitive, and a curator background-worker (a third entry in `BackgroundWorkers.ts`) with dry-run + rollback safety.

This plan ingests **19 open items carried forward from v0.7.0 known-gaps** (see [docs/archive/versions/v0/v0.7.0/known-gaps.md](../../v0.7.0/known-gaps.md) Section 10.2): see sub-tasks tagged `[from v0.7.0 known-gaps: 10.O.N]`. Three (10.O.1, 10.O.2, 10.O.3 -- all P1 Phase-4 panel-host wiring carryovers) close in Phase 0; seven (P2/P3) land in their natural target phases (5.10, 5.11, 6.A, 7.1, 7.A, 7.B, 7.C); and nine more (10.O.11-19 surfaced after the comparison report was written -- HNSW persist/reload bug, marked v12 perf regression, missing E2E test for background workers, operator captures for live-Ollama baselines and `package-lock.json` regeneration, TS-native golden runner decision) land in Phase 0 close-out sub-tasks 0.8-0.13.

The local-only thesis is unchanged. No outbound calls are added. The LM Studio second backend (Phase 4) is local-only and opt-in; the omlx third backend is **explicitly deferred to v0.9.0** due to alpha-stage maintenance risk. Eleven items are explicitly NOT adopted for security/policy reasons (Items N1-N11 in the appendix).

## Items explicitly NOT adopted (security / policy reasons)

The MCP Registry Policy in [AGENTS.md](../../../../AGENTS.md) gates these. All are classified `drop-outright`. They are recorded here, not in the adoption plan above.

- **N1 Messaging gateways** (Telegram, Discord, Slack, WhatsApp, Signal -- S1 hermes-agent `gateway/run.py`). Reason: outbound calls to third-party messaging services violate the local-only thesis (Hard Constraint #1). MCP Registry Policy bucket 5.
- **N2 Cloud terminal backends** (Modal, Daytona, Vercel Sandbox, Singularity -- S1 `tools/environments/`). Reason: sends code to remote sandboxes; violates local-only thesis. Bucket 5.
- **N3 Atropos RL training harness** (S1 `environments/`). Reason: multi-GB ML training stack with cloud connector; out of scope for an editor extension. Bucket 5.
- **N4 DSPy / GEPA prompt evolution** (S1 hermes-agent-self-evolution). Reason: heavy ML dependency stack; offline prompt tuning value does not justify the dep weight on a local Ollama path. Bucket 5.
- **N5 External memory provider services** (Honcho, Hindsight-as-a-service, Mem0 -- S1 `agent/memory_provider.py` bundled adapters). Reason: these ship as cloud services or self-hosted servers; the abstract MemoryProvider ABC is fine but bundling cloud adapters is not. Bucket 5. *Note: the patterns from Mnemosyne, yantrikdb, hindsight ARE adopted but reverse-engineered locally in Phase 4.6, Phase 6.3.*
- **N6 MCP OAuth manager** (S1 `tools/mcp_oauth_manager.py`). Reason: OAuth flows assume browser callbacks to cloud auth servers. Local MCP stdio support stays; OAuth path drops. Bucket 5.
- **N7 Plannotator E2E-encrypted plan-share service** (S7 `~/.plannotator/sessions/` with paste service). Reason: outbound network share, even encrypted, violates local-only thesis. Bucket 5. *Note: local plan archive (Phase 3.2) is adopted.*
- **N8 Cost-estimation / usage_pricing** (S1 `agent/usage_pricing.py`). Reason: meaningless for local Ollama; would only add maintenance burden. Bucket 5 (no value).
- **N9 Curator with always-on auxiliary inference** (S1 `agent/curator.py` running an aux model continuously). Reason: contends with main inference on a single-GPU laptop. Bucket 5 (cost/benefit fails). *Note: the lifecycle pattern IS adopted but gated by hardware tier and run on a 12h timer with dry-run default in Phase 5.2.*
- **N10 Blockchain / crypto-payment skills** (hermes-payguard, USDC/x402 wallet, hermes-blockchain-oracle, ripley-xmr-gateway -- S5). Reason: off-thesis for a local coding agent. Bucket 5.
- **N11 Voice / media / robotics skills** (resemble-ai/detect-skill, hermes-embodied, mars-rover, hermescraft -- S5). Reason: out of editor-extension scope. Bucket 5.
